> Хэрэгжүүлсэн: 2026-09-08, хоёр дахь баримтаар өргөтгөсөн: 2026-09-09, арав дахь баримт: 2026-09-11.  Бүх тоо `npm run ai:eval:norm`-оос **хэмжигдсэн**;
> хэмжээгүй тоо энэ баримтад **байхгүй**.

## Энэ юу вэ, юу БИШ вэ

Энэ бол мандатын **§11** — ажилтны PC дээрх локал мэдлэгийн сан:
SQLite + FTS5 + бүтэцтэй дүрмийн хүснэгт + солигдох вектор индекс.

**⚠️ ЭНЭ НЬ СУРГАЛТ БИШ.**  Мандатын §16 — *«DO NOT start by fine-tuning»* —
болон багцын өөрийнх нь бодлого хоёул үүнийг шаарддаг:

```json
"training_policy": "retrieval_first_do_not_bake_changeable_norms_into_model_weights"
```

Норм нь загварын **жинд ОРОХГҮЙ**.  Тэд SQLite-д орж, асуулт бүрд эшлэлтэйгээр
татагдана.  Үр дагавар:

- 2019 оны нэмэлт ирэхэд **дахин шингээнэ**, дахин сургахгүй
- буруу оруулсан мөрийг устгаад дахин оруулж болно
- загварын хувилбар солигдоход мэдлэг **хэвээр** үлдэнэ
- ажилтан 8 GB GPU-тай эсэх нь хамаагүй — энэ давхарга **загваргүй** ажиллана

## Хэрэглэх

```bash
# 1. Багцыг локал санд шингээх (D1 РУУ ЮУ Ч ЯВАХГҮЙ)
npm run ai:ingest:norm -- ai/data-train-files/MGL_AI_BNbD_21_04_05_dataset --verify

# 2. Хэмжих — «ажиллав уу» гэдгийн ЦОРЫН ГАНЦ хариу
npm run ai:eval:norm

# 3. Runtime-аас асуух
curl -H "x-mglai-secret: $(cat "$LOCALAPPDATA/MglAi/secret.txt")" \
     -H 'Content-Type: application/json' \
     --data-binary @query.json  http://127.0.0.1:39217/norm
```

Сангийн байршил: `%LOCALAPPDATA%\MglAi\knowledge\knowledge.sqlite`
(`config.ts`-ийн `knowledgeDb`).  **Загвараас ТУСДАА хавтас**: `models/` нь
хувилбараар солигддог, `knowledge/` нь хуримтлагддаг.

## Хоолой

```
асуулт
  → нормчлол (нэгж, бичгийн систем, entity)      normalize.ts
  → бүтэцтэй хайлт («Хүснэгт 3, мөр 9.1.2»)      search.ts
  → alias → дүрэм (англи хайлтын цорын ганц хөл)  legs.ts

  → RRF нэгтгэл                                   fusion.ts

  → эрхийн шүүлт (SQL-д, §6)                      pipeline.ts
  → ДЕТЕРМИНИСТ дүрмийн үнэлгээ                   rules.ts
  → эшлэл                                         citation.ts
```

### Дөрөв дэх багц — БНбД 11-03-21 (2026-09-10)

Эх сурвалж нь **хуудасны зураг БИШ, legalinfo.mn-ийн одоо мөрдөж буй бичвэр**
(`lawId=16390402482361`, 2022-08-07-оос хүчинтэй, БНбД 11-03-01-ийг орлосон).
Багц өөрөө «structured paraphrase/index, not verbatim» — хэсэг бүр
`metadata.paraphrase: true` тугтай, заалтын хуудас **зориуд NULL** (эшлэл нь
заалтын дугаараар).  Гурван шинэ хэлбэр, бүгд адаптерт:

- **`rule_id` = хэсгийн id.**  3.9-д гурван тоон мөр, 1.13-д үүрэг ба
  шаардлага хоёулаа ижил id-тай — шууд PK болговол дарна.  Дүрмийн id нь эх
  хэсгийн id-ээр угтварлагдана (`…:clause:3.9:numeric`,
  `…:clause:5.2:table:5-1:simple:low`); `norm-golden.mjs` тэр угтвараар
  «энэ дүрэм тэр заалтынх» гэж тулгана.
- **Муж нь `_min`/`_max` хоёр мөр** → адаптер нэг `between` болгоно (хагас хос
  бол нэг талт хэвээр, нөгөө талыг зохиохгүй).  Мөн `operator: "="`
  («1 м тутамд», «дундаж гүн 8 м») → `rules.ts`-д **`=` харьцуулагч** ил
  нэмэгдэв (ЯГ тэнцүү; `between [v,v]`-ээр тойрвол нөхцөлийн текст «8–8 м»
  болно).
- **Хүснэгтийн тоо заалтын бичвэрт БАЙХГҮЙ** («хүснэгт 5-1-ээр тогтооно»).
  `reference_tables.json`-ийн мөр бүр ӨӨРИЙН хэсэг (`kind: 'table_row'`,
  `metadata.derived_from`) + дүрэм болно — БНбД 21-04-05-ын хэлбэр, зөвхөн
  энд бид өөрсдөө угсарна.  Утга бүр `numeric_requirements.jsonl`-тэй
  **нэрээр тулгагдана**; зөрвөл `unverified_reference_table` (гүйцэтгэгдэхгүй)
  + анхааруулга.  Тулгагдсан тоон мөр скаляр дүрэмд дахин орохгүй.

Хэсгийн хайлтын мөрөнд **бүлгийн нэр** нэмэгддэг (4.8 «Энэ шатанд…» гэж
эхэлдэг — ямар шат гэдэг нь зөвхөн «Дөрөв. Эх загвар зураг / ТЭЗҮ үе шат»-д).

**Баталгаажилт**: `verified_from_official_legalinfo_text`,
`verified_current_text`, `verified_against_current_legalinfo_clause_index`,
`verified_legalinfo`, `verified_appendix_presence_and_title` тав
`EXECUTABLE_VERIFICATION`-д орсон.

**⚠️ Багцын ХЭСЭГ БҮР дүрэмтэй байх ёстой** — `pipeline.ts` эшлэлийг
нотолгооны эхний ДҮРЭМТЭЙ хэсгээс авдаг.  Өмнөх гурван баримтад бараг бүх
хэсэг дүрэмтэй байсан тул ажиглагдаагүй; энд 176-ийн 24 нь л файлд байсан.
Хэмжсэн хоёр гажиг: «БНбД 11-03-01 хүчинтэй юу?» → эшлэл 3-р байрны
УББ 12-01-01 2.5; зөвхөн төлөвийн хэсэгт дүрэм өгөхөд «БНбД 11-03-21 1.1 …»
213 тестийн 138-д эшлэл нь **хүчингүй нормын URL-тай** төлөвийн хэсэг болов.
Одоо УББ-11-201-00-тэй ижил: заалт бүр `quote_source_clause` шаардлага.

### Зургаа дахь багц — УББ 12-204-01 Даамлын дүрэм (2026-09-10, `flat_clause_rules`)

Хэсэг нь `clause_rules`-ийн хэлбэр (скан, хэвлэмэл + PDF хуудас), дүрэм нь
legalinfo-ийн ХАВТГАЙ мөр — хоёр адаптерыг хослуулсан профайл (`duty_rules` +
`qualification_rules`, `legal_status_graph`-ГҮЙ; `legalinfo_rules`-ийн ДАРАА
шалгагдана).  Хоёрхон тоон мөр, нэг нь **нийлмэл**: 4.3 «сард 2-оос доошгүй удаа
санал тавьсан БА захиалагч шийдвэрлээгүй БА ноцтой зөрчил» → үйлдвэрлэл зогсоох
эрх.  Багц сүүлийн хоёрыг зөвхөн англи тайлбарт бичдэг тул адаптер заалт
бүрийг нэрлэн угсарна (тоо нь багцаас).  Хөдөлгүүрт хоёр зориудын нэмэлт:

- **`kind: 'flag'` нөхцөл** (`rules.ts`) — үнэн/худал оролт: `true` хангана,
  `false` хангахгүй, бусад дутуу.  `required_context`-д л бичвэл «байгаа эсэх»
  шалгагдаж `false` ч «хангана» болж байв (хэмжсэн: R004).
- **`all_conditions` нэгдсэн туг** — зөвхөн `decision_policy`
  `evaluate_all_conditions…` дүрэмд (гал түймрийн ГУАТ/ГМДХ нь «аль нэг» хос
  тул өгөгдмөлөөр үүсгэхгүй).  Нэг нь ч null бол null.

Дөрвөн хөдөлгүүрийн засвар энэ багцаас гарав, бүгд хэмжигдсэн:

1. **Хамаарлын хаалга `search_text`-ийг ч тулгана** (`pipeline.ts`).  35 англи

   `text_mn`-тэй тулгадаг, англи үг нь `text_en`/галигт л байдаг.  Англи
   25.7% → 94.3%; NO_MATCH 6/8 хэвээр (суларсангүй).
2. **«БНбД»/«УББ» угтвар ойлголтын alias болохгүй** — багц «барилгын зураг
   төсөл» бүлэгт «БНбД» alias өгсөн тул «БНбД 11-03-21 …» гэсэн БҮХ асуулт
   «approved design» гэсэн үг авч, даамлын 4.4 эхэнд гарч байв.
3. **`ai_aliases.doc_id` (схем 3)** — alias-ыг канонаар цэвэрлэдэг байсан тул

### Долоо дахь багц — СНиП II-97-76* (2026-09-10, `legalinfo_rules`-ийн ГУРАВ ДАХЬ хувилбар)

Зөвлөлтийн норм, Монголын хүчин төгөлдөр нормын албан жагсаалтад (gazar.gov.mn,
х.32, Цогцолбор 30, мөр 4; УБХ-ны 1987 оны 107 тогтоол) бүртгэлтэй.  Техникийн
бичвэр нь **1990 оны нэгтгэсэн орос mirror (meganorm.ru)** — MCIS PDF-тэй
byte-for-byte тулгаагүй гэж багц өөрөө хэлдэг.  Тиймээс:

- хэсэг `verification_status` ОГТ өгдөггүй → баримтын провенансаас
  (`mcis_pdf_byte_alignment_verified: false`) **`verified_mirror_text_mongolia_listed`**
  гэсэн ТУСДАА мөр (цагаан жагсаалтад, `verified_official_text`-ээс зориуд өөр);
  12 хаалттай заалт (Зөвлөлтийн хууль/ГОСТ-ын хамаарал, 2.13/2.14 редакцын
  зөрүү) → `needs_human_review`;

## Хэмжилтээр төрсөн шийдвэрүүд

Эдгээр нь таамаг биш — тус бүр нь A/B хэмжилтээр батлагдсан:

1. **ASCII `\b` нь кириллийн хажууд ажиллахгүй.**  `/\bм2\b/u` нь «300 м2»-ыг
   **хэзээ ч** олохгүй.  Нэгж таних, «БНбД» таних, «ГУАТ» таних гурвуулаа
   чимээгүй үхмэл байсан.  Одоо Unicode үсгийн харцаар хил тавьдаг.

2. **FTS5-д `chunk_id`-аар устгах нь чимээгүй бүтэлгүйтдэг** (UNINDEXED
   багана).  Хоёр дахь шингээлтийн дараа индекст 126-ийн оронд 252 мөр үлдэж,
   BM25 нэг хэсгийг хоёр удаа тоолж байв.  Одоо индексийг бүтнээр нь дахин
   барина.

3. **Alias-ыг НИЙЛБЭРЭЭР биш ХАМРАЛТААР жинлэнэ.**  Нийлбэрээр жинлэхэд олон
   alias-тай дүрэм үргэлж ялдаг байв — англи Recall@5 25%.  Хамралтаар
   (тухайн дүрмийн alias багцын хэдэн хувь нь асуултад орсон) → **67.9%**.

4. **Таамагласан entity нь ЭРЭМБЭД ОРОХГҮЙ, зөвхөн ҮНЭЛГЭЭНД.**  Чөлөөт
   бичвэрээс regex-ээр гаргасан утгыг дүрэм *сонгоход* оруулахад дүрмийн
   таарц 74.7% → 65.8%, монгол 97.3% → 78.6% болж унасан.  Учир нь буруу
   **тоо** нь `inputs_used`-д харагдаж засагдана, харин буруу **дүрэм** нь
   өөр нормын шаардлагыг зөв тоогоор хэлж, хэрэглэгч ялгаж чадахгүй.

5. **Монгол хэлэнд тоо нь нэр томьёоны ӨМНӨ зогсдог.**  «1.1 заалтад» —
   зөвхөн «заалт 1.1» дарааллыг барих нь бүх монгол ишлэлийг алддаг.
   УББ багцын Recall@5 78.2% → **100%** (mn-Cyrl) болж өссөн.

6. **Нэг заалтад ОЛОН дүрэм ноогдож болно.**  УББ-ийн 1.3-р заалт нь үүрэг
   БА босго хоёуланг агуулдаг.  `LIMIT 1` нь цагаан толгойн эрэмбээр
   үүргийн дүрмийг сонгож, тооцоолохыг үл тоомсорлож байв — алтан кейсийн
   6 нь ингэж унасан.  Одоо: **нөхцөл өгсөн бол тооцоолох дүрэм, өгөөгүй бол
   заалтын эх бичвэр** ялна.

7. **НЭГ ЗААЛТЫН ХОЁР ТООГ АСУУЛТААР ЯЛГАНА.**  УББ-11-201-00-ын 3.8-р заалт
   нь график зургийн эх **2 хувь**, тайлбар бичиг **4 хувь** гэсэн ХОЁР тоо
   агуулна; 3.3 нь **20 жил** ба **5–10 жил**.  Хоёулаа нэг ХЭСЭГТ холбогддог
   тул ангилал тэнцүү болж, цагаан толгойн эрэмбэ («explanatory» < «graphic»)
   нь «график хувь хэд вэ?» гэсэн асуултад **«4 хувь»** гэж тодотгож байв
   (хэмжсэн 2026-09-09).  ⚠️ **Хэмжүүр үүнийг БАРЬДАГГҮЙ** — эшлэл, хуудас,
   нотолгоо бүгд зөв хэвээр байсан; зөвхөн загварт өгөх ГОЛ дохио буруу
   байв.  Одоо `loadRuleForChunk` нь ангилал тэнцүү үед **асуулттай
   хамралтаар** (объектын үгийн хэдэн хувь нь асуултад орсон бэ) эрэмбэлнэ.
   Хамралтыг ХУВИАР бодно, тоогоор БИШ: тоогоор бодвол заалтын бүтэн бичвэр
   нь өөрөөсөө гаргасан тоон мөрийн бүх үгийг агуулдаг тул ҮРГЭЛЖ ялна.
   `retrieval/test/pipeline.test.ts` энэ дөрвөн тохиолдлыг барина.
   ⚠️ Үлдсэн хязгаар: «Төлөвлөлтийн хугацаа хэдэн жил вэ?» гэсэн ЕРӨНХИЙ
   асуултад хоёр тоо ижил хамралт авдаг тул «5–10 жил» ялна.  Заалт 3.3
   ХОЁУЛАНГ хэлдэг ба нотолгооны бичвэрт хоёулаа байгаа тул хариу буруу
   болохгүй — гэхдээ энэ нь **шийдэгдээгүй хоёрдмол утга**, засвар биш.

8. **ХУГАЦААНЫ НЭГЖ СОЛИГДОХГҮЙ.**  «50 хоног» нь «2 сар»-д багтах эсэх нь
   хуанлийн асуулт (2 сар = 59-62 хоног).  Хөдөлгүүр хоногийн оролтыг САРЫН
   дүрэмд хэрэглэхгүй ба `null` буцаана — «хуанлиар тоол» гэсэн үг.  Багцын
   алтан кейс G006 яг үүнийг шаарддаг; хөрвүүлбэл ХУДАЛ итгэлтэй хариу гарна.

## ⚠️ Баталгаажилтын хаалга — ГАНЦ МӨР биш, ЖАГСААЛТ

`evaluateRule` нь эхэндээ яг `'verified_from_page_image'` гэсэн ГАНЦ мөртэй
тулгадаг байв.  УББ-11-201-00-ын эх PDF нь **зураг зөвхөн** (шигтгээст текст
огт байхгүй) тул багц нь бүх 76 мөрөндөө
`verified_from_rendered_page_image_with_ocr_normalization` гэж бичсэн —
«рендерлээд, монгол OCR-дээд, хуудасны ЗУРАГТАЙ ТУЛГАЖ шалгасан».

⚠️ **Энэ нь ЧИМЭЭГҮЙ доройтол байсан.**  Тулгалгүй бол 71 заалт бүгд
`blocked_unverified` → `uncertain` болж «хүний хяналт хүлээж байна» гэж
хариулах ба **хэмжүүр НОГООН хэвээр үлдэнэ**: гоожилт нь «баталгаажаагүй мөр
`verified` болов уу» гэж хэмждэг бөгөөд энэ баримтад `verified` төлөв ОГТ
үүсэхгүй (76 дүрэм бүгд тоон нөхцөлгүй тул хамгийн дээд нь `supported`).

Шийдэл: `rules.ts`-д `EXECUTABLE_VERIFICATION` гэсэн **нэрлэсэн цагаан
жагсаалт**.  Дөрвөн шинж чанар нь чухал:

- Нотлох барьцаа нь ИЖИЛ (хуудасны зураг); ялгаа нь зөвхөн цэг таслал, мөр
  таслал жигдэрсэн явдал бөгөөд багц өөрөө үүнийг `human_review_notes`-д ил
  бичсэн.
- Мөрийг **ДАХИН БИЧСЭНГҮЙ** — сан дотор эх төлөв хэвээр үлдэнэ, тиймээс
  OCR-оор ирсэн бичвэр ба хүн шалгасан бичвэр хоёр хожим ялгагдана.
- `needs_human_review` (гал түймрийн багцын 6 мөр) нь энд ХЭЗЭЭ Ч орохгүй.
- `/norm/info`-ийн «баталгаажаагүй» тоолуур ба `ingest`-ийн тоолуур мөн
  ЯГ ЭНЭ жагсаалтаас уншина (`executableVerificationSql()`).  Өмнө нь тэр
  мөр **гурван газар** давхардаж бичигдсэн байв — нэгийг нь шинэчлээд
  нөгөөг мартах нь «UI 82 мөрийг баталгаажаагүй гэж бичих атлаа хөдөлгүүр
  тэднийг гүйцэтгэсэн хэвээр» гэсэн хамгийн төөрөгдүүлэх зөрүү үүсгэнэ.

## Аюулгүй байдлын хоёр баталгаа

- **`needs_human_review` дүрэм ХЭЗЭЭ Ч `verified` болохгүй.**  Багцын 6 мөрийн
  эх бичвэр тодорхойгүй (PDF-ийн шигтгээст текст эвдэрсэн).  Тэд **хайгдана**
  (ажилтан эх сурвалжийг үзэж болно) ч `evaluateRule` тэднийг
  `blocked_unverified` гэж буцаана.  `ai:eval:norm` үүнийг «leakage» гэж
  хэмжиж, 0-ээс өөр байвал **унана** (exit 1).
- **Захиалагч нь `public_norm` бус мөрийг ХАРАХГҮЙ** — шүүлт SQL-ийн түвшинд,
  prompt угсрахаас өмнө (§6).  Загварт «битгий хэл» гэж хэлэх нь шүүлт биш.

## Юу ХИЙГДЭЭГҮЙ

- **Вектор хөл унтарсан.**  `node:sqlite`-ийн build-д `vec0` модуль байхгүй
  (хэмжсэн) ба локал embedding загвар суулгаагүй.  `NullVectorIndex` нь
  хоосон буцаана, RRF үлдсэн хөлүүдээр ажиллана.  Интерфейс (§12) бэлэн —
  адаптер солиход л хангалттай.  Тайлан бүр үүнийг **ил** бичдэг.
- **Reranker байхгүй** (§11-ийн заавал бус алхам).
- **Хуулийн хүчинтэй байдал шалгагдаагүй.**  Хоёр баримт ХОЁУЛАА үүнийг
  өөрсдөө хэлдэг: БНбД-ийнх `unknown_requires_legal_verification`, УББ-ийнх
  `current_status_not_checked_for_later_amendments_or_replacement`.  УББ
  12-01-01 нь **2001 оных** — 25 жилийн дараа хүчинтэй эсэх нь тусдаа
  хуулийн ажил.  Эшлэл бүр `legal_review_required: true` тугийг үүрдэг.
- **Гурван багц хараахан шингээгүй** (`data-train-files/` дотор байгаа):
  БД 21-101-12 (**38 томьёо** — тооцоолох шинэ ойлголт), БНбД 11-03-02
  (журмын алхам, шаардлагатай баримт), **БНбД 11-106-25** (байр зүйн зураглал,
  GOLD v3 — `legalinfo_rules` гэж танигддаг ч 145 тоон мөр эх хэсэггүй:
  масштаб тус бүрийн `supported_1_500`-хэлбэрийн мөрүүд, хэмжсэн 2026-09-11;
  ажилтны санд ОРООГҮЙ — `--all` биш, 10 хавтсыг нэрлэн шингээсэн).  Тус бүрд
  `datasetProfiles.ts`-д адаптер хэрэгтэй.
- **БНбД 11-03-21-ийн детерминист шийдвэр чат руу ХҮРЭХГҮЙ.**  `/norm` нь
  `decisions: {permafrost_min_borehole_depth: false, …}` буцаадаг ч
  `backend/src/lib/mglai/localNorm.ts`-ийн `parseLocalNorm` зөвхөн
  `rule_object_mn` · `note_mn` · `citation` · `evidence` · `missing_context`-ыг
  уншдаг — `decisions` ба `inputs_used` ХАЯГДАНА.  Гал түймрийн баримтад
  ялгаагүй байсан (тэнд D1-ийн `normDecide` шийддэг), энд «8 м < 10 м» гэсэн
  дүгнэлт зөвхөн загварын тооцоонд үлдэнэ.  Тусдаа өөрчлөлт.
- **БНбД 11-03-21-ийн хүснэгтийн мөрийг сонгох нь ХАЙЛТААР** (FTS тоог яг
  таарна: «700 кН/м» → 700-ийн мөр), нөхцөлөөр биш.  650 кН/м гэвэл ямар ч
  мөрөнд 650 байхгүй тул эхний мөр сонгогдож, `load_ceiling` нь «700 хүртэл»
  гэж ҮНЭН хэлэх ч 500-ийн мөр байж болзошгүй.  Тоон завсраар мөр сонгох нь
  `loadRuleForChunk`-ийн шинэ ойлголт — pipeline.ts өөр агентын WIP байсан
  тул хойшлуулав.
- **УББ-11-201-00-ын `formulas.jsonl` ХООСОН нь зориуд** — эх сурвалжид
  гүйцэтгэх боломжтой инженерийн томьёо огт байхгүй (багц өөрөө ингэж
  бичсэн).  Түүний хоёр алтан кейс нь ЖИЛИЙН АРИФМЕТИК («2026 + 20 = 2046»)
  бөгөөд хөдөлгүүр үүнийг **хийдэггүй**: кейсүүд эх заалт олдсон эсэхээр
  шалгагдана, тоог нь загвар «derived» гэж ИЛ тэмдэглэж хэлнэ.
