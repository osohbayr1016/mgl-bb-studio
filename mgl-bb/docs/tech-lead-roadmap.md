## A. Cloudflare Workers платформ

Бүх backend нэг Worker дээр байдаг. Энэ платформын хязгаарлалтуудыг мэдэхгүйгээр ямар ч
архитектурын шийдвэр гаргах боломжгүй — учир нь энэ репогийн хамгийн хачирхалтай код бүхэн
ямар нэг Cloudflare-ийн хязгаарын хариу юм.

### 1. Workers runtime загвар — **[Заавал]**
Isolate, Node API байхгүй, `ctx.waitUntil`, CPU/subrequest limit, module-scope state нь isolate тутам.
**Хэрхэн сурах:** `backend/src/index.ts` бүтнээр унш, дараа нь `routes/push.ts:213`-ийн module-level Map isolate дахин эхлэхэд юу болохыг тайлбарла.

### 2. `wrangler.toml`-ийн бүх binding — **[Заавал]**
D1 · 2×R2 · KV · Durable Object · Browser Rendering · Workers AI · 2 service binding · 2 cron. Аль өөрчлөлт нь DO migration tag шаарддагийг мэдэх.
**Хэрхэн сурах:** Binding бүрийн хэрэглэгчийг grep-ээр ол, `backend/src/types.ts`-ийн `Env`-тэй тааруул, дараа нь `deploy --dry-run`.

### 3. Production deploy runbook — **[Заавал]**
Migration ЭХЛЭЭД, дараа нь worker — үргэлж `--config wrangler.toml`-той. Энэ PC дээр root `wrangler.jsonc` config-ийг дарж авдаг.
**Хэрхэн сурах:** `docs/dev/11-deploy.md`-ийг локал D1 дээр давт. Санаатайгаар `--config`-гүй ажиллуулж алдааг нүдээрээ үз.

### 4. Cron / scheduled handler дизайн — **[Заавал]**
2 cron expression, 1 handler. Танигдаагүй бүх cron нь Gmail sync руу унадаг fail-safe салаа. Шинэ cron нэмбэл гурван sync давхар ажиллана.
**Хэрхэн сурах:** `index.ts:274-298` → `lib/deadlineSweep.ts`-ийн "cron нэмэхийн оронд өөрөө цагаа шалгах" загварыг унш.

### 5. Локал орчин: miniflare + node:sqlite — **[Заавал]**
`wrangler dev`-ийн 5 өөр "network error" шалтгаан: root config, IPv6 localhost, `ALLOWED_ORIGINS` яг таарах, орхигдсон workerd process, дууссан Cloudflare token.
**Хэрхэн сурах:** Тус бүрийг санаатай эвдэж үз. Дараа нь `.wrangler/state/v3/d1/…/*.sqlite`-ийг `node:sqlite`-аар шууд нээ.

### 6. Cloudflare Pages + `_headers`/`_redirects` — **[Заавал]**
Rule merge, SPA fallback, `.html` устгах 308. COOP/COEP-ийг `/*`-аас нарийсгавал service worker бүртгэгдэхээ болино.
**Хэрхэн сурах:** Preview branch руу deploy хийж `curl -I`-ээр толгойнуудыг шалга.

### 7. Cloudflare-ийн тоон хязгаарууд — **[Заавал]**
D1: 100 bind/statement. Request body ≈100 MB. `waitUntil` budget. Pages asset upload limit. Эдгээр нь кодод аль хэдийн шингэсэн.
**Хэрхэн сурах:** `qto.ts:669,859-895` · `upload.ts:69` · `wrangler.toml:36-42` — тоо бүрийг ухаж ойлго.

### 8. Edge cache-ийн шийдвэр — **[Заавал]**
`withEdgeCache` нь authenticated хариуг зохиомол түлхүүрээр кэшлэнэ. Нэг varyTag мартвал 30 секундын хугацаанд нэг хэрэглэгчийн өгөгдөл нөгөөд харагдана.
**Хэрхэн сурах:** `lib/edgeCache.ts` (90 мөр) + 7 дуудлагын цэг. `company.ts:178`-ийн `'staff'` tag яагаад одоохондоо л зөв байгааг тайлбарла.

### 9. Browser Rendering / puppeteer PDF — **[Хэрэгтэй]**
60 секундын JWT → headless Chromium → frontend-ийн print route. 6 бараг ижил хуулбар байна. Chromium дээр кирилл фонт байхгүй тул хуудас өөрөө ачаална.
**Хэрхэн сурах:** `routes/quotes.ts:790-830` ба `routes/projects.ts:2350-2520`-ийг зэрэгцүүлж унш.

### 10. R2 үйл ажиллагаа — **[Хэрэгтэй]**
`MEDIA_BUCKET` нээлттэй, `MEETING_BUCKET` хаалттай. Content-Type-ийг саармагжуулах, multipart proxy, `ownsKey` prefix шалгалт.
**Хэрхэн сурах:** `routes/upload.ts` бүтнээр, дараа нь `media.ts` vs `meetingAudio.ts`-ийг харьцуул.

### 11. Durable Object migration ledger — **[Хэрэгтэй]**
v1–v5 tag нь append-only түүх; 3 нь устгагдсан классын булш. Tag устгавал deploy эвдэрнэ. McpAgent заавал `new_sqlite_classes`.
**Хэрхэн сурах:** `git log -p -- backend/wrangler.toml` — v1→v5 хэрхэн хуримтлагдсаныг хар.

### 12. Secret менежмент — **[Хэрэгтэй]**
10 production secret, зөвхөн код доторх тайлбарт бичигдсэн. `JWT_SECRET` эргүүлэх нь session, MCP token, print token, Revit add-in-ийг зэрэг үхүүлнэ.
**Хэрхэн сурах:** `wrangler secret list`-ийг `types.ts` болон `docs/dev/01-setup.md`-тэй тулга.

### 13. Production debug: `wrangler tail` — **[Хэрэгтэй]**
APM байхгүй. Ганц телеметр нь `index.ts:113`-ийн 5% sampling `[timing]` мөр.
**Хэрхэн сурах:** `wrangler tail --format pretty` ажиллуулж Server-Timing толгойтой тулга.

### 14. Cloudflare Zero Trust үзэл баримтлал — **[Хэрэгтэй]**
Access IdP, WARP enrollment policy, Gateway TLS decrypt, HTTP rule. Одоо бүх rule нь log-only.
**Хэрхэн сурах:** `scripts/setup-zero-trust.mjs` (252 мөр) — 6 хэсэг нь dashboard-ийн 6 хуудастай 1:1 таарна.

### 15. Service binding sidecar Worker — **[Хэрэгтэй]**
`mgl-stirling`, `mgl-weasyprint` — production-д ажиллаж байгаа мөртлөө **эх код нь энэ репод байхгүй**. Binding нь optional тул алга болбол чимээгүй 503.
**Хэрхэн сурах:** Эхний ажил: эзэн нь хэн бэ, эх код нь хаана байна вэ гэдгийг олж баримтжуул.

## B. Backend, API, эрхийн загвар

56 route модуль, ~403 handler, 48k мөр. ORM байхгүй, validation library байхгүй, global error
handler байхгүй. Бизнесийн дүрэм нь handler дотор амьдардаг — route файлыг унших нь
тодорхойлолтыг унших гэсэн үг.

### 16. Hono routing ба middleware дараалал — **[Заавал]**
`cors → timing → authMiddleware → workerScopeGuard → routes`. Дараалал нь хамгаалалт өөрөө. Модуль дотор ч `put('/reorder')` нь `put('/:id')`-аас өмнө байх ёстой.
**Хэрхэн сурах:** 57 `app.route()` дуудлагыг 56 файлтай тааруул — mount хийгдээгүй нэгийг нь ол (`companyDailyReport.ts`, 600 мөр).

### 17. Auth архитектур: JWT, cookie vs bearer — **[Заавал]**
Гараар бичсэн HS256 (81 мөр). Нэг secret нь 5 төрлийн token гаргадаг: 24ц session, 1 жилийн MCP, 60сек print, 6ц audio, OAuth state.
**Хэрхэн сурах:** `signToken`-ийн 9 дуудлагын цэгийг жагсаа, тус бүрд "үүнийг /mcp дээр давтаж болох уу?" гэж асуу. Хариу нь: **болно**.

### 18. Бүрэн эрхийн матриц (5 механизм) — **[Заавал]**
DB role · `workerScope` allowlist · CEO id=2 hardcode · `users.is_support` · `users.attendance_unrestricted`. Сүүлийн хоёр нь баримтжаагүй, audit log-гүй.
**Хэрхэн сурах:** Матрицаа гараар бүтээ: `types.ts:169-205`, `middleware/auth.ts:75-98`, `lib/workerScope.ts`, `lib/ceo.ts`, `users.ts:481`.

### 19. `worker` (цэвэрлэгч) sandbox — **[Заавал]**
Ирцийн бүх дүрэм эсрэгээрээ: төсөл сонгохгүй, утасны хориг байхгүй, хоцролт 0 — харин office IP шалгалт **үргэлж** хүчинтэй. 3 давхарга зэрэг хөдлөх ёстой.
**Хэрхэн сурах:** Нэг clock-in-ийг `worker` болон `engineer`-ээр дагаж үз. API allowlist ↔ `frontend/src/shared/lib/roles.ts` таарч байгааг батал.

### 20. Public / exempt гадаргууг мэдэх — **[Заавал]**
Яг 6 зам auth-аас чөлөөлөгдсөн, бүгд яг тэнцүү string таарлаар. Нэмээд root дээрх `/media`, `/meeting-audio`, speechmatics webhook, OAuth endpoint-ууд.
**Хэрхэн сурах:** `middleware/auth.ts:12-43` — CLAUDE.md-д бичсэн `/api/quotes/public` нь **байхгүй** гэдгийг өөрөө батал.

### 21. Гараар бичсэн validation-ийн бодит байдал — **[Заавал]**
`c.req.json<T>()` нь зөвхөн cast — runtime шалгалт хийхгүй. 96 дуудлагын цэг, 233 `typeof` хамгаалалт. zod нь dependency боловч route-д огт хэрэглэгдээгүй (зөвхөн MCP tool-д).
**Хэрхэн сурах:** `routes/upload.ts` (сайн загвар) vs `routes/auth.ts` (сул загвар)-ыг харьцуул.

### 22. UB цагийн бүсийн зөв тооцоо — **[Заавал]**
`lib/time.ts` дөнгөж 3 функц, огнооны арифметик **байхгүй**. Тиймээс хэрэглэгчид өөрсдөө бичсэн. `isSummerSchedule` нь time util дотор нуугдсан бизнес дүрэм.
**Хэрхэн сурах:** `attendance.ts`, `leaves.ts` доторх `new Date(`-уудыг "timestamp" эсвэл "далд алдаа" гэж ангил.

### 23. Мэдэгдлийн тархалтын дизайн — **[Хэрэгтэй]**
Зөвшөөрөх эрх ≠ мэдэгдэл авах хүрээ. ~7 админд бүгдийг цацвал багийн ахлагчийн жагсаалт булагдана гэдгээс болж санаатай нарийсгасан.
**Хэрхэн сурах:** `lib/notify.ts` (229 мөр) бүтнээр — хоёр fan-out функцийн ялгааг ол.

### 24. Web Push: VAPID, sweep, SSRF allowlist — **[Хэрэгтэй]**
RFC 8030/8291-ийг гараар хэрэгжүүлсэн 516 мөр. Push endpoint нь хэрэглэгчийн өгсөн URL — host allowlist л SSRF-ээс хамгаална.
**Хэрхэн сурах:** `lib/webPush.ts`, `lib/pushSweep.ts`, `routes/push.ts:28-58`. Эхний засвар: унасан тестээ ногоон болго.

### 25. Google / Gmail интеграци — **[Хэрэгтэй]**
Service account RS256 JWT-г гараар гарын үсэглэдэг, refresh token-ыг AES-GCM-ээр шифрлэдэг, incremental history sync, calendar echo-loop хамгаалалт.
**Хэрхэн сурах:** `lib/google/googleAuth.ts` → `gmailClient.ts` → `emailSync.ts` → `crypto/secretBox.ts`.

### 26. Speechmatics STT + webhook reconcile — **[Хэрэгтэй]**
Хурлын бичлэг хаалттай bucket-д, гарын үсэгтэй URL-аар EU бүс рүү. Webhook алдагдвал 2 минутын cron сэргээнэ.
**Хэрхэн сурах:** Нэг хурлыг эхнээс нь дуустал дага: upload → submitJob → callback → finalize → reconcile.

### 27. Монгол хэлээр алдааны текст бичих — **[Хэрэгтэй]**
Хэрэглэгчид харагдах алдаа монголоор. `worker`-т өөр текст, ажилтанд өөр текст.
**Хэрхэн сурах:** `lib/workerScope.ts` (бүтэн монгол тайлбар) + `attendance.ts:79-90`.

### 28. `types.ts`-ийг эх сурвалж болгон унших — **[Хэрэгтэй]**
1,031 мөр, 40 commit — backend-ийн хамгийн их өөрчлөгддөг файл. `COMPLEXITY_PERCENT` зэрэг бизнес тогтмолууд DB-д биш энд байдаг.
**Хэрхэн сурах:** Нэг удаа бүтнээр унш. `worker-configuration.d.ts`-ийг хэзээ ч бүү зас.

## C. Өгөгдлийн загвар, SQL, migration аюулгүй байдал

147 migration, 100+ хүснэгт, 0 trigger, 0 view — бүх инвариант нь TypeScript дотор. Энэ хэсэгт
алдаа гаргавал буцаах боломжгүй: production D1 дээр бодит ирц, цалин, оноо, progress түүх байдаг.

### 29. Гараар нарийн SQLite бичих — **[Заавал]**
9 давхар CTE, correlated subquery, window function (`ROW_NUMBER`, `LAG`, `SUM OVER`), `json_*`, partial index.
**Хэрхэн сурах:** `routes/projects.ts:88-315`-ийн `PROJECT_LIST_SQL`-ийг санаж чадтал унш, дараа нь локал sqlite дээр `EXPLAIN QUERY PLAN`.

### 30. 5 түвшний жинтэй шатлалыг тайлбарлах — **[Заавал]**
Project → Block → Drawing → Component → Task. Гэхдээ **component-ийн жин тооцоонд огт ордоггүй** — математик нь 4 түвшин.
**Хэрхэн сурах:** Жин нь 70 болдог төсөл үүсгэ. UI-д харагдах тоо, оноо олгодог тоо хоёр яагаад зөрөхийг тэмдэглэ.

### 31. Гурван зөрүүтэй rollup хэрэгжилт — **[Заавал]**
`PROJECT_LIST_SQL` нь бодит хүүхдийн нийлбэрээр норм болгоно; `calcProjectProgress` нь зарласан төсвөөр хуваана; JS replay нь хоёр дахийг дагана.
**Хэрхэн сурах:** Гурвыг ижил өгөгдөл дээр ажиллуулж яг хаана салахыг бич. Энэ тоо чиний бүх ирээдүйн incident-ийн гол асуулт.

### 32. D1 migration аюулгүй байдал — **[Заавал]**
Production дээр `foreign_keys=1`. `migrations apply` нь файл бүрийг transaction-д ороодог тул parent хүснэгтийг `DROP` хийхэд ~40 хүүхэд хүснэгт чимээгүй устана.
**Хэрхэн сурах:** `migrations/0136_worker_role.sql`-ийн 60 мөрийн толгойг бүтнээр унш, хаягдал D1 дээр хэмжилтийг нь давт.

### 33. D1 client contract — **[Заавал]**
`batch()` бол цорын ганц transaction. Statement тутам 100 bind. `meta.last_row_id` / `meta.changes`. Компенсацийн DELETE загвар.
**Хэрхэн сурах:** `qto.ts:800-905`-ийн chunk арифметик (21 bind × 4 мөр = 84). `qto_facts`-д нэг багана нэмбэл шинэ chunk хэмжээ хэд болохыг тооц.

### 34. Схемийн археологи — **[Заавал]**
Committed migration-ууд **шинэ DB босгож чадахгүй**. 0022 хоосон, 6 дугаар давхардсан, 2 файл apply хийсний дараа дугаар нь солигдсон. Жинхэнэ схем нь амьд D1.
**Хэрхэн сурах:** Loop дадлага: `node:sqlite`-аар бодит DDL → `grep`-ээр амьд бичигчийг ол. "Үлдэгдэл" гэж нэрлэгдсэн хүснэгт бүр дээр давт.

### 35. Зөвшөөрлийн урсгал ба оноо — **[Заавал]**
<100% автоматаар батлагдана, ≥100% дараалалд ордог. Оноо нь **илгээсэн хүнд бүтнээр** очно — CLAUDE.md-д бичсэн "хуваана" гэдэг хоцрогдсон.
**Хэрхэн сурах:** Нэг submission-ийг эхнээс нь дага: POST → pending → approve → `awardPointsForEntry` → `user_points` → leaderboard.

### 36. Ирцийн домэйн дүрмүүд — **[Заавал]**
Улирлын хуваарь (6–8 сар албан ёсоор 08:00), grace нь хасагддаг (босго биш), дахин орох дүрэм, өдрийн хоолны давхцал, хоцролт уучлах дүрмийн 3 хуулбар.
**Хэрхэн сурах:** Амралт, баяр, хагас чөлөө, өглөөний OOO агуулсан зуны нэг долоо хоногийн grid-ийг гараар гаргаад API-тай тулга.

## F. AI, MCP, автоматжуулалт

32 MCP tool нь компанийн бүх өгөгдлийг — төсөл, ирц, HR аналитик, и-мэйлийн бие, хурлын

### 71. OAuth 2.1 + DCR — **[Заавал]**
Бүх Worker нь OAuthProvider-ээр ороодог — Hono бол зөвхөн fallback. `/register` нь нээлттэй (claude.ai шаарддаг). CLAUDE.md-д бичсэн `handleMcp` **байхгүй**.
**Хэрхэн сурах:** `oauth/authorize.ts` бүтнээр + `/.well-known/oauth-authorization-server`-ийг curl хий.

### 72. LLM-д зориулж tool дизайн хийх — **[Заавал]**
Tool-ийн тайлбар текст нь цорын ганц "prompt engineering". Хариуны хэмжээ, paging, `sections` параметр — бүгд token төсвийн шийдвэр.
**Хэрхэн сурах:** Туранхай tool (`projects.ts`) vs баян tool (`report.ts`)-ийг харьцуул. Дараа нь өөрөө нэг read-only tool бич.

Гаднаас ирсэн и-мэйлийн 20k тэмдэгт нь моделийн context руу шууд ордог. Тэр **ижил session**-д ажилтанд бодит даалгавар үүсгэдэг write tool байдаг.
**Хэрхэн сурах:** Локал D1-д өөрөө injection и-мэйл бич. `emailTriage.ts`-ийн confirm-gate загварыг хоёр хамгаалалтгүй write tool руу зөөх төлөвлөгөө гарга.

### 74. Хоёр гадаргуугийн эрхийг тааруулах — **[Заавал]**
REST нь middleware-ээр, MCP нь **бүртгэлийн үед** хаадаг. 32-оос 31 tool нь "чамд бүртгэгдээгүй" гэдэгт л найддаг. Нэг register дуудлагыг зөөвөл 30 tool чимээгүй нээгдэнэ.

## G. Аюулгүй байдал, чанар, гүйцэтгэл

Transaction дотор `PRAGMA foreign_keys = OFF` нь чимээгүй үйлчилдэггүй тул `DROP TABLE` нь ~40 хүүхэд хүснэгтийг цувраагаар устгана: ирц, progress, оноо, мэдэгдэл. Зөв зам нь `d1 execute --remote --file` + гараар `d1_migrations`-д бичих. 2026-08-04-нд хаягдал D1 дээр хэмжсэн.

**02. `public/sw.js`-ийг устгах эсвэл нэр солих** ☠️
`_redirects` нь байхгүй замд `index.html`-ийг 200-аар буцаадаг тул браузерын шинэчлэлийн шалгалт MIME дээр унаж, **хуучин worker мөнхөд идэвхтэй үлдэнэ**. Дараагийн ямар ч deploy тэр хэрэглэгчид хүрэхгүй. Тэтгэвэрт гаргах бол эхлээд өөрийгөө устгах агуулга нийтлэх ёстой.

**03. `/media/:key`-г `/media/*` болгож "засах"** ☠️
Одоо ганц сегмент таардаг нь **санамсаргүй хамгаалалт**: компанийн бүх синк хийгдсэн Gmail архив (бие + хавсралт) яг тэр bucket дотор үүрлэсэн түлхүүрээр хэвтэж байна. Route-ийг өргөвөл бүх и-мэйл интернэтэд нээгдэнэ. (Тал нь: `generate_report`-ийн PDF холбоос ийм учраас 404 өгдөг — түүнийг гарын үсэгтэй route-аар засах хэрэгтэй.)

**04. `_headers`-ээс COOP/COEP-ийг нарийсгах**
web-ifc устсан тул илүүц мэт харагдана. Гэвч Chrome нь cross-origin-isolated хуудаснаас service worker бүртгэхийг зөвшөөрөхгүй — push чимээгүй үхнэ. `vite.config.ts`-той толин тусгал байх ёстой.

**05. `vite.config.ts`-ийн `classnames` дүрмийг зөөх**
`recharts` дүрмээс дээр байх ёстой. Доогуур бол rolldown нь clsx-ийг recharts chunk руу нэгтгэж, ~110 KB gzip нь login болон маркетингийн хуудасны эхний зурагт наалдана. Энэ бол онол биш, болсон regression.

**06. Cron expression нэмэх**
Handler нь зөвхөн `* * * * *`-ийг таньдаг; бусад бүх утга Gmail + хурал + календарь + deadline sweep рүү унадаг. Шинэ cron нэмбэл тэр гурвыг давхар ажиллуулна. Зөв загвар нь cron нэмэхгүй, ажил өөрөө цагаа шалгах.

**07. Олон материалтай элементийн `count`-ийг "засах"**
4 давхаргатай хана 4 мөр болдог ч зөвхөн хамгийн зузаан нь `count=1` авдаг. Энэ нь `SUM(count)`-ийг элементийн тоотой тэнцүү байлгадаг инвариант. Бусад мөрөнд хуулбал бүх тоолол 4 дахин өснө — хаана ч алдаа гарахгүй.

**08. `combo_key` / `normalizeRawName`-ийг өөрчлөх**
Түлхүүр нь зөвхөн (category | type | material) — family, level, зузаан **санаатай** ороогүй. Нормчлолын дүрмийг сольвол хадгалагдсан бүх шифрийн alias нэг дор өнчирнө. Migration 0120-ийн толгой үүнийг өөрчлөгдөшгүй гэж бичсэн.

**09. `tailwind-merge`-д бүртгэлгүй typography token нэмэх**
`cn('text-body','text-muted-foreground')` нь хэмжээг чимээгүй устгана — tailwind-merge танихгүй `text-*`-ийг өнгө гэж ангилдаг. `cn()` 1,500+ газар дуудагддаг. Алдаа огт гарахгүй.

**10. DO migration tag устгах**
v1–v5 нь append-only түүх; гурав нь устгагдсан классын булш. "Цэвэрлэвэл" deploy эвдэрнэ. Мөн шинэ DO нь SQLite суурьтай бол заавал `new_sqlite_classes`.

**11. Migration файлын дугаарыг apply хийсний дараа солих**
`d1_migrations` нь **файлын нэрээр** бүртгэдэг. Дахин дугаарлавал файл дахин ажиллана. Одоогийн хоёр тохиолдол санамсаргүй аюулгүй байсан — дараагийнх нь байхгүй байж магадгүй.

**12. `JWT_SECRET` эсвэл `VAPID_PUBLIC_KEY` эргүүлэх**
JWT_SECRET нь бүх session, бүх 1 жилийн MCP token, бүх Revit add-in суулгалт, нислэг дунд байгаа бүх print token-ийг зэрэг үхүүлнэ. VAPID эргүүлэх нь бүх push захиалгыг хүчингүй болгоно. Аль аль нь буцаах боломжгүй.

> **Дадлагын санал:** эдгээрийн 1, 2, 5, 9-ийг локал эсвэл preview орчинд **санаатай эвдэж** үз.
> Уншиж мэдсэн хавх мартагддаг; өөрөө эвдэж үзсэн хавх мартагддаггүй.
