## Эхлэхийн өмнө нэг удаа хийх ажил

Эдгээр нь кодоос **тогтоох боломжгүй** тул эхний сессээс өмнө шалгах хэрэгтэй:

```bash
# 1. Идэвхтэй загвар байгаа юу?  Байхгүй бол талбар дээрх бүх add-in зөвхөн түлхүүр үгээр ажиллаж байна
npx wrangler d1 execute mgl-progress-db-v3 --remote --config backend/wrangler.toml \
  --command "SELECT version, accuracy, example_count, created_at FROM assistant_models WHERE is_active=1"

# 2. Чат ямар provider дээр байна?  (0193 нь INSERT OR IGNORE — суусан эсэх нь мэдэгдэхгүй)
npx wrangler d1 execute mgl-progress-db-v3 --remote --config backend/wrangler.toml \
  --command "SELECT key, value FROM app_settings WHERE key IN ('revit.agent_provider','assistant.logging','assistant.min_confidence')"

# 3. Сурах гогцоо бодитоор ажилласан уу?
npx wrangler d1 execute mgl-progress-db-v3 --remote --config backend/wrangler.toml \
  --command "SELECT (SELECT COUNT(*) FROM assistant_logs) AS logs, (SELECT COUNT(*) FROM assistant_examples) AS examples, (SELECT COUNT(*) FROM assistant_examples WHERE source='usage') AS curated"

# 4. TRACK 2 — БАГИЙН БОДИТ БҮРТГЭЛ.  Бүрэлдэхүүнийг эзэн 2026-08-30-нд ХААСАН: 8 салбарын баг
#    (BA BB HAS TSBU TSAH HD AU IZ) — шипсэн IMPLEMENTED_TEAMS-тэй ЯГ ижил.  `teams` нь 11 мөртэй
#    хэвээр (0007 нь энэ 8 + MGMT, 0074 нь EZ + GT) — MGMT/EZ/GT-д багц БАЙХГҮЙ, тиймээс зөвхөн
#    нийцлийн шалгалт нь алгасагдана.  Тэд UNCERTAIN БИШ: team_code нь бодит код хэвээр (2-1 §3.4).
#    Энэ асуулга нь одоо зөвхөн sort_order ба мөрийн бодит байдлыг батлахад л хэрэгтэй, бүрэлдэхүүнд БИШ.
npx wrangler d1 execute mgl-progress-db-v3 --remote --config backend/wrangler.toml \
  --command "SELECT code, name_mn, sort_order FROM teams ORDER BY sort_order"

# 5. TRACK 2 — багийн ҮНДСЭН гишүүдийн тоо (2-1-ийн шатны 3-р шат `is_primary = 1`-ээр л шүүнэ)
npx wrangler d1 execute mgl-progress-db-v3 --remote --config backend/wrangler.toml \
  --command "SELECT t.code, COUNT(*) AS n FROM user_teams ut JOIN teams t ON t.id=ut.team_id JOIN users u ON u.id=ut.user_id WHERE u.status='active' AND ut.is_primary=1 GROUP BY t.code ORDER BY n DESC"

# 6. TRACK 2 — 0212…0216 продакшн дээр ҮНЭХЭЭР хэрэгжсэн үү?  Хэрэггүй бол add-in нь
#    `addin_version`, `timing_json`-ыг БАЙХГҮЙ баганад бичиж байна
npx wrangler d1 execute mgl-progress-db-v3 --remote --config backend/wrangler.toml \
  --command "SELECT name FROM d1_migrations ORDER BY id DESC LIMIT 20"
```

Мөн эзнээс асуух:

1. **Anthropic-ийг анхдагчаас буулгах уу?** Brief §4 production-д төлбөртэй LLM API-г хориглодог. `app_settings` нэг мөрийн UPDATE, deploy шаардахгүй.
2. **LAN инференсийн сервер батлагдах уу?** Хэмжсэн техник хангамжаар ажлын станц дээрх локал LLM бодитой биш (RTX 3070 = 8 ГБ VRAM, бодит төсөл 4.9 ГБ / 12 загвар).
3. **QTO өгөгдөл нь үнийн ангиллынх уу?** 1A-6-ийн эрхийн хүрээг энэ шийднэ.
4. **`assistant_logs`-ийн зөвшөөрлийн мэдэгдэл ба хадгалах хугацаа** — хөдөлмөрийн харилцааны шийдвэр, инженерийнх биш.
5. ~~**ЯГ ХЭДЭН баг вэ, IZ тэдний нэг үү?**~~ — **ХААГДСАН, ЭЗЭН БАТАЛСАН 2026-08-30.** Хариу: **8 салбарын баг** (BA BB HAS TSBU TSAH HD AU IZ), IZ тэдний нэг — дээрх **Ш1**. Багцын дараалал: **BA бүрнээрээ эхлээд, IZ хоёрдугаарт** — дээрх **Ш2**. IZ-д хуучин `norms_*` тэмдэглэгээ ба `iz/` фолдер **бүхэлдээ** БНбД эшлэл **ТЭГ** хэвээр (хэмжсэн 2026-08-30) тул түүний дүрмийн багцыг хураах биш, **зохионо**. `2-1`, `2-2`, `2-6` дээрх блок **АРИЛСАН**.
6. **Албан ёсны БНбД / MNS баримтыг ХЭН авчрах вэ, аль хэвлэлийг?** Тэдгүйгээр §40-R3-ын долоон нотолгооны талбар дүүрэхгүй, `eval/golden/rules.json` хоосон хэвээр (`run_golden.py` **exit 2**), ба **дүрэм код эшлэх ЭРХГҮЙ** — зөвхөн «дотоод шалгуур» гэж гарна. Инженерийн бус, баримт худалдан авах ажил. R2/R5/R6-ийн критик зам, **эзэнгүй**.
7. **Ажилтны мэдэгдэл, гэрээ ҮНЭХЭЭР шинэчлэгдсэн үү?** `9fe82a0` нь 0195-ийн «геометр, файлын агуулга хадгалахгүй» амлалтыг эзний шийдвэрээр ЦУЦЛАВ гэж бүртгэсэн; `bim.capture.notice_version` нь **ирээдүйн** огноогоор суусан. Track 2-ийн олдвор нь элементийн id, өрөөний нэр, хэмжээ агуулна — event store-оос ЧАНГА. Релизийн урьдчилсан нөхцөл.
8. **Эзний гарын үсэг шаардах шийдвэр:** binding нь BA гэж, үндсэн баг нь IZ гэж хэлвэл — бид **UNCERTAIN** гэж шийдсэн (§48-R6 «буруу багийн дүрмийг чимээгүй хэрэглэж болохгүй»). Зөвшөөрөх үү, эсвэл аль тал ялахыг заах уу?

## Мартаж болохгүй гурван зүйл

**① Сургалтад тэнцэх өгөгдөл өнөөдөр ТЭГ.** Шипсэн 2 532 мөрийн корпус бүхэлдээ
машин зохиосон эсвэл гарал үл мэдэгдэх. `HUMAN_VERIFIED`, `RULE_VERIFIED`,
`HUMAN_CORRECTED` — гурвуулаа тэг мөр. Тиймээс **1B-6 (курацийн UI)** нь хамгийн
богино замд байгаа хамгийн чухал ажил: түүнгүйгээр цуглуулах гадаргуу нэмэх бүр
**хэн ч шошголохгүй** мөр нэмнэ.

**② Дараалал алдагдаж байгаа нь загварын хэмжээнээс чухал.** `ChangeTracker` нь
элемент тус бүрийн **зөвхөн сүүлийн** үйлдлийг үлдээж, `capture_baseline` тухайн
өдрийн олонлогийг устгадаг. «хана үүсгэв → зөөв → хаалга нэмэв → senior залруулав
→ батлав» гэсэн гинжийг **хэзээ ч сэргээхгүй** — тэр гинж нь зан төлөв, залруулга,
санаа, ажлын урсгал, шалтгаан-үр дагаврын сургалт бүгдийн суурь.

**③ 2026-08-30-ны эзний хүсэлт нь долоон шаардлага, тэдгээр нь Track 2-ийн ЦОРЫН
ГАНЦ хэмжүүр.** Үг үсгээр нь `docs/bim-ai/2-0-OWNER-BRIEF.md`-д, задаргаа нь:
**R1** add-in суулгахад бэлэн, **алдаагүй** өгөгдөл цуглуулна ·
**R2** хэрэглэгчийн ажлын урсгалыг илрүүлж, **цоорхойг хараад**, ӨНДӨР БАРИЛГЫН
норм дүрмээр барилгын алдааг буцаана ·
**R3** **8 салбарын баг** (ЭЗЭН БАТАЛСАН 2026-08-30 — Ш1), **баг бүрийн дүрэм ӨӨР** —
дүрэм нь багаар хамрагдана, глобал ХЭЗЭЭ Ч биш ·
**R4** баг тус бүрийн сургалтын өгөгдөл; add-in нь үйлдэж буй гишүүний багийг
**АВТОМАТААР** таана, гараар сонгохгүй ·
**R5** BA бол **зөвхөн BA**-ийн архитектурын дүрэм, AI өөрөө асуудал, алдааг хэлнэ ·
**R6** IZ бол **шууд** интерьерт хамаарах өндөр барилгын нормыг хэлж, алдаа засахад
бодит цагт тусална ·
**R7 — ХАМГИЙН ЧУХАЛ** ажлын урсгалд **огт нөлөөлөхгүй**, **гацалт байхгүй**,
гараар ямар ч алхам байхгүй, бодит цагт, хурдан.

**⚠️ БҮРЭЛДЭХҮҮН ТОГТСОН, ГИШҮҮДИЙН ТОО БАТЛАГДААГҮЙ (2026-08-30).**
**ЭЗЭН БАТАЛСАН:** салбарын бүртгэл нь **8 баг** — BA, BB, HAS, TSBU, TSAH, HD, AU, IZ
(«MGMT-ийг хасаад үлдсэн 8-н багийг оруулна»). Энэ нь шипсэн `IMPLEMENTED_TEAMS`
(`frontend/src/features/projects/team-reports/TeamReportsTab.tsx:52-61`)-тэй **ЯГ ижил**,
мөн v2 §46-ийн бүртгэлтэй ижил. *(Түүхэн тэмдэглэл: 2026-08-30-ны өмнө эх сурвалжууд
зөрдөг байсан — v2 §46 «7 teams», `IMPLEMENTED_TEAMS` 8, миграц 9, `0074`-ийн дараа 11.
Тэр зөрчил эзний шийдвэрээр хаагдав.)* Үлдсэн нюанс нь ганцхан: **`teams` хүснэгт 11 мөртэй
хэвээр** — `0007_teams.sql:39-47` нь энэ 8 + MGMT, `0074_seed_ez_gt_teams.sql:13-14` нь
EZ + GT. Тэр **гурав нь дүрмийн багцгүй** тул тэдний сесст **нийцлийн шалгалт АЛГАСАГДАНА**,
өөр багийн дүрмээр ХЭЗЭЭ Ч шалгагдахгүй (багц алга бол шалгалт алга, орлуулга БИШ — v2 §48-R6).
⛔ Гэвч тэд **UNCERTAIN БИШ**: илрүүлэлт нь амжилттай тул `team_code` нь бодит код (MGMT/EZ/GT),
`team_source`/`team_confidence` нь шатны бодит утга, `learning_events` тэр кодоор шошголсон хэвээр
(§72), chip нь «Баг: EZ (дүрмийн багцгүй)» гэж гарч хэрэглэгчээс залруулга **ШААРДАХГҮЙ**.
UNCERTAIN бол илрүүлэлт УНАСАН тохиолдол (`team_code = NULL`, шошго `null`, «Баг: тодорхойгүй»,
хэрэглэгчээс залруулга шаардана). Хоёр төлөвийн канон харьцуулалт: **`2-1-team-context.md` §3.4**.

*(Түүхэн тэмдэглэл 2026-08-30: v2 §46-ийн ростерын тэмдэглэл нэгэн үе «багцгүй баг нь §48-ын дагуу
TEAM = UNCERTAIN болно» гэж бичсэн байсан ба энэ мөр түүнийг давтаж байлаа. Тэр нь БУРУУ; v2 §46 нь
эх сурвалж дээрээ зассан, `2-1` §3.4 нь эхнээсээ зөв байсан.)*

Тиймээс хэвээр үлдэх заавар: **салбарын багцыг ажиллах үедээ `teams.code`-оос УНШИНА,
7 ч, 8 ч, 9 ч гэж ХЭЗЭЭ Ч кодонд бичихгүй** — баталсан 8 бол **төлөвлөлтийн** тоо
(хэдэн дүрмийн багц зохиох вэ), компайл хийх литерал БИШ; §69-ийн «Team checks: n/n» нь
**тухайн төсөлд байгаа** багуудын дотроос багцтай нь тоолж тооцоологдоно.

Продакшны D1 руу энэ машинаас хүрч чадсангүй (Cloudflare API алдаа **7403 not authorized**,
2026-08-30), тул **баг тус бүрийн гишүүдийн тоо** батлагдаагүй хэвээр. Дээрх «Эхлэхийн өмнө»
блокийн 5-р асуулгыг ХЭРЭГЖҮҮЛЭХИЙН ӨМНӨ ажиллуулж, хариуг `2-0-OWNER-BRIEF` дээр
бүртгэнэ. Тэр бүртгэл нь мөн `2-1`-ийн 4-р шатны эвдэрсэн код (`foldText('BB') === 'b'`,
`2-1-team-context.md:202`) хэр өргөн нөлөөтэйг шийднэ — **BB нь баталсан 8-ын дотор**, тул
энэ эвдрэл одоо тодорхой хамааралтай.
