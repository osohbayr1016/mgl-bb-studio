# MGL QTO — 24/7 batch автоматжуулалт

Инженерүүд сүлжээний хавтас дахь central `.rvt` файлаа өөрчлөхөд энэ PC
хуваарийн дагуу (өдөрт 2-3 удаа) өөрчлөгдсөн файлуудын тоо хэмжээг вэбсайт
руу автоматаар илгээнэ.

```
Task Scheduler (02:00 / 12:30 / 18:30)
  └─ batch-qto.ps1: config дахь файлуудын mtime-ийг state-тэй харьцуулна
       └─ өөрчлөлттэй бол batch-queue.json бичээд Revit-ийг асаана
            └─ RevitMcpAddin (BatchQto.cs): файл бүрийг DETACHED нээж
               QtoExtractor → POST /api/qto/revit-runs → Revit унтарна
       └─ batch-result.json-г уншиж лог + state шинэчилнэ
```

## Нэг удаагийн тохиргоо

> ⚠️ **БҮХ АЛХМЫГ БАТЧ ДАНСААР НЭВТЭРЧ БАЙЖ ХИЙНЭ.**  Add-in
> (`%APPDATA%\Autodesk\Revit\Addins\<он>\`), API токен ба
> `batch-config.json` / `batch-state.json` (`%APPDATA%\RevitMcpAddin\`) БҮГД
> **хэрэглэгч тус бүрийн** зам — өөр дансаар ажиллуулбал:
> add-in ачаалагдахгүй → queue уншигдахгүй → **ажиллагаа бүр `exit 1`**;
> state хоосон → **бүх файл дахин push** → `qto_runs` давхардана.

0. **Батч дансаар нэвтрэх** — жишээ нь `MGL\qto-batch`: домэйн админ **БИШ**,
   сүлжээний `.rvt` хавтас руу **зөвхөн унших** эрхтэй тусдаа Windows данс
   (доорх «Windows данс» тэмдэглэлийг үз).  Дараагийн бүх алхам ЭНЭ session
   дотор.
1. **Add-in суулгах** — release zip-ийг задлаад `Install.bat`.
   ⚠️ `dotnet build ..\..\addin\RevitMcpAddin.csproj -c Release` нь DLL-ээ
   **build хийж буй хэрэглэгчийн** `Addins` хавтас руу хуулдаг тул батч дансанд
   таарахгүй — зөвхөн хөгжүүлэгчийн машинд тохиромжтой (Revit хаалттай үед).
2. **Токен** — Revit нээгээд `MGL > Тохиргоо`-оос нэг удаа нэвтэрнэ
   (1 жилийн токен `%APPDATA%\RevitMcpAddin\settings.json`-д хадгалагдана).
3. **Тохиргоо** — `batch-config.template.json`-г
   `%APPDATA%\RevitMcpAddin\batch-config.json` болгож хуулаад файлын зам +
   `project_id`-уудыг бөглөнө.
4. **Гараар турших** (Revit хаалттай үед):
   ```powershell
   powershell -ExecutionPolicy Bypass -File batch-qto.ps1 -Force
   ```
   Лог: `%APPDATA%\RevitMcpAddin\batch-log.txt`; вэб дээр `/app/qto`-с run-аа шалгана.
5. **Хуваарь суулгах** — ЯГ ТЭР дансаар нэвтэрсэн хэвээр, `-User`-**гүй**:
   ```powershell
   powershell -ExecutionPolicy Bypass -File install-batch-task.ps1
   ```
   Task нь бүртгэсэн (= энэ) дансаар ажиллах тул 1-4 алхмын per-user төлөвтэй
   заавал таарна.

   **`-User 'MGL\qto-batch'` нь ХОЁРДОГЧ зам** — админ өөр дансны өмнөөс
   бүртгэх үед.  Тэр данс дээр **1-4 алхам аль хэдийн хийгдсэн байх ёстой**;
   script нь add-in + `batch-config.json` байгаа эсэхийг шалгаад анхааруулга
   бичнэ (профайл руу нэвтрэх эрхгүй бол шалгаж чадахгүй).  Бүртгэхэд админ
   PowerShell шаардлагатай.
   **`-Credential` дэмжигдэхгүй** — нууц үгтэй логон нь `LogonType=Password`
   болгодог ба тэр session нь **интерактив БИШ** тул Revit GUI асахгүй; script
   өгөгдсөн тохиолдолд шууд зогсоно.

## Анхаарах зүйлс

- **⚠️ Хуучирсан queue**: script ХАТУУ тасалдвал (Task Scheduler-ийн
  `ExecutionTimeLimit` дуусах, task-ыг зогсоох, Ctrl+C, reboot)
  `batch-queue.json` диск дээр үлдэнэ. Тэр үед тухайн Windows хэрэглэгчийн
  ДАРААГИЙН **ЭНГИЙН** Revit нээлт батч горимд орж, файлуудыг push хийгээд
  **Revit-ээ өөрөө хаана** — инженерийн хадгалаагүй ажил алдагдана, шалтгаан нь
  ямар ч попапаар харагдахгүй (батч горимд `TaskDialog` зориудаар гаргадаггүй).
  `batch-qto.ps1` одоо (а) эхлэхдээ өөрөө цэвэрлэдэг, (б) `try/finally`-ээр
  Ctrl+C/алдааны үед өөрийн queue-г устгадаг. Гараар шалгах:
  ```powershell
  Test-Path "$env:APPDATA\RevitMcpAddin\batch-queue.json"             # $false байх ёстой
  Test-Path "$env:APPDATA\RevitMcpAddin\batch-queue.processing.json"  # $false байх ёстой
  ```
  ⚠️ **`$true` гарсан нь өөрөө асуудлын шинж БИШ** — батч ажиллаж байх үед
  тэдгээр нь ХЭВИЙН `$true` байдаг (queue бичигдээд Revit асахыг хүлээж байна,
  эсвэл add-in боловсруулж байна).  **ГАРААР БҮҮ УСТГА**: тэр нь `batch-qto.ps1`-ийн
  өөрийнх нь «амьд эзэн» хамгаалалтыг үгүйсгэж, яг явж буй шөнийн push-ыг
  таслах эрсдэлтэй.  Эхлээд эзэнтэй эсэхийг шалга:
  ```powershell
  $q = Get-Content "$env:APPDATA\RevitMcpAddin\batch-queue.processing.json" -Raw | ConvertFrom-Json
  $q | Select-Object pid, created_at, nonce
  Get-Process -Id $q.pid -ErrorAction SilentlyContinue   # байвал = PS эзэн АМЬД
  Get-Process -Name Revit -ErrorAction SilentlyContinue  # байвал = Revit боловсруулж байж болзошгүй
  ```
  Хоёулаа хоосон **бөгөөд** файл нь хэдэн цагийн өмнөх бол л эзэнгүй.  Тэр үед
  ч гараар устгахын оронд `batch-qto.ps1`-ээ дахин ажиллуулахад хангалттай —
  эхлэхдээ өөрөө цэвэрлээд лог-д «эзэнгүй … устгалаа» гэж бичнэ.
  ⚠️ Энэ эрсдэл нь зөвхөн батч PC-д хамаарахгүй:
  дээрх «Гараар турших» алхмыг ажлын станц дээр ажиллуулаад таслах нь тэр
  инженерийн **өөрийнх нь машиныг** ижил байдалд оруулна.
  **Гэхдээ АМЬД ажиллагааг устгахгүй**: цэвэрлэгээ нь queue доторх `pid`-ыг
  шалгаж, тэр процесс амьд (powershell, `batch-qto` командын мөртэй, queue
  бичигдэхээс өмнө эхэлсэн) бол ЮУГ Ч устгалгүй `exit 0`-ээр гарна. Лог-д:
  `ЗОГСЛОО: өөр batch ажиллагаа явж байна`. Хоёр ажиллагаа давхцахад
  (триггер давхцах, эсвэл нэгэн зэрэг гараар турших) хожуу эхэлсэн нь
  өмнөхийн queue-г устгаад тэр шөнийн push-ыг алдахаас сэргийлнэ. PID дахин
  ашиглагдсан/өөр хэрэглэгчийн процесс бол эзэнгүй гэж үзээд хэвийн устгана.
  **Revit талыг мөн шалгана**: `pid` нь ЗӨВХӨН PowerShell-ийг хэмждэг тул PS
  тал хатуу алагдаад Revit нь push-аа үргэлжлүүлж байх боломжтой.  Тийм үед
  зөвхөн pid-ээр шүүвэл дараагийн ажиллагаа ХОЁР ДАХЬ Revit асааж, ижил
  файлууд давхар `qto_runs` үүсгэнэ.  Тиймээс queue/processing файл
  бичигдсэнээс ХОЙШ эхэлсэн Revit процесс амьд байвал мөн `exit 0` хийж
  алгасна (лог: «…боловсруулж яваа Revit АМЬД байна»).  Файл 3 цагаас
  (`$LiveRevitMaxAgeMinutes`, install-batch-task.ps1-ийн `ExecutionTimeLimit`-тэй
  тааруулсан) хуучирвал энэ шүүлт унтарна — эс бөгөөс инженер Revit-ээ
  нээлттэй байлгах бүрд батч мөнхөд хаагдана.
- **`.processing.json` үлдэгдэл**: add-in дуусахдаа өөрөө устгадаг
  (`BatchQto.cs:97`), гэхдээ Revit timeout-оор алагдвал / лицензийн попап дээр
  унавал үлддэг.  `batch-qto.ps1` одоо `finally`-дээ **зөвхөн өөрийнхөө**
  үлдэгдлийг (nonce тулгаж, Revit зогссон үед) устгадаг тул дараагийн
  ажиллагаанд «эзэнгүй … устгалаа» гэсэн худал анхааруулга бичигдэхгүй.
- **nonce — үр дүн ӨӨРИЙНХ мөн эсэх**: script queue бүрд санамсаргүй `nonce`
  бичдэг, add-in түүнийг үр дүн бүрд цуурайтуулдаг (`results[].nonce`).
  Уншихдаа тулгана:
  - таарахгүй → **АЛДАА**, үр дүнг бүхэлд нь голж `batch-state.json`-г
    ШИНЭЧЛЭХГҮЙ (өөр ажиллагааны үр дүнгээр state бичвэл push хийгдээгүй
    файлууд «илгээгдсэн» болж, тэр өөрчлөлт үүрд алгасагдана), `exit 1`;
  - огт байхгүй → одоохондоо зөвхөн **анхааруулга**, учир нь nonce
    цуурайтуулдаггүй хуучин add-in талбар дээр байсаар байгаа (~20 ПК,
    албадан шинэчлэх механизмгүй). ⚠️ Бүх ПК-г шинэчилснийг **баталсны
    дараа л** үүнийг алдаа болгоно — эсрэгээр нь хийвэл шөнийн батч бүх
    хуучин машин дээр чимээгүй зогсоно.
- **⚠️ `.ps1` файлууд UTF-8 BOM-ТОЙ хадгалагдсан — BOM-ыг бүү хас.** Windows
  PowerShell 5.1 нь BOM-гүй UTF-8 файлыг Windows-1252 гэж уншдаг тул бүх
  кирилл тайлбар, лог мөр, алдааны текст эвдэрнэ. Шалгах:
  ```powershell
  (Get-Content .\batch-qto.ps1)[1]   # уншигдахуйц кирилл байх ЁСТОЙ
  [IO.File]::ReadAllBytes((Resolve-Path .\batch-qto.ps1))[0..2]   # 239 187 191 (EF BB BF)
  ```
  Засварласны дараа редактороо «UTF-8 with BOM»-оор хадгалсныг батал.
- **⚠️ Windows данс**: батч task-ыг **домэйн админ БИШ**, сүлжээний `.rvt`
  хавтас руу **зөвхөн уншихын** эрхтэй тусдаа дансаар ажиллуул
  (`RunLevel Limited`). Тэр PC диск дээрээ ~1 жилийн API токен хадгалдаг тул
  түүнийг бусад ажилд бүү ашигла.  Хамгийн найдвартай нь: тэр дансаар
  **нэвтэрч** дээрх 0-5 алхмыг бүхэлд нь хийх (`-User` хэрэггүй) — тэгвэл
  add-in / токен / config нь task-ийн ажиллах данстай **бүтцээрээ** таарна.
  Шалгах: `(Get-ScheduledTask -TaskName 'MGL QTO Batch').Principal`
- **`ExecutionTimeLimit` > `timeout_minutes`**: `install-batch-task.ps1`-ийн
  3 цаг нь `batch-config.json`-ий `timeout_minutes` (анхдагч 90 мин)-ээс урт
  байх ёстой. Урвуулбал task эхэлж зогсож, `finally` ажиллахгүй → хуучирсан
  queue үлдэнэ.
- **Лиценз**: TRIAL лицензтэй Revit асахдаа попап харуулбал автомат ажиллагаа
  зогсоно — 24/7 PC-д жинхэнэ лиценз шаардлагатай. Попапаас болж гацвал лог-д
  "add-in batch-г огт эхлүүлээгүй" гэж бичигдэнэ.
- **Хэрэглэгч нэвтэрсэн байх**: Revit GUI тул task нь интерактив session
  шаардана — PC-г нэвтэрсэн хэвээр (дэлгэц түгжээтэй OK) байлгана.
- **Central файлд халгүй**: файлыг үргэлж detach хийж нээдэг тул инженерүүдийн
  worksharing-д ямар ч нөлөөгүй.
- **Batch = зөвхөн хост**: Тохиргооны «Link файлуудыг хамруулах» нь зөвхөн
  ribbon товчинд үйлчилнэ — batch горимд салбар файл бүр `batch-config.json`-д
  тусдаа мөр тул link expansion хийдэггүй (давхар илгээлтээс сэргийлнэ).
- **Нэг төсөлд олон файл** (БА + ББ гэх мэт): одоогоор run бүр тусдаа
  хадгалагдана — вэб дээрх "сүүлийн run" нь хамгийн сүүлд push хийгдсэн
  ГАНЦ файлын тоо хэмжээ. Олон файлын нэгтгэл бол дараагийн шатны ажил.
- Токены хугацаа (~1 жил) дуусахад бүх push 401 болно — Revit нээгээд
  Тохиргоо-оос дахин нэвтэрнэ.
