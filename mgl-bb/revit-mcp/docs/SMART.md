### Цонх ↔ Revit: `SmartExecutor`
- Модальгүй цонх Revit API-д ЗӨВХӨН `SmartExecutor` (өөрийн `ExternalEvent`)-оор хүрнэ.  Урт ажил = `ISmartJob` ХЭСЭГ
  (`Step`), Step бүр ≤ ~100–150 мс; Step хооронд Revit UI-д амьсгал өгч, «Цуцлах» дарагдана.  Handler НЭГ Ч УДАА шидэхгүй
  (Revit шидвэл ExternalEvent-ийг `Denied` болгодог); `Denied/TimedOut` үед хугацаатай дахин оролдоно.  `Step` шидвэл ч ажлын түр нөөц `OnCancelled`-ээр цэвэрлэгдэнэ.
  `Execute` дотроос хийсэн `Raise()` нь `Pending` буцааж болох (дараагийн Execute-ийн баталгаа баримтжуулагдаагүй) тул Execute буцсаны ДАРАА 80 мс-ийн follow-up `Raise()` +
  3 с-ийн «харуул» (watchdog); `Raise()`-ийн `Accepted` БИШ эхний 20 үр дүнг логлоно (бодит Revit дээр юу болдгийг шалгах).
- **Smart Publish цонх МОДАЛЬ** (командын API контекст хүчинтэй) — Revit модаль цонхны үед ExternalEvent ГҮЙЦЭТГЭХГҮЙ,
  тиймээс «Өөрчлөлт шинжлэх» цонхыг хаагаад КОМАНД өөрөө `ImpactJob.Step`-ийг шууд явуулж, дараа нь цонхыг дахин нээнэ.
- `await`-ын дараах UI код `UiThread.Run`-аар (SynchronizationContext баталгаагүй); `UiThread.Run`/`Progress` нь алдааг
  БАРИЖ логлоно — thread pool-д гарсан UI алдаа Revit-ийг унагахаас сэргийлнэ (smoke тест `ThrowOnError`-оор бодит алдааг харна).

### Таних тэмдэг
- **Баримт**: `DocumentKey.Id = doc:<CreationGUID>` (нөөц: cloud:/ws:/path:/unsaved).  Хадгалаагүй (түлхүүргүй) баримт ЗӨВХӨН
  session-ийн санах ойд — түр түлхүүрээр диск дээр файл үүсгэхгүй.
- **Элемент**: `ElementKey` = host `doc|UniqueId`, линк `host>linkInstanceUid>linkDoc|UniqueId`.  `ElementId` нь ЗӨВХӨН
  session доторх хурдан лавлах (хадгалагддаг ч `UniqueId` давамгайлна).
- «Өөрчлөгдсөн» илрүүлэлт: `ModelChangeCounter` (DocumentChanged тоолуур).  `DocumentVersion.VersionGUID`-д ҮНДЭСЛЭХГҮЙ:
  Revit өөрөө «бүх өөрчлөлтөд шинэчлэгдэхгүй» гэж баримтжуулсан.
- **`Document` wrapper-ийн тэнцүүлэл**: Revit ижил нээлттэй баримтыг өөр `Document` instance-аар өгч болно (баримтжуулсан) →
  `SmartDocs.Same` ба `DocumentTable<T>` (Revit-ийн `Equals`/`GetHashCode`) ашиглана, ӨӨРӨӨР тэнцүүлэхгүй.  ⚠️ Арын thread-ээс/UI-аас
  `Document`-д ХЭЗЭЭ Ч хүрэхгүй: `ChangeStamp` handle-ийг API контекстод (session үүсгэхэд) авч хадгална, цонх зөвхөн тэр handle-ийг уншина.
  `DocumentTable` нь баримтыг ХҮЧТЭЙ (strong) лавлана — сул лавласан үед wrapper GC-д орвол tracker/`ChangeStamp` чимээгүй алдагдаж хадгалагдаагүй
  өөрчлөлт тасарна (2-р хяналтын HIGH).  Хаагдсан (`IsValidObject = false`) баримтын мөр `DocumentClosed` үед (`PurgeDead`, хаалт цуцлагдсан бол хөндөхгүй)
  цэвэрлэгдэнэ; хаагдсан wrapper шинэ баримттай `Equals` тэнцсэн ч ТОХИРОХГҮЙ (`Matches` нь `IsAlive`-г шаарддаг).  **Цонхны танилт** =
  `DocumentKey.Id@ChangeStamp.Id` (`SmartWindows.IdentityOf`): ижил файлыг хаагаад дахин нээхэд хуучин нээлтийн цонх (хуучирсан tracker/тоолуур) дахин ашиглагдахгүй.

```

docs\<docHash>\publish-history.json  publish-checkpoints.json

```
`SmartStore`: `{schema, savedUtc, payload}`; **атом** (tmp → Replace), `.bak`, эвдэрсэн файл `.corrupt-*` руу quarantine
(ачаалахад ШИДЭХГҮЙ — анхдагч), шинэ хувилбарын файлыг ДАРЖ БИЧИХГҮЙ, `.premigrate-vN.bak`, enum нь танигдаагүй утгад
`Unknown(0)`.  Revit-ийн Extensible Storage-д хадгалахгүй (загварыг «өөрчлөгдсөн» болгож, транзакц шаарддаг тул).

⚠️ **Түгжигдсэн/уншигдахгүй файл ≠ хоосон файл.**  Файл байгаа ч УНШИГДААГҮЙ (антивирус/өөр процесс түгжсэн) үед `LoadStatus.Unreadable`:
хоосон төлөв рүү чимээгүй ЗАЛГИХГҮЙ, дараагийн `Save` нь тэр файлыг ДАРЖ БИЧИХЭЭС ТАТГАЛЗАНА (амжилтгүй гэж ИЛ хэлнэ) — эс бөгөөс түүх,
хадгалсан төлөв бүхэлдээ алга болно.  `PeekSchema` нь IO алдаатай бол ч бичихээс татгалзана.  Бүх «хадгалж чадсангүй» нь UI-д харагдана
(Publish: `PersistWarnings`/`WarnIfNotPersisted`, Clash: run `Failed` + ⚠ тэмдэглэл, Impact: тайлангийн тэмдэглэл).

⚠️ **`File.Exists` ХЭЗЭЭ Ч ашиглахгүй** (2-р хяналт): тэр нь эрх/түгжээ/сүлжээний алдаанд ч `false` буцааж «файл байхгүй» гэж худал хэлдэг.  `Load`/`PeekSchema`
файлыг ШУУД нээж, ЗӨВХӨН `FileNotFound`/`DirectoryNotFound` нь «байхгүй» (`Missing`, дахин оролдлогогүй), бусад IO/эрхийн алдаа нь `Unreadable`.
`Load` НЭГ Ч УДАА шидэхгүй: `JsonNode.Parse` нь объектыг эргэцтэй байгуулдаг тул давхардсан түлхүүр (`{"schema":1,"schema":2}`) нь Parse-д биш анхны
`root["schema"]` хандалтад `ArgumentException` шиддэг (тестээр олдсон бодит алдаа) — задлалт + дугтуйн бүх хандалт НЭГ `try` дотор, ямар ч алдаа = эвдэрсэн
файл (quarantine).  Эвдэрсэн файлыг `.corrupt-*` руу НҮҮЛГЭЖ ЧАДААГҮЙ (түгжигдсэн) бол мөн «уншигдахгүй» мэт тэмдэглэгдэж `Save` татгалзана — гараар сэргээж
болох цорын ганц хуулбарыг хоосон анхдагчаар дарахгүй.  `SmartSettings.Save` нь кэшийг ЗӨВХӨН амжилттай хадгалсны дараа шинэчилнэ; уншигдаагүй тохиргоо
`SmartSettingsFile.Unreadable` тэмдэгтэй (нөлөөллийн шинжилгээ «цоорхой байхгүй» гэж хэлэхгүй).

## 1. Smart Publish — PDF / DWG / IFC

`SmartPublish/Core` (нэршил, planner, preflight, түүх/checkpoint) · `Revit` (экспорт, цуглуулалт, команд) · `Ui` (цонх, профайл засварлагч).

- **Профайл**: формат (PDF/DWG/IFC), хуудас сонгох дүрэм, нэршлийн загвар, хавтас, давхардал (`Overwrite`/`Version`/`Skip`),
  PDF/DWG/IFC тохиргоо.  5 жишээ профайл.  Хувилбартай; хадгалагдаж, хуулж/устгаж болно.
- **Нэршил**: `{ProjectNumber}_{SheetNumber}_{SheetName}[_Rev{Revision}]`, токен + засагч (`|upper|max=20`), `[ … ]` нөхцөлт бүлэг.
  Системд нийцэхгүй тэмдэгт цэвэрлэгдэнэ, давхардал шийдэгдэнэ (planner нь хавтас бүрийг НЭГ л удаа жагсаана).
- **Preflight** (ГАРГАХААС ӨМНӨ): байхгүй/бичих эрхгүй хавтас, давхардсан нэр, хоосон токен, байхгүй DWG setup, ревиз заавал,
  хэвлэх боломжгүй хуудас, PDF тохиргооны буруу enum.  Блоклосон асуудалтай үед «Гаргах» идэвхгүй.
- **Экспорт** (Revit-ийн УДИРДЛАГАТАЙ API): PDF = хуудас бүр `Combine=true`+`FileName`, `SetExportInBackground(false)`;
  DWG = урьдчилсан setup ӨӨРЧЛӨХГҮЙ; IFC = нээлттэй транзакц ШААРДДАГ тул түр транзакц → **ҮРГЭЛЖ ROLLBACK**
  (`ImpactCapture.Suppress()` нь тэр түр өөрчлөлтийг нөлөөллийн бүртгэлд оруулахгүй).
- **Баталгаажуулалт**: «Revit true буцаасан» ≠ «файл гарсан».  `ArtifactValidator` экспортын өмнө/хойно хавтсыг жагсаан
  харьцуулна (цагаар БИШ): хуучин файл амжилт болохгүй; 0 байт = `EmptyArtifact`; PDF-д Revit `false` ба файл үүссэн бол
  артифакт `Failed` (хэсэгчилсэн замыг тэмдэглэнэ, УСТГАХГҮЙ).
- **Түүх/дахин оролдох**: гүйлт ЭХЛЭХЭД (`Running`) болон ДУУСАХАД атомаар хадгалагдана (Revit унасан ч «дуусаагүй» гэж харагдана).
  Дахин оролдох = ЗӨВХӨН бүтэлгүйтсэн/цуцлагдсан (хуудас, формат) хос.  2-р хяналтын засвар:
  • **Өөрийн хэсэгчилсэн файлыг л дарна** — `PublishArtifact.PartialPath` = ЭНЭ экспортоор ШИНЭЭР үүссэн/шинэчлэгдсэн (бүрэн бус байж болзошгүй) файл
    (`ArtifactCheck.Fresh`: экспортын өмнөх жагсаалтад байгаагүй/хэмжээ-цаг нь өөрчлөгдсөн; хоосон 0 байт ч шинэ).  Бүтэлгүйтсэн артифактын `Path` нь ЗӨВХӨН
    төлөвлөсөн зам — тэнд өөр хүний (`TargetChanged`), өмнөх гаргалтын эсвэл түгжигдсэн файл байж болох тул түүгээр нуух/дарж бичих БОЛОМЖГҮЙ.
    `HidingFileSystem` нь замыг бүтэн замаар (`/`↔`\`, том/жижиг үсэг) тулгана.  Хуучин түүх (талбаргүй) = нуухгүй → Version горимд `_v2` (аюулгүй тал).
  • **Бүх хуудсаар төлөвлөөд шүүнэ**: эх гүйлтийн БҮХ хуудас + эх «одоо» (`PublishRun.PlanNowUtc`, `{Date}` токен) — зөвхөн бүтэлгүйтсэн хуудсаар
    төлөвлөвөл `{Index}`/`{SheetCount}`/давхардлын дагавар өөр гарч файл ӨӨР нэртэй болно.  `Filter` нь нэрийн асуудлыг ч зорилтоор шүүнэ.
  • Анхны гаргалтын цонх шиг «байгаа файлыг дарж бичнэ» гэж ИЛ асууна (өмнөх оролдлогын хэсэгчилсэн файлаас бусдыг).
- **Төлөвлөгөө ↔ диск уралдаан** (`PublishRace`, цэвэр): дарж бичихээр ТӨЛӨВЛӨӨГҮЙ (`Export`, `Versioned`) зорилтот зам гаргалтын үед диск дээр байвал
  `TargetChanged`.  ⚠️ «Шинэ дугаартай» (`_v2`)-д ТӨЛӨВЛӨСӨН нэр дээр шалгана — эх нэрийн `TargetExists` нь `_v2` чөлөөтэй гэсэн баталгаа БИШ.
- **Checkpoint**: хуудас бүрийн «сүүлд АМЖИЛТТАЙ гаргасан» тэмдэг, **ФОРМАТ БҮРЭЭР** (`FormatStamp`: PDF/DWG тус тусдаа
  `ChangeSeq` + `DocVersionGuid`; нийт `ChangeSeq` = формат бүрийн ХАМГИЙН БАГА, «гаргасан» огноо ч мөн ХАМГИЙН ЭРТ формат — watermark-тай нийцнэ).  Хуудсын
  тухайн формат амжилттай ба ШИНЭЭР гарсан үед л тэр форматын тэмдэг ахина — бүтэлгүйтсэн/цуцлагдсан/алгассан гаргалт тэмдгийг ӨГСӨХГҮЙ.  Нэг форматаар (PDF)
  гаргаад нөгөөгөөр (DWG) гаргаагүй хуудас «шинэчлэгдсэн» биш: `Partial` → «Хараахан гаргаагүй».
  ⚠️ **IFC нь хуудасны формат БИШ** (`PublishCheckpointStore.SheetFormats`): загварын түвшний ганц файл (`ItemId "*"`, гишүүнгүй) — хуудасны «бүрэн гарсан»
  нөхцөлд ОРОХГҮЙ (орвол Authority/Archive профайлаар нэг ч хуудас хэзээ ч «бүрэн» болохгүй байв).  Профайлд дараа нь формат (DWG) нэмэгдвэл хуучин «PDF-only»
  checkpoint «DWG дутуу» (`MissingFormats`) — «Хэсэгчлэн · … · DWG дутуу».
- **Шинжилгээ ПРОФАЙЛД холбогдоно** (`AffectedPublishSet.ProfileId` + `FormatsKey`, `AppliesTo`): хуудас бүрийн watermark профайл тутмын checkpoint-оос
  гардаг тул шинжилгээ ӨӨР профайл/форматын багцад хүчингүй — цонх профайл солиход «Өөрчлөлт» баганыг хоосолж, товчнуудыг идэвхгүй болгож, шалтгааныг тайлбарлана.
- **Impact checkpoint (`Kind=publish`)** ЗӨВХӨН бүх файл амжилттай, профайлын дүрмээр гарах БҮХ хуудсыг хамарсан, дахин оролдлого БИШ гүйлтэд — «энэ дугаар хүртэл
  БҮХ зүйл гарсан» гэсэн утгатай тул 50-ын 3-ыг гаргасан гүйлт бусад 47-ийн өөрчлөлтийг нуух ёсгүй (`ItemSelection.CoversAllSheets`).
- Бүгд «алгассан» гүйлт «Амжилттай» БИШ («Алгассан — шинэ файл гараагүй»).
- **DWG ҮРГЭЛЖ хуудас тус бүрээр** (Revit `ExportDWG` нэрийг файлын нэр/угтвар болгодог тул нэгтгэсэн DWG-ийн нэрийг баталгаажуулах
  боломжгүй).  Гаргалтын ӨМНӨХ planner-ийн нэр ба ДИСК дээрх файл хоорондын уралдаан (`TargetChanged`) илрэх бөгөөд гаргалт эхэлсний
  дараа нэр өөрчлөгдсөн бол «бүтэлгүйтсэн» тэмдэглэнэ, чимээгүй дарж бичихгүй.  Гаргалтын үед эзэн цонх `OwnerLock` (EnableWindow=false) —
  синхрон ажлын дундуур товч дарагдахаас сэргийлнэ.

## 2. Smart Count

`SmartCount/Core` (хайлтын загвар, evaluator, нэгж, бүлэглэлт) · `Revit/CountJob` (хэсэглэсэн цуглуулалт).

- Нөхцөл (AND/OR, нэг түвшин үүрлэнэ): ангилал, гэр бүл, төрөл, давхар, параметр (өөрийн/төрлийн).  Хадгалсан хайлт.
- **Хурдан шүүлт ЭХЭНД**: ангилал (quick) → ElementLevelFilter/ElementParameterFilter (slow, ЗӨВХӨН superset) → ЯГ шалгалт.
  ⚠️ Тоон `ElementParameterFilter` нь ЗӨВХӨН **нэг ангилалтай**, **төрөл тоолоогүй**, нэр дэвшигчдийн дунд **загварын (loadable family) instance БАЙХГҮЙ** үед
  ба параметр нь built-in/shared/project (id нь глобал) үед: ижил нэртэй параметр ангилал/family бүрт ӨӨР id-тай байж болох (нэг family built-in, нөгөө нь
  ижил нэртэй өөрийн параметртэй) тул эхний элементийн id-г бүгдэд хэрэглэвэл evaluator-т таарах элементийг native шүүлтүүр хасаж үр дүнг дутуу тоолно
  (`HasLoadableFamilyInstances`: `ElementClassFilter(FamilyInstance)` — удамтай тул Panel/Mullion ч орно; тодорхойгүй бол «байна» гэж үзнэ).  Үр дүн ЯГ хэвээр,
  зөвхөн хурдасгалт хэрэглэгдэхгүй (хана, шал, өрөө г.м. систем элементэд үлдэнэ).  **Нэгж ба хүлцэл**: хязгаар бүр ӨӨРИЙН нэгжтэй
  (`NumericBound.MinUnit/MaxUnit`: тодорхой нэгж > утга дахь дагавар > каноник — evaluator-ийн `TryTarget`-тай ИЖИЛ; `Between 50 cm … 1 m`), каноник руу
  хөрвүүлсний ДАРАА сольж харьцуулна; native тэлэлт нь evaluator-ийн `AbsTol/RelTol`-оос ≥2 дахин (эзлэхүүн/талбайн хил дээрх 1e-6 м³ хүлцэл фут³-д 3.5e-5 —
  хуучин тогтмол 1e-5 хүрэлцэхгүй байв).  Давхрын нэр `QueryEvaluator.Norm`-оор (trim + NFC) харьцуулагдана.  «Идэвхтэй харагдац» нь Revit-ийн
  «харагдаж БОЛОХ элемент» collector — crop-оос гадуурх/халхлагдсан элемент орж болох (хэт тоолох) тул тайланд ⚠ тэмдэглэнэ.
  Нэг нэртэй хэд хэдэн параметр (built-in + shared) байвал `GetParameters`-ээс ТОГТВОРТОЙ сонгож (утгатай нь, Id өсөхөөр) тайланд
  «ойлгомжгүй нэр» гэж ИЛ хэлнэ (`LookupParameter` нь «санамсаргүй нэгийг» буцаадаг).  Revit-ийн амьд `ElementType`-ийг Step хооронд
  хадгалахгүй — зөвхөн (id → family/нэр) хуулбар.  «Сонголтоос» тоолсон бол линк/дэд элемент орохгүйг тэмдэглэнэ.
- **Нэгж**: дотооддоо канон (урт→мм, талбай→м², эзлэхүүн→м³, өнцөг→°); хэрэглэгч `5 m`, `1.200,75 mm` бичиж болно.
  Нэгж таарахгүй = «шалгагдсангүй» (Problem) — `false` БИШ.  Параметр байхгүй нь ЗӨВХӨН «байхгүй» нөхцөлд таарна.
- Дүн: бүлгийн мод (ангилал/гэр бүл/төрөл/давхар/параметр) + мөр; «Сонгох», «Харуулах» нь хэт том сонголтоос хамгаалагдсан;
  загвар өөрчлөгдсөн бол «хуучирсан» тэмдэг; TSV хуулах.

## 3. Clash шалгах

`ClashCheck/Core` (дүрэм, fingerprint, lifecycle, spatial index) · `Revit/ClashJob`, `GeometryVerifier`.

**Конвейер** (`ClashJob`, хэсэглэсэн): дүрэм → A/B цуглуулах (host ба/эсвэл линк instance) → bbox (мм, host координат) →
**ТОР (spatial hash)**-аар нэр дэвшигч хос (O(n²) БИШ) → ЗӨВХӨН тэдэнд геометр → fingerprint → lifecycle-тэй нэгтгэх.

- **Дүн 4**: `ConfirmedClash` · `NoClash` · `Unsupported` · `GeometryError`.  **`Unsupported`/`GeometryError` ХЭЗЭЭ Ч
  `NoClash` болохгүй** — «шалгаж чадаагүй» ≠ «clash байхгүй» (хураангуйд тусдаа тоолуур, Boolean алдаатай хос байвал
  гүйлт «хэсэгчилсэн»).  Геометр = `BooleanOperationsUtils` (Intersect, Fine detail), хос бүрд try/catch, линкийн solid-ийг
  `SolidUtils.CreateTransformed(link.GetTotalTransform())`; solid кэш (LRU) нь загвар өөрчлөгдвөл/линк солигдвол цэвэрлэгдэж,
  native обьектууд `Dispose` хийгдэнэ.
- **Fingerprint** = хэш(дүрмийн id, дүрмийн ТОХИРГООНЫ хэш, элементийн хос — ЭРЭМБЭЛЭЛТГҮЙ).  ⚠️ XYZ координат ОРООХГҮЙ:
  хоолойг 20 мм шилжүүлэхэд ижил хос шинэ clash болж «зөвшөөрсөн» шийдвэр алдагдахгүй.  Сэргээн үүсгэсэн элемент (шинэ
  UniqueId) = шинэ clash (зориуд).  Дүрмийн тохиргоо (сонгогч, босго, алгасах) өөрчлөгдвөл хуучин issue-ууд «хуучин тохиргоо»-ны
  ТҮҮХ болж үлдэж, шинэ шалгалтын үр дүн БИШ (UI-д тусдаа).
- **Төлөв**: `Шинэ → Хянасан → Зөвшөөрсөн → Шийдэгдсэн`.  `Шийдэгдсэн`-г ХЭРЭГЛЭГЧ ГАРААР тавьдаггүй — ЗӨВХӨН дахин
  шалгалтын НОТОЛГООТОЙ: элемент устсан · bbox давхцахаа больсон · геометр «clash биш» гэж ЯГ баталсан · зориудын давхцал
  (join/hosted/холбогдсон MEP) болсон.  Нотолгоогүй (дэмжигдээгүй/алдаатай/цуцлагдсан) бол төлөв хэвээр + «баталгаагүй».
  Цуцлагдсан/бүрэн бус гүйлт юуг ч «Шийдэгдсэн» болгохгүй.  `Шийдэгдсэн` clash дахин илэрвэл `Шинэ` + түүх.
- **Зориудын давхцал** (`IgnoreJoined/Hosted/Connected`, өгөгдмөл ИДЭВХТЭЙ): Join Geometry, хост-хостолсон, шууд холбогдсон MEP.
- **Clearance (зай)**: загвар (`ClearanceMm`, `Inflate`) бэлэн, ГЭХДЭЭ геометрийн шалгагч БАЙХГҮЙ → validator ЯВУУЛАХГҮЙ,
  UI-д сонгох боломжгүй (тайлбартай).  «Зай шалгадаг» мэт хуурахгүй.
- **Хадгалалт**: шалгалтын дүн ба хэрэглэгчийн төлөв солилт НЭГ түгжээнд (`ClashStateStore.Update`: шинээр уншиж → өөрчилж → бичнэ)
  — Revit-ийн thread ба UI thread нэг файлыг зэрэг бичээд бие биеийнхээ өөрчлөлтийг дарахгүй.  Дүнг хадгалж чадаагүй бол гүйлт
  `Failed` (⚠ тэмдэглэл тэргүүнд) — «амжилттай» гэж харуулахгүй.
- **«Шийдэгдсэн»-ийн нотолгоо = тусдаа `Evidence` шат**: өмнөх идэвхтэй issue-ийн элементүүд одоо байгаа эсэхийг хугацаагаар хэсэглэж
  (≤100 мс Step) цуглуулна (олон мянган issue-д Revit-ийг царцаахгүй).  Гүйлт «бүрэн» биш (хязгаарт хүрсэн ЭСВЭЛ загвар шалгалтын явцад
  өөрчлөгдсөн) бол ЮУ Ч «Шийдэгдсэн» болохгүй.  ⚠️ Элемент `GetElement==null` нь «устсан» гэсэн үг БИШ байж болно: хаалттай workset-ийн
  элементийг Revit ачаалдаггүй → баримтад хаалттай workset байвал «байхгүй» гэж БАТЛАХГҮЙ (нотолгоо алга → «баталгаагүй»).
  **Орчны хурууны хээ** (`EnvironmentSignature`): workset нээх/хаах, линкийг дахин ачаалах/хөдөлгөх нь `DocumentChanged` БИШ — `ModelChangeCounter` үүнийг мэдэхгүй.
  Хаалттай workset-үүд (host + линк бүр), линк бүрийн одоогийн файл ба transform-ыг Prepare-д авч, нотолгоо цуглуулахын ӨМНӨ ба Finish-д харьцуулна;
  ялгаатай бол `_modelChanged` (гүйлт «бүрэн БИШ», юу ч Resolved болохгүй).  Линкийн instance ӨӨР файл руу дахин заагдсан (Reload From) бол өмнөх clash-ийн
  элемент «устсан» БИШ «мэдэгдэхгүй» (`ExistsLive` нь `LinkSlot.LinkDocId`-г `ElementKey.Doc`-той тулгана).  Нэр дэвшигч хос хайх Step ≤`VerifySliceMs` (нягт геометрт
  тогтмол 1500 элемент UI-г гацаадаг байв).
- **Линк**: линкийн instance-ийг ялгана (нэг файл хоёр instance-аар орсон ч); линк баримтыг ХЭЗЭЭ Ч өөрчлөхгүй; unload линк
  тоологдож тэмдэглэгдэнэ.  Линкийн элементийг сонгох = `Selection.SetReferences` + `Reference.CreateLinkReference(instance)`
  (Revit «host эсвэл линкийн элемент» гэж баримтжуулсан); бүтэлгүйтвэл host-ыг л сонгож, линкийнхийг сонгож чадаагүйгээ ИЛ хэлээд
  clash-ийн хайрцаг руу ойртуулна (`UIView.ZoomAndCenterRectangle`).
- **Нэр дэвшигч хос**: тор (spatial hash) нь нэг элементийг ≤216 нүдэнд (6×6×6), нийт ≤8 сая бичлэгт бүртгэнэ — хэтэрвэл `big`
  жагсаалтад (шугаман шалгана).  Өмнөх 1024 нүд нь урт элементтэй том загварт санах ойг тэсрэх эрсдэлтэй байв.

## 4. Өөрчлөлтийн нөлөө (Change Impact)

`ChangeImpact/Core` (загвар, граф, бүртгэл, нэгтгэгч) · `Revit` (capture, резольвер, индекс, job) · `Ui`.

### Бүртгэл (`ImpactCapture`)
- `DocumentChanged` handler = ХАЛУУН ЗАМ → **зөвхөн id-г `long[]` болгон хуулна** (≤ 5000/төрөл, нийт тоо хадгална),
  элемент УНШИХГҮЙ, диск/лог/түлхүүр тооцоолол ҮГҮЙ; багц бүрт цаг дээр суурилсан монотон `Seq`.
- 300 мс debounce-ийн дараа үндсэн thread дээр (`SmartExecutor`) элементийн ИДЕНТИТИ (UniqueId, ангилал, харагдац, хост) уншина —
  устгагдахаас ӨМНӨ.  **Устсан элементийн мэдээлэл ЗӨВХӨН энэ кэшээс** (өмнө нь өөрчлөгдөж/нэмэгдэж байсан бол).  Мэдээлэлгүй устгал
  тоологдож ИЛ хэлэгдэнэ (`UnresolvedDeleted`).
- Хязгаар: хүлээгдэж буй ≤ 2000 багц (дүүрвэл хамгийн хуучныг хаяж `DroppedBatches` — UI «цоорхой» гэж анхааруулна), санах ой/диск ≤ 400
  багц/80 000 мөр, кэш ≤ 60 000.
- **Цоорхойн тэмдэглэл ЯМАР Ч алдагдалд**: trim, цэвэрлэх, дараалал дүүрэх, handler алдах бүр `LostThroughSeq` (алдагдсан хамгийн ШИНЭ
  дугаар)-ыг тэмдэглэнэ; бүртгэл унтраалттай байсан хугацаа `TrackingGapThroughSeq`; диск дэх бүртгэл уншигдаагүй бол мөн цоорхой.
  Шинжилгээний муж (`from`-оос хойш) цоорхойтой огтлолцвол тайлан «бүрэн БИШ» (`ImpactCompleteness.HasLogGap`).  Handler нь зөвхөн
  id-г `long[]` болгож, УНШИХГҮЙ, диск/лог ХИЙХГҮЙ (хөнгөн, read-only).  Багцын id-ийн тоо хязгаарт хүрвэл `Truncated` (✂) гэж тэмдэглэнэ.
- Хүснэгтийн ба бүртгэлийн **ДОКУМЕНТЫН ТЭНЦҮҮЛЭЛ** (`DocumentTable<T>`): баримт тус бүрийн tracker; фон timer-ийн flush нь `Document`-д
  хүрэхгүй (`AllTrackers` жагсаалт).
- `TransactionRolledBack`/`GroupRolledBack` БҮРТГЭХГҮЙ (загварыг өмнөх төлөв рүү буцаасан).  Бүртгэл тасралтгүй дискэнд
  (20 с арын thread, хаах/хадгалахад).  ⚠️ Линк загварын ДОТОРХ өөрчлөлт бүртгэгдэхгүй.
- `Seq` = `unixMs×1024+тоолуур` (`ImpactSeq`): session хооронд өснө, диск хэрэггүй.  `Mark()` = «одоо»-гийн хаалт.
  **Цаг ухарвал**: `ImpactSeq.Observe(maxSeen)` нь диск дээрээс уншсан хамгийн ИХ дугаарыг (бүртгэл, шалгах цэг, тайлан, гаргалтын checkpoint, тохиргоо)
  тэмдэглэж, `Next()` хэзээ ч түүнээс БАГА гарахгүй (NTP/гараар засвар/VM сэргээлт); 30 хоногоос хол ирээдүйн (эвдэрсэн) утгыг тооцохгүй.
- **Идентити унших нь ХЭСЭГЛЭСЭН**: нэг багц 15 000 id (3×5000) байсан ч нэг дуудлагад ≤ 1200 id (багцад курсор) — өмнө нь бүтэн багцыг нэг Step-д уншиж Revit-ийн UI секундээр
  гацдаг байв.  `ImpactJob` эх сурвалж бүрийн зангилааг тусдаа `SourceNodes` Step-үүдэд (≤100 мс) уншина (20 000 `Node()` нэг Step-д биш).
- **Файл уншигдахгүй байхад давтахгүй**: ачаалах оролдлого бүр ≈240 мс унтдаг (SmartStore-ийн retry) тул `LoadFailed` үед 30 секундийн back-off — үндсэн thread-д
  300 мс тутам давтан гацахгүй.  API thread арын flush-ийн `PersistLock`-ийг ХҮЛЭЭХГҮЙ (`Monitor.TryEnter`, `Dirty` хэвээр); хаахад л ≤1.5 с хүлээнэ.
- **Цоорхой ДИСКЭД хадгалагдана**: дараалал дүүрч хаясан, handler алдсан (БҮХ tracker `Dirty`) ч тэмдэглэгээ дискэнд очно; ачаалсан файл ЭВДЭРСЭН/ШИНЭ хувилбарынх
  (`Corrupt`/`NewerSchema`) бол өмнөх түүх уншигдаагүй тул `LostThroughSeq = Mark()` (NewerSchema нь мөн «уншигдаагүй» — хэзээ ч дарж бичихгүй); хадгалах/хаахын өмнө
  хүлээгдэж буй (идентитигүй) өөрчлөлтийг эхлээд уншина (`SafeFlush`/`OnClosing`, хаалтад ≤1.5 с).
- **Баримт хаагдахад (`DocumentClosed`)**: хаалт цуцлагдсан ч event ирдэг тул `IsValidObject`-оор тусгаарлаж, хаагдсан баримтын tracker-ийг СҮҮЛЧИЙН удаа хадгална
  (`CleanClose = true`), идентитигүй үлдсэн өөрчлөлт = цоорхой; 3 оролдлогоор ч хадгалж чадахгүй бол цоорхойг ТУСДАА файлд (`SmartSettings.DocGapThroughSeq`, баримт тутам,
  ≤200) тэмдэглэнэ.  **Цэвэрхэн хаагдаагүй session**: бүртгэлийн файл `SessionId` + `CleanClose` тээнэ (session нээлттэй үед `false`); Revit унасан эсвэл ӨӨР Revit ижил
  файлыг ОДОО нээлттэй байлгаж байвал дараагийн session үүнийг цоорхой гэж ИЛ тэмдэглэнэ (сүүлийн ≤20 с-ийн хадгалагдаагүй өөрчлөлтийг өмнө нь ямар ч тэмдэггүй алддаг байв).
- **Хоёр session ижил файлд**: диск дэх файлын хурууны хээ (`урт:цаг`) бидний сүүлд бичсэн/уншсанаас өөр бол бичихийн ӨМНӨ дугаараар union-ээр нэгтгэнэ
  (өөр session-ийн багцыг дарахгүй).  ⚠️ Хоёр session ИЖИЛ `DocumentKey`-тэй ч төв файлын салсан хувилбарууд байж болох тул тэдний ElementId ижил байх нь ТААМАГЛАЛ.

| **A** | Шууд | Revit-ийн тодорхой холбоо, өөрчлөлт нь энэ зүйлийн ӨӨРИЙН агуулга дотор | `view_owner` (view-specific элемент → харагдац/хуудас), `viewport_sheet`, `schedule_instance`, өөрөө өөрчлөгдсөн хуудас |
| **B** | Магадлалтай | Өгөгдлийн холбоо байна, гэвч өөрчлөлт ҮНЭХЭЭР нөлөөлсөн эсэх мэдэгдэхгүй | `tag_host`, `dimension_ref`, `host_hosted`/`host`, `type_instances`, `dependent`, `level_views`, `room_boundary`, `room_side`, `group_member`, `mep_connected`, `view_template`, `dependent_view`, `revision_sheet` |
| **C** | Боломжтой | «Магадгүй харагдаж байна» — crop, нуугдсан, хаагдсан байж болно | `visibility` (харагдацын шүүлтүүр), `schedule_membership` (хүснэгтийн мөрөнд орсон) |
| **D** | Сул таамаг | Ангилал/хамаарлын ерөнхий таарц, шууд нотолгоо алга | `schedule_category`, `project_info` |

Замын итгэл = холбоо бүрийн ХАМГИЙН СУЛ нь.  Холбоо бүр: эх, зорилт, төрөл, итгэл, ШАЛТГААН, резольвер.  «Яагаад?» нь замын алхам бүрийг
(шууд ба таамаг алхмыг ялгаж) харуулна.  ⚠️ Схемийн хувьд Revit-ийн `FilteredElementCollector(doc, viewId)` нь «харагдаж МАГАДГҮЙ»
элементийг буцаадаг (crop-оос гадна байж болно, баримтжуулсан) тул харагдалт нь ХЭЗЭЭ Ч A/B болохгүй (C).

### Граф (`ImpactGraphBuilder`, цэвэр)
Хамгийн хүчтэй итгэл эхэнд (bottleneck/widest-path, нэг зангилаа ГАНЦ удаа дэлгэнэ); давталт/давхардал хамгаалалттай; хязгаар
`MaxDepth 6`, `MaxNodes 20 000`, `MaxEdgesPerNode 400`, `MaxExpansions 60 000` — хэтэрвэл ЧИМЭЭГҮЙ таслахгүй, `Notes`-д ИЛ бичиж
`Complete=false`.  Хэсэглэсэн (`Step`) тул цуцлах боломжтой.  Санамсаргүй граф дээр брут-форс лавлагаатай тулгасан тест бий.

### Шинжилгээний job (`ImpactJob`)
`Prepare → Sources → SourceNodes → Indexes → Graph1 → PostPlan → Post → Graph2 → Report`.  Graph1 = тодорхой холбоо (A, B); **Post** = өрөөний хил,
харагдалт (харагдац бүр тусдаа Step — Revit өөрөө «анх удаа удаан» гэж баримтжуулсан), хүснэгтийн мөр (C, D); Graph2 = бүгд.
Нэг элемент мужийн дотор олон удаа өөрчлөгдвөл нэг эх сурвалж; нэмэгдээд мөн мужийн дотор устсан = цэвэр өөрчлөлтгүй (`ChangeAggregator`, тестлэгдсэн).
Өөрөө өөрчлөгдсөн хуудас/харагдац/хүснэгт ШУУД (A) нөлөөлөл болж тайланд орно.

**«БҮРЭН БИШ»-ийн ГАНЦ эх сурвалж = `ImpactCompleteness.Reasons`** (цэвэр, тестлэгдсэн; UI анхааруулга, тайлангийн тэмдэглэл, Publish-ийн «яагаад
санал болгосон» гурвуулаа ЭНЭ жагсаалтаас).  Шалтгаан: бүртгэлийн цоорхой/унтраалт, хэт олон id-тай багц, эх сурвалж таслагдсан, устсан
элементийн мэдээлэл алга, **устсан загварын элемент** (аль харагдацад харагдаж байсныг ҮНДЭСЛЭЖ БОЛОХГҮЙ — Revit устсан геометрийг өгөхгүй),
граф хязгаар (гүн/зангилаа/сул холбоо), резольверийн cap/алдаа, төслийн ерөнхий тохиргоо, ШИНЖЛЭЭГҮЙ хэсэг (харагдалт/хүснэгт/өрөө сонгоогүй),
baseline уншигдаагүй, **уншигдаагүй (устсан/хаалттай workset-д байж болох) зорилт**, **уншигдаагүй ӨӨРЧИЛСӨН ЭХ СУРВАЛЖ** (бүртгэлийн мөрөөс сэргээж чадаагүй бол;
сэргээж чадвал `Seed` нь «мэдээлэл алга» тэмдэглэгээг бодит идентитиар СОЛИНО), **уншигдаагүй холбоосын зорилт** (харагдацад хамаарах элементийн эзэн харагдац, суулгасан элементийн
хост — өмнө нь чимээгүй алгасдаг байв), тохиргооны файл уншигдаагүй / бүртгэл ХАРААХАН ачаалагдаагүй (`GapInfo`).  «Нөлөөлөл олдсонгүй» нь шалтгаан байвал ХЭЗЭЭ Ч
«өөрчлөгдөөгүй» гэсэн баталгаа биш.  Хүснэгтийн холбоо давхардахгүй (кэш ч дедуплицирсан — `PathCount` хөөрөхгүй).

### Шалгах цэг
`ModelCheckpoint` = `ChangeSeq` (үндсэн хаалт) + Revit `DocumentVersion` GUID/saves (НЭМЭЛТ).  «Сонгосон цэгээс хойш» шинжилгээ нь
бидний бүртгэл + (сонголтоор) `Document.GetChangedElements(versionGuid)`-ийн бидний бүртгэлд ороогүй өөрчлөлт.  ⚠️ Revit өөрөө
GUID нь бүх өөрчлөлтөд шинэчлэгддэггүй гэсэн тул зөвхөн-засвар өөрчлөлтийг алгасаж болно.  ⚠️ Мөн `DocumentDifference`
**workshare-гүй загварт УСТГАСАН элементийг хөтөлдөггүй** (баримтжуулсан) — ямар ч «устгал алга» гэсэн дүгнэлт хийхгүй, шинжилгээнд ИЛ тэмдэглэнэ.  Энэ нь НЭМЭЛТ нотолгоо л.
Гаргалт бүрэн АМЖИЛТТАЙ (бүх файл шинэ, профайлын дүрмээр гарах БҮХ хуудсыг хамарсан, дахин оролдлого биш) болмогц `Kind=publish` цэг автоматаар бүртгэгдэнэ —
«энэ дугаар хүртэл БҮХ зүйл гарсан» гэсэн утгатай тул хэсэгчилсэн/зарим хуудсын гаргалт бүртгэгдэхгүй (хуудас бүрийн checkpoint-д зөв барьдаг).  Шалгах цэгийн файл
УНШИГДААГҮЙ үед `Add`/`Remove` «цэг байгаагүй, амжилттай» гэж худал хэлэхгүй — алдаа буцаана.

### Тайлан/UI
Цонх: өөрчлөлтийн багц (цаг, транзакц, +/~/−, ✂ хэт олон, ⚠ мэдээлэлгүй устгал) → «Шинжлэх» → итгэл (A/B/C/D өнгө, шошготой) ·
төрөл · хайлт → мөр сонгоход «Яагаад?» → «Харуулах/нээх» (хуудас/харагдацыг `RequestViewChange`, бусдыг сонгоно).  **Бүрэн бус**
шинжилгээнд «нөлөөлөл олдсонгүй ≠ нөлөөлөхгүй» гэж ИЛ анхааруулна; загвар өөрчлөгдсөн бол «хуучирсан».

## 4b. Өөрчлөхөөс ӨМНӨ нөлөө — «Өөрчлөхөөс өмнө» (add-in 1.16.0; хаалга зөөх 1.17.0; ямар ч элементийг хулганаар чирж зөөх 1.18.0)

Дээрх §4 нь өөрчлөлт ХИЙГДСЭНИЙ ДАРАА нөлөөг бүртгэнэ; энэ нь нэг шулуун ханыг зөөхөөс ӨМНӨ нөлөөг sandbox-д хэмжиж **НЭГ шийдвэр** гаргана:
🟢 ТЕХНИКИЙН ХУВЬД ЗӨӨЖ БОЛНО · 🟠 ХЯНААД ЗӨӨ · 🔴 ЗӨӨХГҮЙ · ⚪ ДҮГНЭХ БОЛОМЖГҮЙ (моделийн техникийн дүгнэлт — **Монгол нормын автомат баталгаа БИШ**, тусдаа мөр).
Preview ба «Хэрэгжүүлэх» нь commit-ийн ДАРАА (settled) ИЖИЛ төлвийг уншина; Apply = `TransactionGroup { move → settled тулгалт → Assimilate | RollBack }` (нэг Ctrl+Z).
Түр дүн → эцсийн дүгнэлт, кэш, DirectContext3D сүүдэр, зайн товч, зөөх НЭГ товч.  Код: `ChangeImpact/{Core,Revit,Ui}`, `SimulationScope.cs` + `DocChange.cs`
(`ImpactSimulationScope.Suppressed` — sandbox ∪ хойшлуулсан Apply үед MGL-ийн ажиглагчид early-return, баталгаажсаны дараа л нэг удаа дахин тоглуулна).
Интернэт/AI/төлбөр БАЙХГҮЙ.  Дэлгэрэнгүй, шийдвэрийн дүрэм, гар QA (release gate), CEO демо: [`CHANGE_IMPACT_RADAR_MVP.md`](CHANGE_IMPACT_RADAR_MVP.md).
**Хаалга зөөх (1.17.0)** — ИЖИЛ товч: хаалга сонгоод дарвал энэ ИЖИЛ хөдөлгүүр хаалганы операцоор ажиллана (хоёр дахь хөдөлгүүр БИШ — `IPreChangeOperation` seam).
Шинэ байрлал = хост ханын дагуух гарын тоо / ±10·50·100 мм товч / PickPoint (хананд проекцлогдоно) → хаалганы сүүдэр (DirectContext3D) + шууд хоёр түвшний шинжилгээ
(хурдан скан → яг sandbox, 220 мс debounce, generation, «сүүлийнх нь ялна») → «Зөвшөөрөх» = НЭГ бодит зөөлт («MGL — Хаалга зөөх», нэг Ctrl+Z) / «Болих» = моделд хүрэхгүй.
Дэлгэрэнгүй: [`CHANGE_IMPACT_RADAR_MVP.md`](CHANGE_IMPACT_RADAR_MVP.md) §14.
**ЯМАР Ч ЭЛЕМЕНТИЙГ ХУЛГАНААР ЧИРЖ ЗӨӨХ (1.18.0)** — цэс, диалог, зайн тоо БАЙХГҮЙ: Revit-д ямар ч элемент (хана, хаалга, багана, шал, суваг, тавилга…) сонгоод товч дарахад жижиг 3D цонх (WPF `Viewport3D`,
бодит геометр) нээгдэнэ; элементийг ХУЛГАНААР барьж чирэхэд мөргөлдөөн ШУУД УЛААНААР тодорч «Хэрэв та «X»-г эндээс тийш зөөвөл … дахин хийх эсвэл ийм асуудал гарах магадлалтай» гэж хэлнэ (түр дүн, цэвэр Core).
Тавьсны дараа Revit-ийн sandbox (`TransactionGroup`, ҮРГЭЛЖ RollBack) эцсийн дүгнэлт → «Зөвшөөрөх» = НЭГ бодит зөөлт («MGL — Элемент зөөх», нэг Ctrl+Z) / «Болих» = моделд хүрэхгүй.
Хулганы hook, Win32, AI, интернэт БАЙХГҮЙ.  Хуучин хана/хаалганы БҮТЭН шалгалт цонхны «…» цэснээс.  Дэлгэрэнгүй: [`CHANGE_IMPACT_RADAR_MVP.md`](CHANGE_IMPACT_RADAR_MVP.md) §15.
⚠️ **LIVE REVIT QA REQUIRED** — Revit дээр ХАРААХАН ажиллуулаагүй; production-д бэлэн гэж хэлэхгүй.

## 5. Өөрчлөлт → Smart Publish: «өөрчлөгдсөн хуудсыг л гаргах»

Гаргалт бүрийн ЭХЭНД `ImpactSeq.Mark()` хуудас бүрийн checkpoint-д бичигдэнэ (watermark).  «Өөрчлөлт шинжлэх…» (Publish цонхонд):
командын API контекстод хуудас бүрийн watermark-аас хойших өөрчлөлтийг шинжилнэ (watermark ≤ 3 бүлэгт; хуудас бүр ӨӨРИЙН watermark-аас ЭРТ
эхэлсэн шинжилгээнд хамрагдана → хуучин өөрчлөлт давхар тоологдож болно ч ХЭЗЭЭ Ч алдагдахгүй).

| Ангилал | Утга | Сонголтод |
|---|---|---|
| **Нөлөөлөгдсөн** | Шууд (A) нөлөөлөл | «Нөлөөлөгдсөнийг сонгох» |
| **Хараахан гаргаагүй** | Энэ профайлаар гаргаагүй (суурь байхгүй) | «Нөлөөлөгдсөнийг сонгох» |
| **Санал** | B/C/D, эсвэл «өөрчлөгдөөгүй гэж БАТЛАХ боломжгүй» | ЗӨВХӨН «+ Санал болгосныг нэмэх» (ИЛ) |
| **Шинжлээгүй** | Шинжилгээ хийгдээгүй/унасан | «+ Санал болгосныг нэмэх» |
| **Нөлөөлөл олдсонгүй** | Бүртгэсэн өөрчлөлтөөр холбоо олдсонгүй (БАТАЛГАА БИШ) | автоматаар ОРОХГҮЙ (гараар болно) |

«Олдсонгүй» нь ХЭЗЭЭ Ч чимээгүй баталгаа биш: шинжилгээ бүрэн бус, төслийн ерөнхий тохиргоо (Project Info, Revision, Phase...) өөрчлөгдсөн,
мэдээлэлгүй устгал, бүртгэлийн цоорхой, эсвэл Revit-ийн хувилбар гаргалтаас хойш өөрчлөгдсөн бол хуудас «Санал (D)» болж шалтгаанаа хэлнэ.
**Бүгдийг гаргах** («Бүгдийг» товч) үргэлж боломжтой.  Шинжилгээ хийгээгүй бол «Өөрчлөлт» багана хоосон, товчнууд идэвхгүй, хуудсыг
«өөрчлөгдөөгүй» гэж үзэхгүй.

## Revit дээр гараар шалгах жагсаалт (ҮЛДСЭН)

Доорх нь кодоор баталгаажуулах боломжгүй, ЖИНХЭНЭ Revit 2025–2027 дээр шалгах зүйлс.

**Суурь**
1. `DocumentKey` (CreationGUID) тогтвортой эсэх: ижил файлыг хаагаад дахин нээхэд ижил хавтас (`docs\<hash>`) ашиглагдана.  Revit-ийн баримтжуулалтаар CreationGUID = «анх үүсгэх үеийн» GUID тул «Save As» хуулбар ИЖИЛ түлхүүртэй (хуваалцсан түүх/checkpoint) байх магадлалтай — энэ нь хүссэн зан төлөв мөн эсэхийг шалга; local/central файл ижил түлхүүртэй эсэх.
2. Template-аас үүссэн хоёр төсөл ижил `ProjectInformation.UniqueId` авдаг эсэх (бид үүнд ТАЛАЛГҮЙ — зөвхөн CreationGUID).
3. Ribbon: 4 товч харагдаж, Family баримтад бүдгэрнэ; модаль цонх нээлттэй үед Smart цонх хөлдөхгүй.
4. `DocumentVersion.VersionGUID` файлыг хаагаад дахин нээхэд ТОГТВОРТОЙ эсэх (checkpoint-ийн НЭМЭЛТ нотолгоо; тогтворгүй бол «баримтын хувилбар солигдсон» гэж худал
   сэжиглэх эрсдэл — одоо baseline-ийг ашиглаагүй үед л сэжиглэнэ).
5. Хэрэглэгчийн профайл/түүхийн файлыг (`%APPDATA%\RevitMcpAddin\smart\`) нэг Revit-д нээлттэй байхад антивирус/өөр процессоор түгжиж үз → «хадгалж чадсангүй»
   гэж ИЛ гарч, файл хоосон болж ДАРАГДАХГҮЙ.

**Smart Publish** — нэг хуудас PDF · олон хуудас · нэгтгэсэн PDF · DWG (setup-тай; **хуудас тус бүр `<нэр>.dwg` гарч байгаа эсэх** — Revit `ExportDWG`-ийн `name`
нь файлын нэр юм уу угтвар юу гэдгийг баталгаажуулах) · IFC (загвар өөрчлөгдсөнгүй, undo түүх бохирдсонгүй, **гаргасны дараа Change Impact «хуучирсан» гэж худал
тэмдэглэхгүй**) · түгжигдсэн файл (PDF нээлттэй) → `OutputLocked`, дахин оролдлого · байхгүй хавтас · хэсэгчилсэн PDF (Revit `false` + файл) · гаргалтын дундуур
«Цуцлах» → checkpoint ахисангүй · нэршлийн давхардал · гаргалтын үеэр Publish цонхонд товч дарагдахгүй (`OwnerLock`) · PDF-ээр гаргаад DWG-ээр гаргаагүй хуудас
«Хараахан гаргаагүй» хэвээр.

**Smart Count** — ангилал + давхар + параметр (мм/м) нөхцөл; том загвар (50k+ элемент) дээр UI гацахгүй, «Зогсоох»; «Сонгох/Харуулах» хязгаар.

**Clash** — хоолой ↔ дам нуруу: clash гарна · хоолойг 20 мм шилжүүл → ИЖИЛ issue (шинэ биш) · «Зөвшөөрсөн» → дахин шалгахад «Шинэ» болохгүй ·
элементийг устга → дахин шалгахад «Шийдэгдсэн (устсан)» · Join Geometry хий → «Шийдэгдсэн (зориудын давхцал)» · арматур/2D → «дэмжигдээгүй», «clash биш» БИШ ·
линк загвар (хоёр instance) · линкийг unload · «Харуулах» (линкийн clash руу ойртоно) · «Зогсоох» → юу ч «Шийдэгдсэн» болоогүй.
**Шинэ (2026-10-01 дараа)**: (1) линкийн элементийг «A/B сонгох» нь `Selection.SetReferences` + `CreateLinkReference`-ээр ЖИНХЭНЭЭР сонгогдох эсэх (Revit 2025/2026/2027);
(2) workshared файлд workset-ийг ХААЖ дахин шалгах → тэр workset-ийн clash-ууд «Шийдэгдсэн (устсан)» БИШ, «баталгаагүй» болох;
(3) шалгалтын ЯВЦАД загварыг засах → «Загвар өөрчлөгдсөн» ⚠, юу ч «Шийдэгдсэн» болохгүй, гүйлт «ХЭСЭГЧИЛСЭН»; (4) clash-state файлыг түгжиж (өөр процесс)
шалгах → «⚠ Дүнг ХАДГАЛЖ ЧАДСАНГҮЙ», дүн нь «алдаатай» гэж харагдах; (5) 5 000+ clash сонгоод (Ctrl+A) UI гацахгүй.

**Smart Count (шинэ)** — нэг ангилал + тоон параметр (built-in, жишээ нь Length) → хурдасгагдаж, ЯГ ИЖИЛ тоо гарах (шүүлтүүргүйтэй харьцуул);
олон ангилал/family-ийн (family-ийн өөрийн) параметр → шүүлтүүр ИДЭВХГҮЙ, тоо дутахгүй; нэг нэртэй хоёр параметр (built-in + shared) → «ойлгомжгүй нэр» ⚠.
**2-р хяналтын дараа**: (1) хаалга/цонх (загварын family) дээр тоон нөхцөл → хурдасгалтгүй ч тоо ЯГ ижил; (2) `Between 50 cm … 1 m` (холимог нэгж) — тоо мм-ээр бичсэнтэй ижил;
(3) «идэвхтэй харагдац» тоо нь crop-оос гадуурх зарим элементийг оруулж магадгүй (⚠ тэмдэглэл); (4) «Давхар = Level 1 » (араас нь зайтай / кирилл өөр хэлбэр) ХООСОН биш.

**2-р хяналтын дараа — бүртгэл/хадгалалт (Change Impact)**
1. Revit-ийг ШУУД унагаад (Task Manager) дахин нээгээд шинжил → «өмнөх session цэвэрхэн хаагдаагүй» цоорхой гарч, «бүрэн БИШ» болох (ямар ч тэмдэггүй алдагдахгүй).
2. Нэг файлыг ХОЁР Revit-д нээж (хоёуланд нь засвар) → хоёр session-ийн багц нэгдэж, нэг нь нөгөөгийн файлыг дарахгүй; цоорхой тэмдэглэгдэх.
3. Баримтыг хаах → «Save changes?» дээр ЦУЦЛАХ → бүртгэл үргэлжлэх (tracker устаагүй); үнэхээр хаахад `impact-changes.json`-д `cleanClose: true`.
4. Системийн цагийг гараар ухраагаад засвар хийх → шинэ дугаарууд хуучнаас бага гарахгүй (шинжилгээний муж зөв).
5. Хаалттай workset-ийн элемент (workshared) → шинжилгээ «уншигдаагүй эх сурвалж/зорилт» ⚠-тэй; Clash-д workset-ийг шалгалтын ЯВЦАД хаавал гүйлт «хэсэгчилсэн».
6. 15 000+ элементтэй нэг багц (paste/array) → Revit-ийн UI гацахгүй, шинжилгээний «Эх сурвалж уншиж байна» прогресс хөдөлнө.
7. Тохиргооны файлыг (`settings.json`) түгжээд шинжил → «Тохиргооны файл уншигдсангүй» цоорхой.

**2-р хяналтын дараа — Smart Publish**
1. Authority Submission (PDF + IFC) профайлаар гаргаад → хуудас «Хэсэгчлэн» БИШ, бүрэн гарсан (IFC нь хуудасны формат БИШ).
2. PDF-only профайлаар гаргасны дараа профайлд DWG нэм → хуудас «Хэсэгчлэн · … · DWG дутуу»; «Өөрчлөлт шинжлэх» нь өмнөх профайлынх тул хүчингүй (тайлбартай).
3. «Өөрчлөлт шинжлэх»-ийн дараа ӨӨР профайл руу шилжих → «Өөрчлөлт» багана хоосон, «Нөлөөлөгдсөнийг сонгох» идэвхгүй.
4. Version горимд гаргалтын ЯВЦАД (өөр процессоор) `<нэр>_v2.pdf`-ийг үүсгэх → тэр файл `TargetChanged` (дарагдахгүй).
5. Гаргалтыг дундуур нь унагаад (файл түгжих) «Дахин оролдох» → өөрийн хэсэгчилсэн файл дарагдаж, ӨӨР хүний файл (TargetChanged) дарагдахгүй; Overwrite горимд асуулт гарна;
   өөр өдөр/сессид дахин оролдоход `{Date}`/`{Index}` ижил нэр гаргах.
6. «Алгах» (Skip) горимтой профайлаар (файлууд аль хэдийн байгаа) дахин гаргавал түүхэд «Алгассан — шинэ файл гараагүй» гэж харагдана («Амжилттай» БИШ).

**Өөрчлөлтийн нөлөө**
- view-specific (detail line) засах → харагдац + хуудас **A**; viewport зөөх → хуудас **A**; хуудасны title block параметр → хуудас **A**.
- Хана зөөх → өрөө/tag/хэмжээс/хаалга **B**, бусад харагдац/хуудас **C** («Магадлалтай/Боломжтой», «Шууд» БИШ).
- Хана/хаалганы ТӨРӨЛ засах → бүх хувилбар **B**.  Tag/хэмжээс устгах → харьяалах харагдац **A**.  Хуудас устгах → устсан хуудас **A** (нэр нь бүртгэлийн кэшээс; кэшэнд байгаагүй бол «мэдээлэл алга» гэж ИЛ).
- Undo/redo, Sync with Central (бусдын өөрчлөлт бүртгэгдэх), линк reload (дотор нь бүртгэгдэхгүй гэдгийг мэдэгдэнэ).
- Хүснэгт засах → хуудас **A**; хаалгыг засах → хүснэгт **C**/**D**.
- Checkpoint тавьж, засвар хийж, «цэгээс хойш» → зөвхөн тэр засвар; `GetChangedElements` ажилласан (бүртгэлд ороогүй өөрчлөлт) эсэх.
- 10 000+ элемент нэг дор (paste) → handler баллаа саатуулахгүй, `Truncated` (✂) тэмдэгтэй.

**Интеграц** — Publish → «Өөрчлөлт шинжлэх…»: ЗӨВХӨН нэг view-specific элемент засаад «Нөлөөлөгдсөнийг сонгох» нь ЯГ тэр хуудсыг сонгоно · гаргасны дараа «Шинжлээгүй» болж шинжилгээ цэвэрлэгдэнэ ·
Revit-ийг дахин асаасны дараа watermark хадгалагдсан.

## Мэдэгдэж буй хязгаар

- **Clearance** горим хэрэгжээгүй (архитектур бэлэн).  Нэгдсэн (nested) линкийн доторх линк тоологдохгүй.  Boolean үйлдлийг ХОС дундуур тасалж чадахгүй (Step-ийн хооронд л цуцална).
- Элементийн түвшин = `Element.LevelId` (параметрээр биш).
- **Линк загварын ДОТОРХ өөрчлөлт** Change Impact-д бүртгэгдэхгүй (зөвхөн энэ баримтын `DocumentChanged`) — тайланд үргэлж тэмдэглэнэ.
- **Хаалттай workset**: тэнд байгаа элементийг Revit ачаалдаггүй.  Count/Clash үүнийг ⚠ тэмдэглэнэ (тоо/шалгалт тэдгээрийг хамраагүй); Clash тэр
  элементийг «устсан» гэж БАТЛАХГҮЙ.  Change Impact хаалттай workset дахь өөрчлөлтийг харахгүй (Revit өгөхгүй).
- Нөлөөлөл: устсан элементийн харагдац/хуудсыг (өмнө нь бүртгээгүй бол) тодорхойлох боломжгүй → `UnresolvedDeleted`/`DeletedUnderivable`, Publish «санал»
  болгоно.  «Бүрэн индекс» (бүх элементийн идентити) БАЙХГҮЙ — зардал/ашгийн шийдвэр.
- `DocumentVersion.VersionGUID` нь элемент ҮҮСЭХЭД шинэчлэгддэг, бүх өөрчлөлтөд БИШ; устсан элементийг workshare-гүй загварт хөтөлдөггүй → зөвхөн НЭМЭЛТ нотолгоо.
- Группын commit дараа rollback хийвэл өмнө бүртгэсэн хэсэг commit-ууд «хэт тооцоо» болж үлдэнэ (аюулгүй тал).
- Төрлийн (type) өөрчлөлт бүр ангилалаар scan хийдэг; олон зуун төрөл нэг дор өөрчлөгдвөл удаан (хязгаартай, цуцлах боломжтой).
- Резольвер нэг ч удаа алдаа гаргавал шинжилгээ «бүрэн бус» гэж тэмдэглэгдэнэ (лог: `resolver_failed`) — бодит загвар дээр шалгах.
- `smart\docs\<hash>\` хавтас баримт тус бүрд үүсэх бөгөөд ашиглагдахаа больсон файлын хавтсыг ХЭЗЭЭ Ч цэвэрлэхгүй (файл бүр store-ийн хязгаартай:
  Publish түүх 200, Impact бүртгэл 400 багц/80 000 мөр, тайлангийн түүх 40, checkpoint 120, Clash 50 000 issue/60 гүйлт).
- **Revit гэнэт хаагдвал** (Task Manager, крэш) хадгалагдаагүй сүүлийн ≤20 с-ийн өөрчлөлт алдагдана — гэхдээ одоо дараагийн session үүнийг ИЛ цоорхой гэж тэмдэглэнэ (`CleanClose`/`SessionId`);
  Revit-ийн өөр instance ИЖИЛ файлыг нээлттэй байлгаж байх үед ч адил (тэр үед хоёр session-ийн ElementId ижил гэдэг ТААМАГЛАЛ).
  «Session нээлттэй» тэмдэг эхний засварын дараа ≈0.3 с-д (`EnsureLoaded` → шууд `Persist`), үндсэн thread завгүй бол (командын дунд) арын flush-ээр ≤20 с-д дискэнд тавигдана —
  энэ завсарт Revit унавал тэмдэг ч алга (цоорхой тэмдэглэгдэхгүй).  Revit-ийг ЦЭВЭРХЭН хааж байхад (`OnShutdown`) tracker бүр ≤0.8 с, нийт ≤2.5 с-д хадгалагдана; хугацаа/түгжээнд
  баригдвал цоорхойг тохиргоонд (`DocGapThroughSeq`) ШУУД тэмдэглэнэ (процесс дуусах тул дахин оролдохгүй).
- **Publish: бүтэлгүйтсэн ДАРЖ БИЧИЛТ нь хуучин амжилттай файлыг эвдэж болох** (Overwrite горим, Revit файлыг дарж бичсэний дараа алдаа) — `Advance` нь «бүтэлгүйтсэн гүйлт тэмдэгт хүрэхгүй»
  дүрмийг баримталдаг тул тэр хуудасны ХУУЧИН «сүүлд гаргасан» тэмдэг хэвээр үлдэж, UI хуучин огноог «гарсан» гэж харуулж болно.  Алдаатай гүйлт түүхэд ИЛ (хэсэгчилсэн файлын тэмдэглэлтэй) тул
  хэрэглэгч «Дахин оролдох» боломжтой; харин тэмдэг автоматаар хүчингүй болдоггүй (Version/Skip/Fail горимд хуучин файл бүрэн, асуудалгүй).  Сайжруулах санаа — доор.
- **Хуучин (формат тэмдэггүй) checkpoint**: профайлд формат НЭМЭГДСЭНИЙ дараа эхний гаргалтад шинэ формат бүтэлгүйтвэл хуучин checkpoint-ийн тэр форматын тэмдэг «зохиогдож»
  хуудас «бүрэн» харагдаж болно.  Формат тэмдэгтэй checkpoint энэ session-д л нэвтэрсэн тул бодит өгөгдөлд зөвхөн хөгжүүлэгчийн машинд байж болно.
- **`OwnerLock`** (`EnableWindow=false`) нь Revit-ийн ӨӨР модаль цонх (Save, анхааруулга) нээгдэхэд түр суларч болно — Publish-ийн синхрон гаргалтын үеэр ийм цонх гарвал товч
  дарагдах боломжтой хэвээр (бодит Revit дээр шалга).
- Clash «байхгүй» нотолгоо нь хаалттай workset-ийн элемент бүрээр БИШ, баримт бүрээр (workset хаалттай бол тэр баримтын БҮХ «байхгүй» нь «мэдэгдэхгүй») — хэт болгоомжтой тал.
  Нэр дэвшигч хосын `_seenFps` ба spatial grid санах ой том загварт (≤8 сая бичлэг) томорч болно.
- **Хадгалагдах enum-д шинэ утга нэмбэл** файлын `Schema`-г өсгөнө (шинэ утгыг хуучин add-in `Unknown(0)` болгож чимээгүй унших нь «аюулгүй тал» ч түүхийн утга алдагдана).
- Per-sheet «устгал алга» гэж workshare-гүй загварт хэзээ ч дүгнэхгүй (`DocumentDifference` устгал хөтөлдөггүй) — зөвхөн манай бүртгэлээс.
- ЖИНХЭНЭ Revit дээр АЖИЛЛУУЛААГҮЙ (доорх жагсаалт ҮЛДСЭН).  Revit-ийн `Document`/`Reference`/`Workset`/`DocumentDifference` зан төлөвийг баримтжуулалтаас
  (RevitAPI.xml) шалгасан ч бодит загварт баталгаажаагүй.  **Баталгаажаагүй таамаглалууд (UNSURE)**: `GetElement(uid)` хаалттай workset-ийн элементэд `null` эсэх;
  линк баримтад `Workset.IsOpen` зөв эсэх; `Selection.SetReferences` линкийн reference-ийг чимээгүй хаяж болох; `ElementLevelFilter` ↔ `Element.LevelId` бүх ангилалд ижил эсэх;
  `Save As` хуулбарын `CreationGUID`; `Raise()`-ийг `Execute` дотроос дуудахад `Pending` буцах эсэх (follow-up timer хамгаална).

### Production audit

Арга: (1) өөрийн кодын шүүмж; (2) Revit-ийн thread/транзакц/геометр/хадгалалт/worksharing чиглэлээр 3 хараат бус хянагч (код уншиж, баримтжуулалт тулгасан);
(3) олдвор бүрийг BLOCKER/HIGH/MEDIUM/LOW-оор ангилж, BLOCKER/HIGH-ийг ЗАСААД тест нэмсэн; (4) 4 тохиргоо (Debug R24–R27, мөн Release R24/R27) 0 алдаатай бүтсэн.

**BLOCKER**: олдсонгүй.  ⚠️ Энэ нь статик хяналт — ЖИНХЭНЭ Revit дээр ажиллуулаагүй тул «олдсонгүй» нь «шалгагдсан» гэсэн үг БИШ.

**HIGH (зассан)**
1. **Уншигдахгүй файлыг хоосон гэж уншаад дарж бичих** (антивирус/өөр процесс түгжсэн үед түүх, checkpoint, clash төлөв бүхэлдээ алга болно) →
   `LoadStatus.Unreadable` + хадгалахаас татгалзах (`PeekSchema` IO алдаа ч мөн); бүх «хадгалж чадсангүй» UI-д ИЛ.
2. **Change Impact: чимээгүй цоорхой** — trim/цэвэрлэх/дараалал дүүрэх/handler алдах/бүртгэл унтраах нь «нөлөөлөл олдсонгүй» гэсэн итгэлтэй харагдах дүн өгч болзошгүй
   байв → `LostThroughSeq`, `TrackingGapThroughSeq`, диск дэх бүртгэл уншигдаагүй флаг; НЭГ эх сурвалж `ImpactCompleteness` (граф хязгаар, резольверийн cap,
   таслагдсан багц, устсан загварын элемент, шинжлээгүй хэсэг, уншигдаагүй зорилт...).

   `complete = !capped && !modelChanged`, `Evidence` шат, хаалттай workset байвал «байхгүй» гэж БАТЛАХГҮЙ; хадгалж чадаагүй дүн «амжилттай» мэт харагдах → `Failed` + ⚠.

   Publish цонх МОДАЛЬ тул ExternalEvent ажиллахгүй · IFC-ийн rollback транзакц хуурамч өөрчлөлт оруулах · Impact бүртгэл санах ойд хязгааргүй өсөх.

**MEDIUM (зассан)**: Clash сонголтын O(k²) UI шинэчлэл · хуучирсан «бүрэн бус» анхааруулга цуцалсан дахин шинжилгээнд алга болох · хуулбар холбоо (`PathCount` хөөрөх,
