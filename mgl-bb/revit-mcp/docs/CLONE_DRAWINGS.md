## Ачааллын гол дүрмүүд (хэмжиж олсон)

- **Холбогдсон харагдац** = загвар (эсвэл түүний арматур/суусан элемент)-ыг tag-дсан эсвэл хэмжээсээр
  холбосон харагдац + гараар холбосон (`CdLinks.ManualViews`).  «Тусгай» (зорилт бүрд шинэ харагдац)
  vs «ерөнхий» (байгаа харагдацад нэмэх): тайрах хүрээ элементийн хэмжээнээс ≤ 4× (эсвэл +3 м) бол тусгай
  (`DedicatedRule`).
- **Буулгалт = орон нутгийн хайрцгийн «сунгалт»** (`Stretch.Axis`): хайрцгийн гадна → ойрын нүүрнээс
  хэмжсэн зай хадгалагдана; дотор → хувь хэмжээгээр.  Хэмжээ ижил бол хатуу хувиргалт.
- ⚠️ **Шугаман элементийн урт = ТЭНХЛЭГИЙН шугам (0…L), геометр БИШ.**  Дам нурууны геометр баганын
  холболтоор үзүүрээ тасалдаг (дам нуруу бүрт өөр) — геометрээр буулгавал тэнхлэг (grid) хүртэлх
  хэмжээс 3/6 зорилтод унасан.  **Баганын өндөр = түвшин + offset** (хавтантай холбогдож геометр
  тасардаг: 14 фут багана 11.5 гэж гарсан).  Геометрийн хэмжээ (`GeoMin/GeoMax`) ЗӨВХӨН «хэмжээсийн
  утгыг яг тулгаж болох уу» (`CdMap.SameSize`) шалгалтад.
- Шугаман элементийн чиглэлийг загвартай < 90° байхаар эргүүлнэ — баруунаас зүүн тийш зурсан дам нуруу
  180° эргэсэн зураг гаргахгүй.
- **Хэмжээсийн холбоос**: ижил family → stable representation-ийн UniqueId солих (лавлагааны хавтгай);
  үгүй бол геометрээр (эх нүүр ЗАХЫН нүүр бол зорилтын захын нүүр, үгүй бол буулгасан хавтгайд ≤1.5 см);
  тэнхлэг/түвшин → буулгасан байрлалд хамгийн ойр (≤15 см, `DatumTol` — дам нуруу тэнхлэгээс 15 мм
  зөрүүтэй зурагдсан байсан); туслах хавтгай → буулгасан хавтгай; хөрш элемент (тусгай харагдацад л) →
  байрлалаар.  Олдоогүй бол хэмжээс ҮҮСГЭХГҮЙ, тайланд тоологдоно.  Загварын өөрийн нүүрүүдийн хоорондох,
  хэмжээ ижил зорилт дээр утга ЯГ тэнцүү байх ёстой — зөрвөл буцаана.
- **Шинээр үүсгэсэн харагдац (CreateSection/CreateCallout/ViewPlan.Create) эх харагдацын VG-г авдаггүй**
  — callout parent-ынхоо тохиргоог авдаг (хэмжсэн: «Top of Footing» план баганыг нуудаг тул callout-д
  багана алга).  `CopyGraphics` ангилал/дэд ангиллын нуулт+override, filter-ийг хуулна (view template
  байвал хөндөхгүй).
- **Давхардал**: клон харагдац/хуудас `(эх uid, зорилтын uid)`-аар Extensible Storage-оос олдоно;
  tag = (төрөл, элемент); хэмжээс = ижил элементүүд + чиглэл + ИЖИЛ УТГА (үүсгэсний дараа тулгана —
  stable representation-оор тулгавал 25 давхардал, зөвхөн элемент+чиглэлээр бол нэг баганын өргөн ба
  төвөөс-ирмэг хэмжээсийг андуурна); spot = (төрөл, элемент); 2D = ижил төрөл + харагдацын ХАВТГАЙ дээрх
  төв (текстийн bbox гүний тэнхлэгт өөр).  Дахин ажиллуулахад 0 давхардал — хэмжсэн.
- **Tag (1.5.1)** — тусгай харагдацын БҮХ tag (зөвхөн загварынх биш) лавлагаа бүрээрээ буулгагдана:
  элемент → загвар/арматур/хөрш (хөршийг хатуу ≤15 см, олдохгүй бол ижил элемент харагдаж байвал өөрөө,
  эцэст нь СУЛ ≤1 м хамгийн ойр — ижил төрөл давуу, өөр төрөлд +15 см); нүүр (материалын tag) →
  `MapFaceRef`; link файлын элемент → тэр link-ийн доторх ихэр (`CreateLinkReference`).  Ижил төрөл,
  чиглэл (планд 90° → босоо), `RotationAngle`, `MergeElbows`, reference бүрийн leader.  Өрөөний tag →
  буулгасан цэгийг агуулах өрөө; арматурын MRA → тулгасан арматураар `MultiReferenceAnnotation.Create`
  (MRA-ийн дотоод tag-ийг тусад нь хуулахгүй).  3D: эх нь түгжигдсэн бол клоныг `SaveOrientationAndLock`
  хийж tag-ийг 3D цэгээр (хавтгайд проекцлохгүй).  Snowdon дээр: фасад 6/6 tag (захын дам нуруу, эргэсэн
  дам нуруунд тэр байрлалд ферм/багана БАЙХГҮЙ тохиолдол л алгасагдсан — тайланд шалтгаантай).
  Материалын tag-ийг Revit зарим нүүр дээр API-аар «can not be tagged» гэж татгалздаг (хэмжсэн).
- Фасадыг (ElevationMarker шаарддаг) ижил хүрээтэй ЗҮСЭЛТ болгоно.  CreateSection-ийн оролтын тэнхлэг
  (−Right, Up, −ViewDirection) — «Хуулж тавих»-д хэмжсэн.
- `CdLinks` Schema GUID `5b8f2c1e-7d4a-4e9b-9a61-3c2d8e7f1a04` — **ХЭЗЭЭ Ч бүү өөрчил, талбар бүү нэм**.

## 1.6.0 — элементийг нэрээр таних, зөвхөн холбоотой зураг, хурд (2026-09-30)

Эзний хүсэлт: «дам нуруу клонлож байвал зөвхөн дам нуруу орсон хэсгүүдийг л; бүх огтлолыг мэдрээд
удаад байна».  Snowdon-ы 133 харагдацтай файл дээр хэмжсэн.

- **Таних** — `Core/ElementKind.cs` (Revit-гүй, тесттэй): ангилал + family/төрөл + StructuralUsage →
  «Дам нуруу / Ферм / Налуу тулгуур / Прогон / Багана / Шон суурь / Туузан суурь / Хана …».
  `NameMatch.ContainsMark` — харагдац/хуудасны нэрэнд тэмдэг БҮТЭН үгээр («B1» ≠ «B12», кирилл «В1» =
  латин «B1»; «1», «12» шиг тэмдэг хэзээ ч таарахгүй).  Тест 33/33.
- **Шинжилгээ 3.1 с → 0.05 с** (`CdAnalysis.AnalyzeTemplate`): бүх харагдацыг скан хийхгүй.  (1) загвар +
  холбоотой элементийн `GetDependentElements` (tag, хэмжээс, MRA) — 2 мс; (2) нэрэндээ тэмдэгтэй харагдац +
  нэр/дугаартаа тэмдэгтэй хуудсан дээрх харагдац (`ShowsRegion`-оор шүүнэ); (3) гараар холбосон.
  `CdHostIndex` залхуу (`HostedBy` = dependents).  Хуучин бүтэн скан = `FindCandidates` — цонхны
  «Бусад харагдац хайх» товч (≈90 мс, 80 хүртэл).
- **Төрлөөр сонголт** — `CdTemplateInfo.AnnotationKinds` (олдсон харагдацуудын tag/хэмжээсийг элементийн
  төрлөөр тоолно; өрөөний tag = «Өрөө»), `CdOptions.AnnotationKinds` (null = бүгд).  `CdContext.AllowedKinds`:

  тоологдохгүй).  tag / хэмжээс / spot / өрөөний tag дөрвүүлээ; алгассаныг `KindFiltered`.  Өгөгдмөл =
  зөвхөн загварын төрөл; сонголт `CloneDrawingsPrefs.AnnotationKinds[загварын төрөл]`-д санагдана.
- **Клонлолт 13.2 → 6.0 с (зөвхөн дам нуруу), 15.0 → 7.7 с (бүгд)** — 6 дам нуруу × 5 харагдац + 6 хуудас.

## 1.9.1 — харагдацын шүүлт, арын горим, явцын самбар (2026-10-01)

Эзний хүсэлт: «клонлохдоо харагдацын шүүлт — хэт олон харагдац дууддаг, дам нуруу хийж байхад зөвхөн дам
нурууны харагдац; хурдан, зөв; клонлох дармагц бүх зүйл гацдаг — баруун талд явц хэдэн хувь болсон нь харагдаад
би Revit дотроо өөр ажлаа хийдэг байх».

### «Хэт олон харагдац»-ын шалтгаан ба ангилал

- **Гол шалтгаан (кодоос тогтоосон):** тусгай харагдацын БҮХ tag (хөршийнх ч) клонлогддог.  B1-ийг B2…B9 руу
  клонлосны дараа B1 нь B2…B9-ийн зүсэлтэд хөрш болж tag-лагддаг → дахин клонлоход `GetDependentElements` тэдгээр
  харагдацыг «B1-ийн зураг» гэж олж, хэмжээгээрээ «тусгай» тул зорилт БҮРД дахин хуулдаг байв (8 зорилт × 30
  харагдац).  Баганы, хавтангийн зурагт B1 tag-лагдсан бол мөн адил.
- **Ангилал** (`CdAnalysis.Classify` → `Core/ViewFilter.cs` `ViewRelevanceRule`, тесттэй) — дараалал чухал:
  гараар холбосон / загварт өөрт нь клонлосон → **өөрийн**; ӨӨР элементэд клонлосон (`CdLinks` бүртгэл:
  `Kind=view`, `TargetUid ≠ загвар`) → **бусад**; нэрэнд (эсвэл хуудасных нь нэр/дугаарт) загварын тэмдэг →
  тусгай бол өөрийн, том бол ерөнхий; нэрэнд өөр tag-лагдсан элементийн тэмдэг → бусад; тусгай биш (том хүрээ)
  → **ерөнхий**; өөрийн зургийн callout → өөрийн; тайрах хүрээний ТӨВ дээр өөр элемент (≥50% нь хүрээнд,
  25%-ийн хүлцэл) бөгөөд загвар төвд биш эсвэл тэр элемент илүү олон tag/хэмжээстэй → бусад; бусад нь өөрийн.
  ⚠️ «Төвд» нь «элементийн ихэнх нь хүрээнд» гэдгийг шаарддаг: баганын план callout-ийн төв нь дам нурууны
  ҮЗҮҮР дээр бас таардаг (6 м-ийн 1 м л хүрээнд) — хамралтгүй бол тэр callout «дам нурууны зураг» болно.
- **Өгөгдмөл:** зөвхөн «өөрийн зураг» сонгогдоно.  Хэрэглэгчийн өгөгдмөлөөс зөрүүлсэн сонголт харагдацын
  UniqueId-аар (`views_on`/`views_off`, сүүлийн 400), унтраасан төрөл загварын төрлөөр (`view_types_off`)
  санагдана.
- **Цонх:** гурван бүлэг (тус бүр гурван төлөвт чагттай, шалтгааны тэмдэглэлтэй мөр), дээр нь **хайлт** (үг бүр;
  кирилл/латин ижил дүрс ялгахгүй) ба **төрлийн товч** (план / зүсэлт / фасад / callout / 3D).  ⚠️ Шүүлтэд таарахгүй
  мөр КЛОНЛОГДОХГҮЙ (сонгосон ч) — урьдчилсан тооцоо «сонгосон N нь шүүлтээр нуугдсан тул орохгүй» гэж хэлнэ.
  Гарын холбоос (файлд хадгалах) нь шүүлтээс үл хамаарна.  «Аль элементийн tag» жагсаалт СОНГОСОН тусгай
  харагдацуудаас тоологдоно (бусад элементийн зураг сонгоогүй бол «Багана: tag 12» гарахгүй).

### Арын горим (`CdJob` + `CdJobHost`)

- Revit-ийн API зөвхөн үндсэн thread дээр — «арын thread» гэж байхгүй.  Ажлыг **алхам** болгож Revit сул
  зогсох бүрд (`UIControlledApplication.Idling`, `SetRaiseWithoutDelay`) ≈150 мс ажиллана; алхмын хооронд
  хэрэглэгчийн оролт боловсрогдоно.  Баримт: Idling нь «хэрэглэгч товч дарж чадах» үед л дуудагдана → модаль
  цонх, засварлах горим, өөр команд идэвхтэй үед клонлолт өөрөө хүлээнэ.  ExternalEvent-ийг СОНГООГҮЙ:
  Revit VS Code-ийн ард байхад Raise нь хулгана хөдлөх хүртэл «Pending» үлддэг нь хэмжигдсэн.
- **Нэг алхам = нэг Transaction** (Revit callback-ийн гадуур transaction/группийг нээлттэй үлдээхийг хориглодог).
  Алхам: загварын холбоо → бэлтгэл (эх тэмдэглэгээ) → зорилт бүрд: эхлэл → харагдац тус бүр → тэмдэглэгээ
  (харагдац тус бүр; том харагдац хугацаагаар хэд хэдэн алхамд хуваагдана, элемент тус бүрийн алдааг барина) →
  хуудас тус бүр → төгсгөл.  Нэр: «MGL клон 3/8 · B4 · харагдац «…»» — Revit-ийн Undo жагсаалтад ингэж харагдана.
- **«Нэг Ctrl+Z» алга** → самбарын **«Бүгдийг буцаах»**: тухайн ажлын transaction-уудаар НЭМЭГДСЭН элементийг
  (`DocumentChanged.GetAddedElementIds`) цагаан жагсаалтаар (харагдац/хуудас, tag, хэмжээс, MRA, текст, 2D,
  viewport) нэг transaction-д устгана.  Загвар, эх зураг хөндөгдөхгүй; өөрийг нь Ctrl+Z-ээр буцааж болно.
- **Хэрэглэгчийн Ctrl+Z клонлолтын алхмыг буцаавал** (Undo stack-ийн хамгийн сүүлд манай алхам байх нь элбэг)
  → ажил ТҮР ЗОГСОЖ шар мэдэгдэл гаргана; «Үргэлжлүүлэх» → тэр зорилтыг дахин хийнэ (давхардал шалгалттай тул
  дутууг л нэмнэ).  Бусад хэрэглэгчийн өөрчлөлт → дараагийн алхмаас өмнө кэшийг шинэчилнэ: устгал, Ctrl+Z/Y
  → файлаас бүрэн дахин уншина (`CdPlan.Resync`, `CdContext.ResetCaches`); зөвхөн нэмсэн/өөрчилсөн бол хөндөгдсөн
  кэшийг л (2026-10-02, доор «Хөнгөн шинэчлэлт»).
- **Алхам Revit-д буцаагдвал** (шийдэгдэхгүй алдаа): Revit-ийн алдааны цонх ГАРАХГҮЙ — `CdFailureHandler`
  чимээгүй буцаана (`ProceedWithRollBack` + clearAfterRollback), шалтгааныг тайлангийн «АЛДАА»-д бичнэ; тэр алхмын
  тоолуурыг `CdReport.Snapshot`-оор буцаана.  Тэмдэглэгээний алхам буцаагдвал тэр алхмын ЭХЛЭЛ рүү (`Mark`/`Rewind`)
  буцаад АЮУЛГҮЙ горимд (нэг алхамд нэг элемент) дахин хийнэ — шийдэгдэхгүй алдаатай ганц tag/хэмжээс л алгасагдана,
  бусад нь орно (`DetailCheck` 2D-г давхардуулахгүй).  Нэг нэгээр нь зөвхөн буцах үед хүрсэн цэг (`SafeUntil`)
  хүртэл, дараа нь дахин хурдан горимоор; нэг харагдацад хоёр дахь алдаатай элемент олдвол тэр харагдацын үлдсэнийг
  нэг нэгээр.  Хурдан алхмын буцаалт тайланд БИЧИГДЭХГҮЙ (`RunTx(quiet)`, тэр алхмын элемент тус бүрийн алдаа ч
  хасагдана) — нэг нэгээр хийхэд бүгд орсон бол тайлан «алдаатай» гэж худал хэлэхгүй; алдаатай элемент олдвол
  ТҮҮНИЙ шалтгаан + аль эх элемент («хэмжээс 12/40 · ID …») бичигдэнэ.  Дэлгэрэнгүй: доор «2026-10-02».
- **Самбар:** % (нэгж = зорилт бүрийн эхлэл/харагдац/тэмдэглэгээ/хуудас/төгсгөл), одоо юу хийж буй, ажилласан
  ба үлдсэн хугацаа (зөвхөн алхам хийсэн хугацаагаар), тоолуур, Түр зогсоох / Үргэлжлүүлэх / Цуцлах; дууссаны
  дараа тайлан, эхний хуудас/харагдацыг нээх, Бүгдийг буцаах.  Дараалал: нэг удаад нэг клонлолт.  Самбарын товч
  Revit API дуудахгүй (төлөв л); нээх/буцаах нь дараагийн Idling-д.  Алхмын дунд дарагдвал (Revit мессеж
  боловсруулбал) түр зогсоох/цуцлах нь алхам дуусахад.
- Арын хост эхлээгүй бол (OnStartup-д бүртгэл унасан) команд хуучин синхрон замаар (`CdRunner`, нэг Ctrl+Z).

1.9.1-ийн кодыг тусдаа шалгагч уншиж эвдрэл/өгөгдөл алдах гажиг ОЛООГҮЙ; доорх нарийвчлал, хурдын гажгийг засав:

  хавтгайгаар зүсдэг тул ЗАГВАРЫН зүсэлт дээр тавивал зорилт биш загварыг харуулдаг байв; загварт зориулсан план дээр
  тавивал тэмдэг нь загварын зурагт үлддэг байв.  Одоо энгийн зүсэлт/план болгон клонлоно (`TryCallout` → null);
  ерөнхий план дээрх callout хэвээр.
- **Хөнгөн шинэчлэлт** (`CdTouch`, `CdPlan.Forget`, `CdContext.Forget`): өмнө нь хэрэглэгчийн ЯМАР Ч засвар бүх кэшийг
  хаяж дараагийн алхмууд харагдах байдлыг (харагдац × ангилал тутамд ~0.3–0.4 с) дахин тооцдог байсан — хэрэглэгч
  клонлолтын хажуугаар ажиллах бүрд хэдэн секундын гацалт.  Одоо зөвхөн НЭМСЭН/ӨӨРЧИЛСӨН (устгалгүй, ≤2000 элемент)
  transaction-д хөндөгдсөн харагдац (тохиргоо), ангилал (харагдах байдал), элемент (нүүр), viewport (хуудсан дээрх
  байрлал), тэмдэглэгээ нэмэгдсэн харагдацын давхардал шалгалтын кэшийг л хаяна; харагдац/хуудас хөндөгдвөл нэр,
  дугаар, клоны бүртгэлийг дахин уншина.  Загвар, одоогийн зорилт, тэдгээрийн арматур/суусан элемент хөндөгдвөл,
  устгал, Ctrl+Z/Y, нэргүй/хоосон transaction → бүрэн `Resync` (өмнөх шиг).  Мөн БУСАД харагдацын харагдах байдлыг
  өөрчилдөг (тэдгээр харагдац «өөрчлөгдсөн» гэж мэдэгдэхгүй байж болох) элемент — харагдацын загвар (view template),
  шүүлтүүр, үе шат/үе шатны шүүлтүүр, дизайны хувилбар, workset-ийн харагдах байдал, scope box, түвшин, link, ангилалгүй
  танигдахгүй элемент → бүрэн (`CdTouch.ChangesOtherViews`).  Viewport-ын төрөл засагдвал хуудсан дээрх гарчиг/хайрцгийн кэш.
- **Тэмдэглэгээний алхам буцахад бүрэн Resync ХИЙХГҮЙ** — тэр алхамд үүсгэсэн tag/хэмжээсийн түлхүүр, `Dimension`
  объект зөвхөн тэр харагдацын кэшэд үлддэг тул тэднийг л хаяна (`CdContext.ForgetRolledBack`; устсан элементийн
  нүүр/төрлийн кэш — Revit буцаалтын дараа ID-г дахин олгож болно).  Аюулгүй горимд элемент буцвал эхлээд файлаас бүрэн
  дахин уншаад (хэрэглэгчийн засвараар хуучирсан кэш биш гэдгийг баталгаажуулж) тэр элементийг НЭГ удаа дахин оролдоно
  (харагдацад нэг удаа; хөнгөн шинэчлэлтийн дараа дахин нэг удаа); дахиад буцвал алгасна (алгассанд тоологдоно).
  Харагдацыг өөр хүн эзэмшиж (worksharing) байгаа бөгөөд нэг ч алхам амжилтгүйгээр 2 элемент буцвал үлдсэнийг алгасаж нэг
  мөрөөр тайлагнана; эзэмшилгүй харагдацад бөөнөөр ХЭЗЭЭ Ч алгасахгүй (элемент бүрийг шалгана).
- **Revit transaction нээхийг зөвшөөрөхгүй үед** (sketch/бүлэг засах горим г.м.) алхам «бүтэлгүйтсэн» гэж тоологдохгүй,
  юу ч алгасахгүй: «Revit одоогоор өөрчлөлт хүлээж авахгүй байна» гэж хүлээгээд хэрэглэгчийн дараагийн үйлдлийн дараа
  яг тэр алхмаас үргэлжилнэ (Idling-ийг шууд дахин дуудуулахгүй — CPU эргүүлэхгүй).  Файл зөвхөн уншихаар нээгдсэн бол
  зогсооно.
- **Алхмын нэр ажлын дугаартай** («MGL клон #2 · 3/8 · B4 · …») — ижил загварыг ижил элементүүд рүү дахин клонлоход хоёр
  ажлын нэр давхцаж Ctrl+Z/Y нөгөө ажлынхыг андуурдаг байв (нэг ажлын «Бүгдийг буцаах» нөгөөгийн клоныг устгах эрсдэл).
- **Эх нь клонлогдоогүй план callout** ижил давхарт `Duplicate` хийвэл загварын план дээр дахин callout үүсдэг байсан —
  одоо бие даасан план (`ViewPlan.Create`, callout-ын план төрөл эсвэл давхрын анхны план төрөл).
- **Тайлангийн тоо** зорилт × харагдац/хуудас тутамд нэг удаа (`CdReport.Once`) — Ctrl+Z-ийн дараах дахин хийлтэд
  тоологдсоныг дахин тоолохгүй, тоологдоогүйг тоолно; «өмнөх клоныг устгах» алхам Ctrl+Z-ээр буцвал устгасан тоо ба
  анхааруулга засагдана.
- **Ctrl+Z ба «Бүгдийг буцаах»:** Ctrl+Z манай алхмын элементийг устгавал `Created`-аас хасна, Ctrl+Y буцааж нэмнэ

  зарим элементийг устгахыг зөвшөөрөөгүй бол «буцаасан» гэж тэмдэглэхгүй, дахин дарах боломж үлдэнэ.  «Өмнөх клоныг
  устгаж шинээр» горимын ажилд баталгаажуулах цонх «өмнөх клон сэргэхгүй» гэж анхааруулна.
- Ctrl+Z гараар холбосон харагдацын transaction-ыг буцаавал дараагийн алхамд дахин бичнэ.  Ctrl+Z-ийн дараа шинээр
  үүсгэсэн харагдац/tag-ийн тоо давхар тоологдож болзошгүйг тайлангийн тэмдэглэл хэлнэ.
