## 1. Юу хийдэг вэ — НЭГ ШИЙДВЭР

Архитектор **нэг шулуун ханыг** сонгож, зайг товчоор (100 / 200 / 300 / 500 / 1000 мм эсвэл өөрийн тоо), талыг өрөөний нэрээр сонгоно.  MGL загварт ХҮРЭХЭЭС ӨМНӨ
«энэ зөөлтийг хийх үү?» гэсэн ГАНЦ хариулт өгнө:

| Шийдвэр | Нөхцөл (`PreChangeDecisionEngine`, ЦЭВЭР, тодорхойлогдсон) | Зөөх товч |
|---|---|---|
| 🟢 **ТЕХНИКИЙН ХУВЬД ЗӨӨЖ БОЛНО** | Revit зөвшөөрнө · сэргээлт батлагдсан · ШААРДЛАГАТАЙ бүх шалгалт дууссан · хянах/батлагдсан ноцтой нөлөөлөл **0** · **эцсийн** (Full) шат | «**N мм зөөх**» |
| 🟠 **ХЯНААД ЗӨӨ** | Дээрхтэй ижил, гэхдээ хянах (батлагдсан өөрчлөлт, хуудас, хэмжээс, шинэ өрөө…) нөлөөлөл бий, эсвэл зөвхөн **зөвлөх** шалгалт (харагдац, хүснэгт, join) дутуу | «**Хянаад N мм зөөх**» (баталгаажуулах цонхтой) |
| 🔴 **ЗӨӨХГҮЙ** | Revit татгалзсан (Pin, өөр хэрэглэгчийн эзэмшил, зөвхөн унших, хана/хост устах…) ЭСВЭЛ симуляци амжилттай ч **батлагдсан ноцтой** үр дагавар: хана алга, элемент устах, өрөө хаалттай байхаа болих/алга болох, хост алдах, шинэ MEP clash, гарцын зам тасрах, Revit-ийн алдаа | идэвхгүй · «Яагаад?» |
| ⚪ **ДҮГНЭХ БОЛОМЖГҮЙ** | Загвар анхны төлөвт буцсаныг батлаж чадаагүй · хана дэмжигдээгүй · хэрэгслийн алдаа · ШААРДЛАГАТАЙ шалгалт дутуу (өрөө, хэмжээс, хаалга/цонх, MEP, **тохируулсан** гарцын тооцоо, хамаарлын граф) · **түр дүн** (гүн шалгалт үргэлжилж байна) | идэвхгүй · «Шалгалтыг гүйцээх» |

**Дараалал:** Refused/Blocked → 🔴 · NotRestored/Unsupported/Faulted → ⚪ · (симуляци амжилттай) батлагдсан ноцтой → 🔴 · ШААРДЛАГАТАЙ дутуу → ⚪ · хянах → 🟠 · үгүй бол 🟢.
Түр (Quick) шатанд 🟢 **ХЭЗЭЭ Ч** гарахгүй.  Гарц **тохируулаагүй** нь шийдвэрт нөлөөлөхгүй (алдаа биш — тусдаа чип), харин тохируулсан гарцын тооцоо унавал ⚪.
Мөр бүр `ItemCodes` кодоор шийдэгдэнэ — Монгол текстээр БИШ.  `PrimaryReason` + дээд тал нь 3 шалтгаан («Яагаад?»).
**Хянах нөлөөлөл НЭГ Ч мөр 🟢-д нуугдахгүй:** Revit-ийн анхааруулга (`failure.warning`), хаалганы From/To өрөөний өөрчлөлт (`host.rooms`) өөрийн хураангуй шалтгаантай,
харин хүлээн зөвшөөрөгдсөн саармаг кодоос (`HandledReviewCodes`-д жагсаагүй) ЯМАР Ч шинэ хянах/батлагдсан мөр «Хянах» нийлбэр шалтгаан болж 🟠 өгнө (`AnyConfirmedOrReviewNoticeItem_CanNeverYieldGreen…`).

> ⚠️ **ЭНЭ НЬ МОДЕЛИЙН ТЕХНИКИЙН ДҮГНЭЛТ — ХУУЛЬ, МОНГОЛ НОРМ (БНбД)-ЫН ЗӨВШӨӨРӨЛ БИШ.**
> «**Монгол нормын автомат баталгаажуулалт хийгдээгүй.**» мөр шийдвэрээс ТУСДАА, ҮРГЭЛЖ (🟢 дээр ч) харагдана.  Ногоон нь нормын зөвшөөрөл мэт харагдах ёсгүй.
> Хэмжигдэхгүй зүйл «0» гэж харагдахгүй (мэдэгдэхгүй ≠ 0): «тооцоогүй», «тохируулаагүй», «шалгаагүй».

Үнэний 4 төлөв (`TruthState`): `CONFIRMED` · `REVIEW` · `NOT EVALUATED` · `INCOMPLETE`.  Мөр бүрийн ноцтой байдал өнгөөр ГАНЦААРАА биш — тэмдэг + үг.

## 2. 30 секундын ажлын урсгал (архитектор)

1. Revit-д ханаа сонго → «Өөрчлөхөөс өмнө» нээ.  Сонгосон хана **автоматаар** орно (нэмж товших шаардлагагүй).  Өөр хана сонговол цонх «Үүнийг шалгах» гэж санал болгоно (preview-г чимээгүй алдуулахгүй).
2. Зайн товч (**100 · 200 · 300 · 500 · 1000**) дар, эсвэл мм-ээр бичиж Enter.  Тал нь өрөөний нэрээр («Коридор тал руу» / «Оффис 203 тал руу»); эсвэл «**Зураг дээр тал сонгох**» — зураг дээр дарсан цэг ↔ ханын нормалийн скаляр үржвэрээр тал тодорно.
3. Шинжилгээ **автоматаар** эхэлж, ханын **сүүдэр** (ghost) Revit-д шууд харагдана (§7).  Эхлээд **Түр дүн** (өрөө, хэмжээс, хаалга), дараа нь **Эцсийн техникийн дүгнэлт** (MEP, гарц, хүснэгт, хуудас).
4. Шийдвэрийн самбар: тэмдэг + том үг, шалтгаан (≤3), «Юу өөрчлөгдөнө» (тэргүүн 3), 5 карт (Өрөө · Хэмжээс · MEP · Гарц · Хуудас — дарвал Revit-д харуулна), талбайн шилжилт, MEP шинэ/хуучин, гарцын мөр.
5. Доод талын НЭГ товч: «300 мм зөөх» / «Хянаад 300 мм зөөх».  🔴/⚪/түр дүн/хуучирсан/шинэлэг нь тодорхойгүй үед идэвхгүй.  **Хүчээр давах (override) товч БАЙХГҮЙ.**

«**Нарийвчилсан**» (анхнаасаа хаалттай): гарцын тохиргоо, оношилгоо (хугацаа, шалгасан хэсгүүд).  Толгойд төлөвийн мөр: `Өрөө ✓ Хэмжээс ✓ MEP ✓ Гарц — тохируулаагүй Норм — шалгаагүй`.
«Дэлгэрэнгүй» (хаалттай): батлагдсан/хянах/тооцоолоогүй мөрүүд бүрэн жагсаалтаар.  Нормал UI-д Node/Graph/Resolver/DTO/TransactionGroup/A-B-C-D гэх техникийн үг ГАРАХГҮЙ.

**Хуучирсан preview дээр «зөөх» дарвал:** хана ЗӨӨГДӨХГҮЙ → шинжилгээ автоматаар дахин ажиллана → «Загвар өөрчлөгдсөн тул хана зөөгдөөгүй…» → шинэ дүнг хараад хэрэглэгч **ДАХИН дарна** (хоёр дахь товшилт заавал).

**Workshare:** хэн ч эзэмшээгүй хана/хамаарах элементэд preview түр эзэмшил (checkout) үүсгэж болзошгүй → эхлэхээс ӨМНӨ нэг удаа асууна (татгалзвал шинжилгээ эхлэхгүй, нэг ханад дахин асуухгүй).  Өөр хэрэглэгчид эзэмшигдсэн хана/хост/хөрш хана → 🔴 (Refused).
Preview эзэмшлийг ХЭЗЭЭ Ч чөлөөлөхгүй (Revit-ийн API-аар checkout-ийг preview-д зайлсхийх боломжгүй — §8).

## 5. Settled төлөв, sandbox, Apply, ажиглагчийн хойшлуулалт

**Settled төлөв** = хөдөлгөөний транзакц **commit хийгдсэний ДАРАА**, гадаад группийг ХААГААГҮЙ барьж байхад уншсан төлөв.  Revit хязгаарлалт/join/хост/өрөөг commit-д л эцсийн төлөвт хүргэдэг тул
commit-оос ӨМНӨ уншвал бодит үр дүнгээс зөрнө.  **Preview ба Apply ЯГ ИЖИЛ цэг дээр уншина.**

```
PREVIEW   TransactionGroup { Transaction{ MoveElement → Regenerate → Commit }   ← failure processing ЭНД
                             SETTLED унших (группийг нээлттэй барьсаар) }
          tg.RollBack()  ← ҮРГЭЛЖ finally дотор.  Assimilate ХЭЗЭЭ Ч үгүй (preview-г Undo-д оруулахгүй).
          → зориулалттай restore fingerprint: хана, хост, хөрш хана, stamp, нэмэгдсэн/устсан id (бүх элементийн тоо БИШ — зөвхөн STRICT оношилгоонд)

APPLY     TransactionGroup { Transaction{ MoveElement → Regenerate → Commit }
                             SETTLED унших → PreChangePostCommitGate.Decide(preview.After, бодит)
                             таарвал  tg.Assimilate()  (НЭГ Undo)    таарахгүй/тулгаж чадахгүй бол  tg.RollBack()  (БҮГДИЙГ буцаана) }
```

Тулгалт нь ханын ӨӨРИЙН settled байрлалыг үргэлж харьцуулдаг тул өрөө/хэмжээс/хаалгагүй хананд ч «юуг ч тулгаагүй» хоосон баталгаа гарахгүй.  Тулгаж чадахгүй бол fail-closed (буцаана).

**Хоёр дамжлага:** `Quick` = Core (хана, өрөө, хэмжээс, хаалга/цонх, хөрш хана) → түр дүн; `Deep` = хүснэгт, MEP, гарц, орчны зай, шинээр харагдах харагдац.  Хоёр дамжлага ИЖИЛ хөдөлгөөнийг турших тул settled
байрлал ижил байх ёстой (`SettledDifferences`) — зөрвөл нэг тайланд нийлүүлэхгүй, ШААРДЛАГАТАЙ дутагдал болно.

**MGL-ийн ажиглагчид** (`ChangeTracker`, `ModelChangeCounter`, `ImpactCapture`, `RevitIntelligenceHost`, `CloneDrawings`):
- Sandbox үед: `ImpactSimulationScope.Suppressed` (thread-static) → early-return.
- Apply-ийн дотоод commit: ажиглалт **хойшлогдоно** — үйл явдал хуулбарлагдан (`DetachedDocChange`, Revit обьектгүй) буферлэгдэнэ; `Assimilate` АМЖИЛТТАЙ болсны ДАРАА л `ImpactObservationSinks`-ээр
  **нэг удаа** дарааллаар нийтлэгдэнэ; `RollBack` бол хаягдана (хэзээ ч болоогүй өөрчлөлт түүхэнд үлдэхгүй, бодит өөрчлөлт алдагдахгүй).  Sink бүр тусдаа try/catch.
- Анхаар: **гуравдагч талын add-in-ууд** дотоод commit/rollback-ийн `DocumentChanged`-ийг ХАРНА — бид зөвхөн MGL-ийнхийг хаадаг (§8).

**Apply-ийн бүлгийн төлөв (fail-closed):** `Assimilate`/`RollBack` шидэж эсвэл `Committed`/`RolledBack` биш буцаавал `tg.GetStatus()`-ийн ҮНЭН төлвөөр шийднэ:
`Committed` → нийтэлнэ · Revit өөрөө буцаасан (`RolledBack`) → хаяад «Failed» · төлөв тодорхойгүй → бүлгийг буцааж үзнэ; буцаалт БАТАЛГААГҮЙ бол `ModelMayBeModified`, ажиглагчийн
тэмдэг (`ModelChangeCounter.ForceBump`) хүчээр урагшилж, өөрчлөлтийн бүртгэлд «цоорхой» тэмдэглэнэ, plan кэш хаягдана.  Амжилттай Apply-ийн дараа ч тэмдэг урагшлаагүй бол (`EnsureAdvanced`) хүчээр урагшуулна —
өмнөх preview хэзээ ч «Fresh» үлдэхгүй.  Sandbox-ийн `NotRestored` ч мөн тэмдэг урагшуулж, `Faulted`/`NotRestored` кэш хаяна.  Түр бүлэг НЭЭГДЭЭГҮЙ (Revit хаасан) бол «Revit зөвшөөрөөгүй» (🔴) БИШ — «дүгнэх боломжгүй» (⚪).

**Линк/гарцын тохиргоог уншиж чадаагүй** бол `PreChangeCacheKey.Unverifiable` ТОГТМОЛ тэмдэг тавигдана (санамсаргүй цуваа БИШ): кэш хэрэглэгдэхгүй, `PreChangeStale` `Unverifiable` (хоёр талд ижил ч «тэнцүү» гэж үзэхгүй) →
Apply «шалгаж чадсангүй» гэж татгалзана.  Аль ч баримт хаагдахад plan кэш бүхэлдээ хаягдана.

**Хуучирсан эсэх (fail-closed):** `PreChangeFreshness` нь `Fresh` / `Stale` / `Unknown`.  Stamp уншигдаагүй, хурууны хээ байхгүй, exception → `Unknown` = **Fresh БИШ** → Apply хаалттай.
Apply-ийн мөчид бүтэн хурууны хээ (хана, байрлал, төрөл, вектор, хамаарлын хэш, **линк**, **гарцын тохиргоо**, stamp) дахин тооцогдож `PreChangeStale.Evaluate`-аар тулгагдана.

## 6. Гүйцэтгэл

**Хэмжих механизм (бодитоор бичигдсэн):** `StageClock` — шат тус бүрийн ҮНЭН хугацаа (`Measure`, нэг шат давтагдвал нийлбэр) + тэмдэг (`first_result`, `full_result`).  Өмнө нь шатны «хугацаа» нь
хуримтлагдсан (`move` = before+move, `rollback` = before+move+rollback) байсан тул оновчлолд ашиглагдахгүй байв.  Шатууд: `validate`, `indexes`, `graph1/2`, `post`, `deps`, `plan_rooms/mep/egress`,
`visibility_reduce`, `before.{source,rooms,dimensions,hosted,joined,schedules,mep,egress,clearance}`, `sandbox_{quick,deep}`, `move_regenerate`, `commit`, `after_capture`, `rollback`, `restore_check`, `report`.
Лог: `SmartLog` `prechange/preview_finished` (ЛОКАЛ) — кэш hit/miss, нэр дэвшигчийн тоо, `firstResultMs`, `fullResultMs`, `totalMs`, шат тус бүр.  «Нарийвчилсан → Оношилгоо»-д харагдана.

**Оновчлол (шалтгаан тус бүрийг ТОДОРХОЙ арилгасан):**

| Өмнө | Одоо |
|---|---|
| Preview бүрт хамаарлын граф, индекс, харагдалтыг эхнээс | **Кэш** (`PreChangePlan`, түлхүүр = файл + stamp + хана + линк + гарцын тохиргоо): 200→300→500 мм-д дахин БАРИХГҮЙ.  Кэшэнд зөвхөн id/хуулбар (амьд Document/Element үгүй; hub `Attach/Detach`) |
| ӨМНӨХ төлвийг sandbox ДОТОР унших (группийг удаан нээлттэй барих) | ӨМНӨХ төлөв sandbox-оос ГАДНА (Step тусдаа), зайнаас хамааралгүй хэсгүүд `BeforeMemo`-д (өрөө, хэмжээс, хаалга, хөрш хана, хүснэгт, MEP-ийн ӨМНӨХ хос, гарцын зам, орчны зай) |
| Хаалттай биш өрөөний БҮХ өрөөг preview бүрт скан | `UnenclosedRoomIndex` нэг удаа (кэштэй) |
| Буцаалтыг БҮХ элементийн тоогоор шалгах (том загварт үнэтэй) | Зориулалттай restore fingerprint (хана, хост, хөрш, stamp); бүх элементийн тоо зөвхөн `MGL_PRECHANGE_STRICT_RESTORE=1` |
| «Шинээр харагдах» харагдацын нэр дэвшигчийн эхний 400-г л | **Батлагдсан-аюулгүй багасгагч**: crop идэвхтэй ба хананы (шилжсэн) хүрээ crop-ийн X/Y-ээс гадуур бол хасна; perspective/уншигдаагүй/crop-гүй хэвээр (үл мэдэх нөхцөлд ХАСДАГГҮЙ) |

**Цэвэр логикийн тест (Линукс):** кэш (түлхүүр бүрийн өөрчлөлт, LRU, stale-ийг хасах), `StageClock` (нийлбэр, тэмдэг, exception), restore/settled, snapshot merge (мутаци үгүй), ажиглалтын буфер.  **Бодит мс Revit дээр ХЭМЖИГДЭЭГҮЙ.**

## 7. Сүүдэр (ghost) — DirectContext3D

`IDirectContext3DServer` — ханын ШИНЭ байрлал (чиглүүлсэн призм: ханын bbox-ийн төв, байрлалын шугамын чиглэл/урт, зузаан, bbox-ийн Z) + хуучин байрлалын саарал контур + хөдөлгөөний сум.
Өнгө = шийдвэр: ногоон / шар / улаан / саарал (шинжилгээ явж байх, түр дүн, ⚪).  **Загварт ЮУ Ч БИЧИХГҮЙ:** DirectShape, транзакц, Undo, түр элемент, сонголт, параметр — үгүй (`Ghost_NeverWritesToTheModel…` тест).
Цэвэрлэгээ: цонх хаагдах · шинжилгээ цуцлагдах · хана солигдох · Apply амжилттай болох · «Цуцлах» · баримт хаагдах (`DocumentClosing`) · загварт БОДИТ өөрчлөлт орох (`DocumentChanged`, sandbox/хойшлуулсныг тооцохгүй) · Revit унтрах (`SmartHost.Shutdown`).  Сервер бүрэн хасагдана (`RemoveServer`).
⚠️ Хязгаар: призм нь ТОВЧЛОЛ (join-оор сунасан төгсгөл, давхарга, хаалганы нүхийг зурахгүй) — зөвхөн харааны чиглүүлэг.  Төлөвлөгөө/зүсэлт/фасад дээр зурагдах эсэх Revit-ийн хувилбараас хамаарна (3D дээр найдвартай); зурагдахгүй бол ЗӨВХӨН харагдахгүй.

## 8. Дэмжигдэхгүй / мэдэгдэж буй хязгаар

- Зөвхөн **нэг шулуун хана** (муруй, Curtain, Stacked, бүлгийн гишүүн, design option, линк доторх хана — шалтгаантайгаар татгалзана).
- **Гуравдагч add-in-ууд** sandbox ба Apply-ийн дотоод commit/rollback-ийн `DocumentChanged`-ийг харна — Revit-ийн хязгаар, баримтжуулсан.  Тэдний ажиглалтыг хойшлуулах боломжгүй.
- **Workshare checkout:** preview түр эзэмшил үүсгэж болзошгүй, rollback эзэмшлийг ЧӨЛӨӨЛДӨГГҮЙ, дэмжигдсэн API-аар зайлсхийх боломжгүй → эхлэхээс ӨМНӨ асууна.  `GetCheckoutStatus` нь кэштэй төлөв (сануулга, баталгаа БИШ); checkout-ийн төлөв `DocumentChanged`-д ордоггүй тул кэшээс хамааралгүй БҮР preview-д дахин шалгана.
- Линк дотоодын MEP: линк unload / workset хаалттай бол `INCOMPLETE` (шалтгаантай).  Линк доторх элементийг host-д сонгох боломжгүй тул «Харуулах» нь линк загварыг сонгоно.
- Гарц зөвхөн тохируулсан гарцтай; **сонгосон гарц хүртэлх Revit Path of Travel — нормын дээд зайтай тулгаагүй.**  Бүрэн evacuation-ийн норм биш.
- Талбайн шилжилт зөвхөн хоёр талдаа хаалттай, уншигдсан өрөөнөөс; «борлуулах талбай» гэж ХЭЗЭЭ Ч нэрлэхгүй.
- Харагдац нь харагдах байдлаар (visibility) тодорхойлогдоно; хүснэгтийн мөр нь collector жинхэнэ ажилласан үед л `Evaluated`.
- Том загвар: MEP/гарц budget-ээр хязгаарлагдана → `INCOMPLETE`.  Түр дүн UI-д Step хурдан үед зурагдахгүй (§6).
- Сүүдэр нь товчлол (§7).

## 10. Revit дээр гараар шалгах жагсаалт — RELEASE GATE (хийгдээгүй)

Бэлтгэл: хэд хэдэн өрөөтэй, хаалга/цонхтой, хэмжээстэй, нэг хуудсан дээр зүсэлт/план бүхий жишиг загвар (Revit 2025/2026/2027), нэг линк (MEP).  Add-in-ийг ЗӨВХӨН `package-addin.ps1` багцаас суулга (`-p:DeployToRevit=true` ХЭРЭГЛЭХГҮЙ).

**A. Preview нь загварыг ӨӨРЧЛӨХГҮЙ**
1. Preview-ийн дараа Undo түүхэнд ШИНЭ мөр БАЙХГҮЙ; ханын байрлал/хэмжээс/хаалга хөдлөөгүй; «Загварт өөрчлөлт хийгдээгүй».
2. Preview-ийг дараалан 5 удаа (зай/тал солиж) — Undo түүх, элементийн тоо, stamp хэвээр.
3. Түгжигдсэн хэмжээс/pin/join/align-тай хана → 🔴 эсвэл ⚪, загвар хөндөгдөөгүй.
4. Preview явж байхад Esc/«Цуцлах»/зай солих → загвар хөндөгдөөгүй, дараагийн шинжилгээ зөв.

**B. Apply = нэг Undo, бодит = preview**
5. 🟢 дээр «N мм зөөх» → хана яг зөөгдөнө, «Зөөсний дараах бодит төлөв preview-тэй таарсан».  **Нэг Ctrl+Z** хана буцаана; Ctrl+Y дахин зөөнө.
6. Preview-ийн дараа ханыг гараар өөрчлөөд «зөөх» → ЗӨӨГДӨХГҮЙ, автоматаар дахин шалгана, хоёр дахь товшилт шаардана.
7. Preview ба Apply-ийн settled өрөөний талбай, хаалганы байрлал, хэмжээсийн утга ижил (QA хүснэгтээр).
8. Apply-ийн дараа MGL-ийн ажиглагчид (өөрчлөлтийн бүртгэл, AI туслахын ChangeSeq) яг НЭГ өөрчлөлт бүртгэсэн; Apply буцсан (mismatch) үед ЮУ Ч бүртгэгдээгүй.
9. Third-party add-in-ийн `DocumentChanged` хэдэн удаа дуудагдсаныг ажигла (мэдэгдэж буй хязгаар).

**C. Шийдвэр**
10. Өрөө хаалттай байхаа болих → 🔴.  Хаалга host алдах → 🔴.  Шинэ MEP clash (host ба линк) → 🔴, хуучин clash «шинэ» болохгүй.
11. Линк unload → ⚪ (шалтгаантай), ногоон БИШ.  Гарц тохируулсан + зам тасрах → 🔴; тохируулаагүй → ногоонд нөлөөгүй.
12. «Монгол нормын автомат баталгаажуулалт хийгдээгүй.» мөр ТУСДАА, 🟢 дээр ч харагдана.
13. Түр дүн нь хэзээ ч 🟢 харуулдаггүй, зөөх идэвхгүй.

**D. UX ба сүүдэр**
14. Сонгосон хана цонх нээхэд автоматаар орно; Revit-д өөр хана сонговол «Үүнийг шалгах» санал гарч, preview алдагдахгүй.
15. «Зураг дээр тал сонгох»: хананы аль талд дарсан нь тухайн тал (өрөөний нэртэй) болно; 3D харагдац дээр ойлгомжтой алдаа.
16. Сүүдэр 3D дээр, мөн план/зүсэлт/фасад дээр зурагдах эсэх (хязгаар §7).  Өнгө шийдвэрийг дагана.
17. Сүүдэр арилна: цонх хаах · «Цуцлах» · хана солих · Apply амжилттай · баримт хаах · Revit хаах.  Undo түүх, сонголт, параметр хөндөгдөөгүй.
18. Нөөц: ghost-тай үед Revit-ийн view navigation (zoom to fit) хэвийн.

**E. Workshare**
19. Эзэмшилгүй хана → эхлэхээс өмнө асуулт; татгалзвал шинжилгээ эхлэхгүй, нэг ханад дахин асуухгүй.  Өөр хэрэглэгчийн хана/хост → 🔴.

**F. Гүйцэтгэл (ХЭМЖИХ — одоогоор хэмжээгүй)**
20. 50k+ элементтэй загвар дээр: UI гацалт (Step тус бүр), `firstResultMs`, `fullResultMs`, кэш hit-ийн дараах зай солилт — `prechange/preview_finished` логоос уншина; тоог энэ баримтад ЭНД нэм.

## 14. ХААЛГА ЗӨӨХ — интерактив simulation (add-in 1.17.0)

> # ⛔ LIVE REVIT QA REQUIRED (§14.9)
> Энэ хэсгийн Core (геометр, шийдвэр, төлөвийн машин, зураглалын угсралт), controller, source-grep хамгаалалт Линукс дээр тестлэгдсэн.  **Revit-тэй харилцах БҮХ зан төлөв
> (door `MoveElement` + settled төлөв, hosted door-ийн `FromRoom/ToRoom`, DirectContext3D ghost/тодруулга, PickPoint snap, том загварын хурд) Revit дээр ХАРААХАН ажиллуулаагүй.**
> «Ажиллаж байна» гэж ХЭЛЭХГҮЙ.  Хугацаа (мс) — §14.11-д ЗӨВХӨН хэмжсэн утга.

### 14.1 Юу хийдэг вэ — 30–60 секундын ажлын урсгал (захирал, архитектор)

1. Revit-д **нэг хаалга** сонгоод **«Өөрчлөхөөс өмнө»** дар (эсвэл ханаа сонгосон бол хана зөөх; юу ч сонгоогүй бол «Хаалга зөөх / Хана зөөх» гэсэн богино асуулт).
   Цонх хаалгыг АВТОМАТААР авна (эсвэл «Өөр хаалга сонгох» → Revit-ийн native pick).
2. Шинэ байрлал заах — гурван арга, бүгд ИЖИЛ simulation-г ажиллуулна:
   · **«Зураг дээр сонгох»** — Revit-ийн `PickPoint` (snap-тай); цэг хостын төв шугам дээр проекц хийгдэж, хаалга хананаасаа ГАРАХГҮЙ.
   · **← → товч** (Ctrl = 10, Shift = 100, үгүй бол 50 мм) эсвэл **−100 −50 −10 +10 +50 +100** товч.  Бичиж байхад (TextBox) сум ажиллахгүй — «аюулгүй» хэсэг л.
   · **Мм-ээр бичих**: `+300`, `−250`, `0.3 м`, `30 см` (`DoorMoveInput.ParseSignedOffsetMm`).
3. Revit-ийн ЗУРАГ ДЭЭР шууд: хаалганы шинэ байрлал (ghost, тунгалаг) + хуучин байрлалын саарал контур + сум, нөлөөлөх элементүүдийн тодруулга.
4. НЭГ ШИЙДВЭР (хана зөөхтэй ИЖИЛ 🟢 🟠 🔴 ⚪, §1) — «Ноцтой» бүлэг түрүүлнэ; тоотой карт дарвал тэр бүлгийг л Revit-д тодруулна; «Харуулах» товч.
5. **«Хаалгыг +300 мм зөөх»** = ЯГ НЭГ бодит зөөлт, нэг Undo «MGL — Хаалга зөөх».  **«Цуцлах»** (Esc) = хаалга ХЭЗЭЭ Ч хөдлөөгүй, ghost арилна.

### 14.2 Архитектур — ХОЁР ДАХЬ хөдөлгүүр БАЙХГҮЙ

Хана зөөх, хаалга зөөх НЭГ шийдвэрийн хөдөлгүүр, НЭГ snapshot/diff, НЭГ sandbox, НЭГ Apply, НЭГ stale/кэш/ажиглагчийн хойшлуулалт, НЭГ UI-ийн суурийг хуваалцана.
Ялгаа нь `PreChangeOperationKind` (Core) ба `IPreChangeOperation` (Revit) гэсэн ГАНЦ seam:

| Хуваалцсан (өөрчлөгдөөгүй) | Хаалга-тусгай (шинэ) |
|---|---|
| `PreChangeDecisionEngine` (🟢🟠🔴⚪), `TruthState`, `ItemCodes` | `PreChangeOperationKind.DoorMove`, `DoorMoveRequests` (хостын дагуух ТЭМДЭГТЭЙ зай → вектор) |
| `PreChangeDiff.Compute` (snapshot/diff, өрөө, хэмжээс, MEP, гарц, хуудас) | `DoorMoveDiff` (нүх, саад, From/To, орчны зай, flip, wall-end), `DoorImpactGroups` |
| `PreChangeSandbox` (`TransactionGroup`, ҮРГЭЛЖ `RollBack`, settled уншилт, restore probe) | `DoorHostMath`, `DoorSweep`, `DoorFastScan` (цэвэр, мм) |
| `PreChangeApply` (stale → move → settled тулгалт → Assimilate \| RollBack, нэг Undo) | `DoorSimulationController` (generation, debounce, latest-wins, Approve уралдаан) |
| `PreChangePlanCache`, `BeforeMemo`, `PreChangeFingerprint`/`PreChangeStale` | `PreChangeDoorRules`, `PreChangeDoorContext`, `DoorMoveOperation` |
| `ObservationDeferral`, `ImpactSimulationScope`, `ModelChangeCounter` | `GhostScene` (давхаргат зураглал), `DoorOverlay`, `DoorMoveView`, `DoorMoveWindow` |
| ЕДИНСТВЕННЫЙ DirectContext3D сервер (`PreChangeGhost`) — давхаргат болгон ерөнхийлсөн | `IDoorMoveSession` (контекст, PickPoint, ghost) |

`WallMoveOperation` нь анхны MVP-ийн код (үг үсэг, дараалал өөрчлөгдөөгүй, PreChangeJob-оос ХӨДЛҮҮЛСЭН).  Core нь Revit/WPF-гүй хэвээр (`CoreStaysRevitFree`).
R24/net48 нь `ChangeImpact/**`-гүй (хэвээр) — энэ нь R24-д ОРОХГҮЙ.

### 14.3 Загвар, геометр (мм, Revit-гүй, тестлэгдсэн)

* **Скаляр хөдөлгөөн**: хаалганы төв `s = (P − хостын эхлэл)·t`; шинэ байрлал `s₁ = s₀ + offset`; нүх `[s₁ − w/2, s₁ + w/2]`.  Дурын XYZ харьцуулалт БАЙХГҮЙ.
  Хост = шулуун, босоо, ердийн (Basic) хана.  Хаалга **хостоо хадгална**; нүх хостоос гарах эсвэл төв гарах бол «хост ханын гадна байна — хаалганы нүх ханын төгсгөлөөс N мм хэтэрнэ» (🔴, sandbox ХЭРЭГГҮЙ).
* **Нүхний өргөн** = `Parameter` (Rough Width → Width) → `BBox` (ойролцоо) → `Unknown`.  `Unknown` нь ХЭЗЭЭ Ч 0 биш: давхцлын шалгалт зөвхөн төвөөр, батлах боломжгүй (Review), «бүрэн бус» шалтгаан.
  Family-ийн эх цэг нь нүхний төв биш бол нүхний төвийг bbox-оос авна (шилжилтийн инвариант: зай хоёр тохиолдолд ижил).
* **Swept envelope** (`DoorSweep`): ЭХЛЭЛ, ТӨГСГӨЛ, ЗАМ (хоорондох) гурван хайрцаг хостын координатад (s, n, z).  **ЭНЭ НЬ ӨРГӨН ШАТ**: bbox-ын давхцал ХЭЗЭЭ Ч ганцаараа «батлагдсан clash» БИШ —
  зөвхөн нэр дэвшигч.  Батлагдсан огтлолцлыг sandbox дахь `GeometryVerifier` (бодит solid + boolean) шийднэ.
* **Хоёр өөр нөлөөлөл**: (A) ЗАМЫН нөлөө — зам дээрх нүхний дараалал солигдох; (B) ЭЦСИЙН БАЙРЛАЛЫН нөлөө — шинэ байрлалд юутай огтлолцох.  Зам дээрх, эцсийн байрлалд огтлолцохгүй элемент шийдвэрийг ӨӨРЧИЛӨХГҮЙ.
* **Нүхний давхцал** (хост дээрх бусад хаалга/цонх/нүх): хоёулаа өргөн мэдэгдсэн, Z давхцсан, s-ийн давхцал → 🔴 «D-120 нь W-14-ийн нүхтэй 120 мм давхцана».
  Хаалганы ДЭЭГҮҮР transom цонх (Z давхцахгүй) clash БИШ; Z уншигдаагүй бол батлахгүй (Review).  Өмнө нь ч давхцаж байсан бол шинэ нөлөө биш (мэдэгдэх л).

### 14.4 Хоёр түвшинтэй real-time (хуурамч «real-time» ГЭХГҮЙ)

| Түвшин | Юу | Хэзээ | Шийдвэрт |
|---|---|---|---|
| **Fast scan** (`DoorFastScan`) | цэвэр хайрцаг/интервал; нүхний давхцал (тоон), wall-end, саадын нэр дэвшигч | товч/сум/бичилт бүрт ШУУД (UI thread) | **ХЭЗЭЭ Ч 🟢 БИШ** — «урьдчилсан»; зөвхөн хоёр нүхний интервалын давхцал л түр 🔴 |
| **Exact** (`PreChangeJob` → sandbox) | бодит `MoveElement` + settled уншилт + `GeometryVerifier`, From/To, хэмжээс, орчны зай, MEP/гарц/хуудас | **220 мс debounce**-ийн дараа, ХАМГИЙН СҮҮЛИЙН зорилтод ЗӨВХӨН | ЭЦСИЙН дүгнэлт (🟢🟠🔴⚪) |

* **Generation**: зорилт өөрчлөгдөх бүрт өснө.  «зорилт 1 эхэлж, зорилт 2 эхэлж, зорилт 1 хожуу дуусвал → UI ЗААВАЛ зорилт 2» — хожуу ирсэн хуучин үр дүн ХАЯГДАНА (`LateIgnoredCount`), зураглалыг ДАРАХГҮЙ.
* **Latest-wins**: +10 +10 +10 +10 → дараалалд 4 sandbox БИШ; debounce дотор нэг л sandbox.  Явж буй sandbox шинэ зорилтоор ЦУЦЛАГДАНА (`CancelExact` → `SmartExecutor` Step-ийн хооронд).
* Шинэ зорилтыг шалгаж байх хооронд өмнөх үр дүн **бүдэг** (45%) харагдаж, «Өмнөх байрлал (+300 мм)-ын дүн — шинэ шалгалт үргэлжилж байна…» гэж ИЛ хэлнэ; Approve хаалттай.
* Контекст (хост, нүх, саад, өрөө) **зайнаас хамаарахгүй** → `ModelChangeCounter` тэмдгээр кэшлэгдэнэ (`PreChangeDoorContext.Cache`); 300 → 320 мм-д дахин уншихгүй.  Тэмдэг өөрчлөгдвөл (загвар засагдсан) цонх автоматаар
  дахин уншина (15 с-д ≤ 3 удаа — буцаалт баталгаагүй гэх мэтээр байнга өөрчлөгдвөл гогцоонд орохгүй, «Дахин шалгах» санал болгоно).

### 14.5 Зураг дээрх харагдац (DirectContext3D, ЗӨВХӨН дэлгэц)

* **Нэг л сервер** (`PreChangeGhost`, `ServerId` хэвээр) — давхаргат зураглал (`GhostScene`/`GhostLayer`): ghost (тунгалаг хүрээ + контур + сум), хуучин контур (саарал), severity тус бүрийн тодруулга (тунгалаг хайрцаг + ирмэг + босоо «зүү»).
  Өнгө: **улаан** ноцтой · **улбар шар** хянах · **шар** өөрчлөгдөнө · **цэнхэр** мэдээлэл.  Өнгө ганцаараа БИШ — цонхны жагсаалт + үгтэй хамт.  Урьдчилсан тодруулга эцсийнхээс бүдэг (0.88 vs 0.70 transparency).
* **Хязгаар**: ≤ 40 хайрцаг, ≤ 12 зүү (Critical түрүүлнэ).  Линк загварын элемент hostын transform-оор.
* **Шуурхай шинэчлэл**: зураглалыг UI thread-д Revit API-гүйгээр угсарч, сервер бүртгэгдсэн бол `TrySwapScene`-ээр ТЭР ДОР орлуулна; нэг ExternalEvent л (нэгтгэсэн, хамгийн сүүлийнх — «pump») серверийг бүртгэж `UpdateAllOpenViews` хийнэ.  Хулганы глобал hook, Win32, reflection БАЙХГҮЙ (`DoorSimulation_UsesNoMouseHooksWin32OrReflection…` хамгаалалтын тест).
* **ЗАГВАРТ ХҮРЭХГҮЙ**: DirectShape, DetailLine, ModelLine, транзакц, Undo, selection, түр элемент ХЭЗЭЭ Ч үүсгэхгүй (`Ghost_NeverWritesToTheModel…`).
* **Цэвэрлэгдэх тохиолдол** (идемпотент): зорилт солигдох · хаалга солигдох · Цуцлах/Discard · Apply амжилттай БА амжилтгүй · баримт өөрчлөгдөх (`DocumentChanged`, sandbox/Apply-ийн commit-ийг тооцохгүй) · баримт хаагдах · файл солигдох ·
  цонх хаагдах · Revit унтрах (`SmartHost.Shutdown`).
* ⚠️ Төлөвийн хязгаар: DirectContext3D нь 3D дээр найдвартай; план/зүсэлт/фасад дээр зурагдах эсэх Revit-ийн хувилбараас хамаарна (§7).  Зурагдахгүй бол ЗӨВХӨН харагдахгүй — шийдвэрт нөлөөлөхгүй.

### 14.6 Юуг шалгадаг (бүгд Revit-ээс хэмжсэн; нормын шалгалт БИШ)

| Шалгалт | Хаана | Шийдвэр |
|---|---|---|
| Хост дээрх БУСАД нүх (өргөн мэдэгдсэн) давхцах | fast + exact | 🔴 (батлагдсан) · өргөн/Z мэдэгдэхгүй бол 🟠 Review |
| Бүтэц / багана / хана — **геометрээр** батлагдсан огтлолцол | exact (`GeometryVerifier`) | 🔴 |

| Орчны зай ӨМНӨ / ДАРАА / ЗӨРҮҮ (3D ray) | exact (deep) | мэдээлэл · «Геометрээр хэмжсэн. Нормын шалгалт биш.» · уншигдахгүй бол «тооцоолоогүй» (0 БИШ) |
| Хаалганы flip (facing/hand) хадгалагдсан эсэх | exact | өөрчлөгдсөн бол 🟠 · уншигдахгүй бол «мэдэгдэхгүй» |

| **Монгол норм (БНбД)** | — | «автомат шалгалт хийгдээгүй» — ТУСДАА мөр, шийдвэрт нөлөөлөхгүй |

### 14.7 Approve / Discard / Apply — уралдааны хамгаалалт

* **Approve** зөвхөн **ЯГ ОДООГИЙН generation-ийн ЭЦСИЙН (Full, sandbox) дүн** байхад идэвхжинэ (`ExactIsCurrentAndFinal`).  Debounce / sandbox ажиллаж байх / түр дүн / өөр зорилтын дүн / хуучирсан загвар / 🔴 / ⚪ — бүгд хаалттай.
  `TryBeginApply` нь шалгалтыг ДАХИН хийж (generation, шалгасан зай = одоогийн зай, Gate) тайланг буцаана; давхар дарахад хоёр дахь нь `null` (`Applying`).
* **Apply** = хана зөөхтэй ИЖИЛ `PreChangeApply`: хурууны хээ (хуучирсан/шалгаж чадаагүй → ЗӨӨХГҮЙ, fail-closed) → `TransactionGroup «MGL — Хаалга зөөх»`{ move → regenerate → commit → SETTLED уншилт →
  preview.After-тай тулгалт → таарвал `Assimilate` (**НЭГ Undo**) \| үгүй бол `RollBack` }.  MGL-ийн ажиглагчид баталгаажсаны ДАРАА нэг удаа.  «Preview ба бодит таарсан» гэж ЗӨВХӨН settled-тэй тулгасан үед.
* Apply хийгдэж байхад зорилт өөрчлөх, Discard, хожуу ирсэн үр дүн — бүгд ҮЛ ХЭРЭГСЭНЭ.  Амжилтгүй/буцсан/хуучирсан: ghost ЦЭВЭРЛЭГДЭНЭ, зорилт хэвээр, «Дахин шалгах» санал болгоно (хуучирсан бол автоматаар шалгана — хоёр дахь товшилт заавал).
* **Discard** = шинжилгээг цуцлах + ghost, тодруулга, зорилт, түр төлөвийг арилгах.  Бодит хаалга ХЭЗЭЭ Ч хөдлөөгүй тул загвар буцаах хэрэггүй (sandbox аль хэдийн буцсан).

### 14.8 Дэмжигдэхгүй хаалга — Монгол шалтгаантай

Линк загварын хаалга · Curtain Wall самбар/хаалга · Stacked/нумант/налуу хост · хостгүй хаалга / хана биш хост · группийн гишүүн · nested (өөр family-ийн дотор) · design option · байрлалын цэггүй ·
Pin (🔴 Revit татгалзана) · зөвхөн унших файл (🔴) · өөр хэрэглэгчид эзэмшигдсэн хаалга/хост (🔴) · хэн ч эзэмшээгүй (checkout сэрэмжлүүлэг — эхлэхээс ӨМНӨ асууна) · Family файл.
Түгжигдсэн хэмжээс/хязгаарлалт Revit-д зөөлтийг ХИЙЛГЭХГҮЙ бол sandbox `Blocked` → 🔴 + Revit-ийн failure мессеж.

### 14.9 Revit дээр гараар шалгах — DOOR RELEASE GATE (хийгдээгүй)

Хана зөөхийн §10 A–E хэвээр, ДОР НЭМЭЛТ:
1. **Сонголт**: хаалга сонгоод товч → цонх автоматаар авна · хана сонгоод → хана зөөх · хоосон → асуулт · линк/групп/nested/curtain/pin хаалга → зөв Монгол шалтгаан.
2. **Ghost**: нэг товчны дарталт бүрт ghost шинэ байрлалд, хуучин контур саарал, сум; план, зүсэлт, 3D дээр (хаана зурагдаж/зурагдахгүйг тэмдэглэ).  Хаалга/хана хөдлөхгүй; Undo жагсаалт өөрчлөгдөөгүй.
3. **Тодруулга**: тавилга/багана/бусад нүх/өрөө рүү зөөхөд зөв элемент зөв өнгөөр; карт дарахад тэр бүлэг л; «Харуулах» Revit-д сонгож zoom хийнэ; линк элемент host-ын id-тай мөргөлдөхгүй.
4. **Latest-wins**: +10-г 10 удаа хурдан дарахад Revit гацахгүй, зөвхөн сүүлийн зорилт дүн болно; шинжилгээ ажиллаж байхад шинэ зорилт өгөхөд хуучин дүн UI-г дарахгүй.
5. **Settled**: Revit хаалгыг хүссэн зайгаас ӨӨР зайд зөөвөл (түгжигдсэн хэмжээс г.м.) preview ба Apply хоёулаа «Revit өөр зайгаар зөөсөн» гэж 🟠 харуулна.
6. **Apply**: «Хаалгыг +300 мм зөөх» → ЯГ нэг зөөлт, **Ctrl+Z нэг удаа** буцаана (Undo-н нэр «MGL — Хаалга зөөх»); preview-ийн дараа гараар өөрчилбөл зөөгдөхгүй.  Цуцлах → хаалга хөдлөөгүй.
7. **From/To**: хаалгыг өөр өрөөний хажууд зөөхөд өрөөний нэр зөв; Apply-ийн дараа хаалганы хүснэгт зөв.
8. **Workshare**: өөр хэрэглэгчийн хаалга → 🔴; эзэмшээгүй → асуулт.
9. **Хурд (F)**: том загвар дээр fast scan ≪ 100 мс, exact (хоёр sandbox дамжлага) хэд вэ — ХЭМЖИЖ тэмдэглэ (§14.11-ийн «хэмжигдээгүй» хэсгийг бөглө).
10. **Цонх/файл хаагдах**: цонх хаахад, файл солиход, Revit унтрахад ghost үлдэхгүй.

## 15. ЯМАР Ч ЭЛЕМЕНТИЙГ ХУЛГАНААР ЧИРЖ ЗӨӨХ — симуляц (add-in 1.18.0)

> # ⛔ LIVE REVIT QA REQUIRED (§15.9)
> Core (геометр, BVH, мөргөлдөөн, камер, чирэлт, тайлан, контроллер) Линукс дээр тестлэгдсэн.  **WPF цонх, хулганаар чирэх, Revit-ийн геометр уншилт, sandbox, Apply, DirectContext3D сүүдэр
> Revit дээр ХАРААХАН ажиллуулаагүй.**  «Ажиллаж байна» гэж ХЭЛЭХГҮЙ.

**Эзний хүсэлт (2026-10-05):** цэс, диалог, зайн тоо БАЙХГҮЙ.  Revit төслийн дотор ЯМАР Ч элементийг (хаалга/хана гэж ялгахгүй) сонгоод, ХУЛГАНААР барьж чирж тавихад тэр элемент юутай мөргөлдөж, ямар асуудал
үүсэхийг шууд шинжилж «хэрэв та «X»-г эндээс тийш зөөвөл … дахин хийх эсвэл ийм асуудал гарах магадлалтай» гэж хэлээд, мөргөлдөж буй зүйлийг жижиг 3D цонхонд (Revit-тэй төстэй, бодит геометр) ИЛ ТОД харуулах.

### 15.1 Юу хийдэг вэ — 30–60 секундын ажлын урсгал

1. Revit-д **ямар ч элемент** (хана, хаалга, цонх, багана, шал, суваг, тавилга…) сонгоод **«Өөрчлөхөөс өмнө»** дар.  Юу ч сонгоогүй бол Revit-ийн статус мөрөнд заавартай зураг дээр дарж сонгуулна (`PickObject`, диалог БИШ).
2. **Simulation цонх** нээгдэнэ: элемент ЦЭНХЭР, орчин (хана, шал, багана, суваг…) ангиллаар өнгөлөгдсөн саарал, анхны байрлал тунгалаг сүүдэр.
3. Элементийг **ХУЛГАНААР БАРЬЖ ЧИРНЭ**: ямар ч тоо, товч шаардлагагүй.  Хавтгайд (X, Y) / нэг тэнхлэгээр / дээш-доош; алхам Чөлөөтэй/1/5/10/50/100 мм (өгөгдмөл 10); сумтай товчоор нарийн нудна (Shift ×10, PageUp/Down = Z).
4. Чирж байх ЯВЦАД (~мс) мөргөлдөж буй гадаргуу УЛААНААР 3D дээр тодорч, цэг дээр улаан шошго, баруун самбарт «Хэрэв та «Багана · #1»-г эндээс тийш зөөвөл (X +2300 мм): …» гэсэн тайлбар гарна.
5. Тавьсны дараа (260 мс тогтвортой байвал) **Revit өөрөө** ТҮР транзакцэд зөөж, settled төлвийг уншаад БҮТНЭЭР буцаана → эцсийн дүгнэлт 🟢 🟠 🔴 ⚪; Revit-ийн зураг дээр ч сүүдэр харагдана.
6. **«Зөвшөөрөх»** = ЯГ НЭГ бодит зөөлт, нэг Undo «MGL — Элемент зөөх».  **«Болих»** (Esc) = загвар ХЭЗЭЭ Ч хөдлөөгүй.  «Эхнээс нь» = элементийг анхны байрлал руу буцаана.

Хулганы удирдлага: барих = элемент дээр зүүн товч · хоосон зайд зүүн/баруун товч = эргүүлэх · Shift + баруун эсвэл дунд товч = шилжүүлэх · дугуй = курсор руу ойртуулах · Home = бүтнээр · T = дээрээс · I = 3D · Enter = зөвшөөрөх · Esc = болих.

### 15.2 ЯАГААД Revit-ийн зураг дээр БИШ, өөрийн WPF 3D цонхонд (инженерийн үнэн)

Revit API нь өөрийн зураг дээр «хулганаар чирж байхад» мөр бүрд хүсэлт өгөх арга өгдөггүй (хулганы hook, Win32, reflection ХОРИОТОЙ), мөн нэг `TransactionGroup`-ыг чирэлтийн турш нээлттэй барьж болдоггүй.
Тиймээс чирэлтийг ӨӨРИЙН цонх ХУЛГАНЫГ эзэмшиж гүйцэтгэнэ, бүх барилт/шинжилгээ цэвэр Core-д (Revit-гүй, тестлэгдсэн) байна:
**Revit-ийн бодит геометрийг НЭГ удаа уншиж (мм, орчин төвлөрсөн) → цонх ӨӨРИЙН ХҮЧЭЭР чирж, мөргөлдөөнийг ӨӨРӨӨ шууд тооцно → тавьсны дараа Revit sandbox-оор баталгаажуулна.**
Үр дагавар (нуухгүй): цонх Revit-ийн UI thread-ийг хуваалцдаг тул Revit-ийн шалгалтын (~0.3–3 с, §15.11) үеэр цонх хөлдөнө; «чирэх үеийн улаан» нь ТҮР дүн (§15.6), эцсийнх нь Revit-ийнх.

### 15.4 Зураглал (3D)

Бүх геометр гурвалжин бүрт өөрийн оройтой (flat shading — Revit-ийн хурц ирмэг бүдгэрэхгүй), frozen, арын thread-д бүтээгдэнэ.  Орчин ангиллаар (хана, шал, дээвэр, хаалга, цонх, багана, суваг, хоолой…) бүлэглэгдэж ≤30k гурвалжингийн хэсэг, нийт ≤260k зурна.
**Мөргөлдөөн ИЛ ТОД**: мөргөлдөж буй гурвалжингууд УЛААН давхаргаар (5 мм нормалийн дагуу түлхэгдсэн — z-fighting үгүй) дахин зурагдаж, давхцлын бүс тунгалаг улаан хайрцагтай, цэг бүрт шошго.  «Орчин тунгалаг» сонголт.
Эцсийн дүнгээс хойш Revit-ийн БОДИТ settled геометр (чирсэн хуулбарыг орлоно) ба Revit өөрчилсөн хөрш (улбар шар) харагдана.

### 15.5 Шинжилгээний хоёр түвшин (хуурамч «real-time» ГЭХГҮЙ)

| Түвшин | Хэзээ | Юу | Статус |
|---|---|---|---|
| **Түр** (UI thread, цэвэр Core) | чирж байх, нудах бүрд | AABB → BVH-ийн гурвалжин огтлолцол + эзлэхүүн давхцал; baseline-тай харьцуулалт | «Түр дүн» — Revit-ээр БАТЛАГДААГҮЙ |
| **Эцсийн** (Revit sandbox) | тавьсны дараа 260 мс тогтвортой | зөөх → commit → settled унших → RollBack; boolean clash, өрөө, устсан, dependents, failure | «Батлагдсан» |

Хуучирсан дүн ХЭЗЭЭ Ч шинийг дарахгүй: offset өөрчлөгдөх бүрд `Generation` өсөж, Revit-ийн дүн зөвхөн generation ба offset ХОЁУЛАА таарч, хэрэглэгч чирж байхгүй үед л хүлээн авагдана.

### 15.6 Юуг шалгадаг / ШАЛГАХГҮЙ (нууцгүй)

Шалгадаг: **ямар ч категорийн** хоорондох мөргөлдөөн (host + линк), устсан элемент, өрөө (талбай, хаагдсан эсэх), хамаарагч (hosted/join), Revit-ийн failure/warning.
Тайланд ҮРГЭЛЖ «Шалгаагүй: харагдац, хуудас, хүснэгт, гарц, MEP-ийн холболт, Монгол норм» мөр гарна (coverage).  Орчин ачаалсан хүрээнээс гарсан, нийт гурвалжин хязгаарлагдсан бол «ачаалсан орчноос гарлаа» гэж ИЛ хэлнэ.
Мөргөлдөөн нь хатуу хүлцэлтэй (6 мм-ээс бага нэвтрэлт, шүргэлт, нэг хавтгай — мөргөлдөөн БИШ); анхны байрлалд аль хэдийн байсан давхцал «Урьд нь байсан», ≥15 мм дордвол «Дордсон».
Ноцтой байдал: Blocking (🔴 — шинэ бүтэц/MEP мөргөлдөөн, устсан, Revit-ийн failure) · Review (🟠 — тавилга, мэдэгдэхгүй) · Info (хөрш join, dependents).  Дүгнэлтийн дараалал: **ЗӨӨХГҮЙ > ДҮГНЭХ БОЛОМЖГҮЙ > ХЯНААД ЗӨӨ > ЗӨӨЖ БОЛНО**.

### 15.7 Approve / Discard / Apply — уралдааны хамгаалалт

`Approve` нь ЗӨВХӨН: чирэлт дууссан · Revit-ийн эцсийн дүн ЭНЭ offset-д таарсан · дүгнэлт зөөх боломжтой · загвар шалгалтаас хойш өөрчлөгдөөгүй (ChangeStamp) үед идэвхтэй.  🟠 бол MessageBox-оор батлуулна.
Apply = `TransactionGroup «MGL — Элемент зөөх»` { зөөх → regenerate → commit → settled тулгалт (байрлал, устсан) → Assimilate (нэг Undo) | RollBack }, MGL-ийн ажиглагчид `ObservationDeferral`-ээр хойшлогдоно.
Тулгалт зөрвөл буцаана, буцаалт баталгаажихгүй бол «Ctrl+Z-ээр шалга» гэж ИЛ хэлнэ.  Discard (Esc, Болих) загварт хүрдэггүй.

### 15.8 Зөөж БОЛОХГҮЙ элемент — Монгол шалтгаантай

Линк загварын, группийн гишүүн, Pin хийгдсэн, design option, stacked wall-ийн гишүүн, bbox-гүй, read-only, өөр хэрэглэгчид эзэмшигдсэн (workshare) элемент.  Эзэмшигдээгүй (workshare) бол шинжилгээ түр эзэмшил үүсгэж болзошгүй тул ЭХЛЭЭД асууна.
Хана дагасан хаалга/цонх зөвхөн хананы шугамаар хөдөлнө (шугамт хязгаар).  Нэг дор ≤40 элемент (hosted ≤120).

### 15.9 Revit дээр гараар шалгах — SIMULATION RELEASE GATE (хийгдээгүй)

Хана зөөхийн §10, хаалгын §14.9 хэвээр, ДОР НЭМЭЛТ:
1. **Сонголт**: хана / хаалга / багана / шал / суваг / тавилга сонгоод товч → цонх нээгдэнэ · юу ч сонгоогүй → статус мөрөнд заавар, зураг дээр дарж сонгоно, Esc = цуцлах · линк/групп/Pin → зөв Монгол шалтгаан · цонх нээлттэй үед өөр элемент сонгоод дахин дарахад `SwitchTo`.
2. **3D харагдац**: орчны геометр Revit-тэй төстэй эсэх (хана, шал, багана, цонх); эргүүлэх/шилжүүлэх/ойртуулах мэдрэмж; том загварт (≥200k гурвалжин) цонх хэр гацах — ХЭМЖИЖ тэмдэглэ.
3. **Чирэх**: барих/чирэх (хавтгай, тэнхлэг, босоо), snap, сумтай нудалт; хананд hosted хаалга хананаасаа гарахгүй; Esc чирэлтийг цуцлах.
4. **Улаан тодруулга**: тавилгыг ханын дотор, багана шалан дотор, суваг хананд оруулахад мөргөлдөх гадаргуу ИЛ ТОД, зөв нэртэй тайлбар; flush (шүргэсэн) давхцал; анхны байрлалд аль хэдийн мөргөлдсөн зүйл «Урьд нь байсан».
5. **Revit-ийн дүн**: тавьсны дараа ~0.3–3 с-д «Батлагдсан» болох, ӨӨР зайд зөөсөн (түгжигдсэн хэмжээс) бол preview-тай зөрөхийг ИЛ хэлэх; Revit-ийн failure/warning; dependents.  Цонх энэ үед хөлдөнө — хэр удаан бэ, ХЭМЖИЖ тэмдэглэ.
6. **Apply**: «Зөвшөөрөх» → ЯГ нэг зөөлт, **Ctrl+Z нэг удаа** буцаана (Undo-н нэр «MGL — Элемент зөөх»); шалгасны дараа Revit-д гараар өөрчилбөл «Шинэчлэх» мэдэгдэл, Зөвшөөрөх хаалттай.
7. **Ghost**: эцсийн дүнгийн дараа Revit-ийн зураг дээр сүүдэр (план, 3D, зүсэлт); цонх хаахад үлдэхгүй.
8. **Workshare**: өөр хэрэглэгчийн элемент → зөөхгүй; эзэмшээгүй → асуулт.
9. **Хуучин цонх**: «…» цэснээс хана/хаалганы БҮТЭН шалгалт нээгдэнэ.
10. **Цонх хаах/файл солих/Revit унтраах** үед сүүдэр үлдэхгүй, sandbox-ын буцаалт баталгаатай.

## 17. REVIT-Д ШУУД ЗӨӨХӨД ШАЛГАХ + ахлагч/төслийн баг + өөрийн шийдвэрээр зөвшөөрөх (2026-10-06, 2-р хэсэг)

**Эзний шийдвэр (AskUserQuestion):** «3D модель дотор шууд» = архитектор Revit-ийн өөрийн Move / чирэлт / сумтай товчоор зөөмөгц хэрэгсэл ӨӨРӨӨ шалгана
(тусдаа simulation цонх нь «урьдчилж турших» горим болж үлдэнэ).  Автоматаар мэдэгдэх «бусад хүмүүс» = **мэргэжлийн ахлагч + төслийн баг**.

### 17.1 Урсгал
1. `Revit/PostMoveWatch.cs` (App.cs-д `PostMoveWatch.Init`): `SelectionChanged` → сонгосон (≤40) элементийн байрлалыг санана; `DocumentChanged` (зөвхөн
   `TransactionCommitted`, «MGL»-ээр эхэлсэн гүйлгээ, sandbox/Apply (`ImpactSimulationScope`) алгасна) → `SimNativeMove.TryTranslation` цэвэр зөөлт эсэхийг тулгана.
   Ханын холбоотой төгсгөлийг Revit тайрдаг тул шулууны **хөндлөн** хэсэг ижил бол зөөлт, урт дагуух тайралтыг тэвчинэ (Revit 2027-д хэмжсэн: 800 мм зөөхөд нэг үзүүр 105 мм тайрагдсан).
   Эргүүлэлт, үзүүр чирэх (сунгах) — зөөлт БИШ, шалгахгүй.
2. 0.7 с тайван болсны дараа (дараалсан нудалт нэг шинжилгээ) `Revit/PostMoveAnalyzer.cs` — **гүйлгээгүй**: одоогийн байрлалд `GeometryVerifier` (simulation-тай ижил),
   өмнөх байрлалд зөөгдсөн элементийн солидыг −шилжилтээр хөрвүүлж огтлолцлыг дахин бодно (аль хэдийн байсан мөргөлдөөн «шинэ» биш); гүйлгээний modified-аас дагаж өөрчлөгдсөн бие.
   Тайлан = ижил `SimNarrative`.
3. Хэн нэгний ажил хөндөгдсөн бол л (`SimNativeMove.WorthShowing`) баруун доод буланд жижиг цонх (`Ui/PostMoveWindow.cs`, фокус авахгүй) + Revit-ийн зураг дээр саарал (өмнөх) /
   өнгөт (шинэ) хүрээ, сум, улаан мөргөлдөөн (`SimGhostScene.ForNativeMove`).  Товч: **Буцаах** (яг −шилжилтээр, нэг Undo «MGL — Зөөлтийг буцаах», `PostMoveRevert.cs`),
   **Хаах**, **Зөвшөөрөх · N хүнд мэдэгдэх** (`mode:'native'`).  «Энэ Revit-ийн сессэд шууд зөөлтийг шалгахгүй» чагт.
4. **🔴 үед ч архитектор зөвшөөрнө** — Revit өөрөө зөвшөөрсөн бол (`SimReport.CanForce`) шалтгаан заавал (`Ui/SimReasonDialog.cs`, ≥5 тэмдэгт), мэдэгдэлд `forced_reason`.
   Revit татгалзсан / шалгалт дуусаагүй үед хэзээ ч үгүй.  Simulation цонх ба шууд зөөлтийн цонх хоёуланд.
5. **Хүлээн авагч:** Revit зохиогч (үүсгэсэн / сүүлд өөрчилсөн / эзэмшиж буй) + **мэргэжлийн ахлагч** (элементийн төрлөөр баг: BA/BB/HAS/TSBU/TSAH; `teams.lead_user_id`,
   эс бөгөөс тэр багийн үндсэн senior-ууд) + **төслийн баг** (файлтай холбогдсон ERP төслийн таск дээр ажилласан хүмүүс, ≤25) — зөвхөн мөргөлдөөн байгаа үед; ERP сервер
   өөрөө тооцно (клиентэд итгэхгүй), цонх урьдчилан харуулж чагтаар хасуулна.  ⚠️ Локал D1-д 2026-10-06-нд нэг ч багт ахлагч тохируулаагүй; TSAH-д senior алга.
6. **Дагаж өөрчлөгдөх биеийн үнэн:** Revit «modified» гэдэг нь заавал шилжсэн гэсэн үг биш.  Simulation-д буцаалтын ДАРАА анхны байрлалтай тулгаж `LocationChanged`
   (шилжсэн → 🟠 мэдэгдэнэ; зөвхөн холболт/нэгдэл → ℹ «байрлал хэвээр», мэдэгдэхгүй).  Шууд зөөлтөд өмнөх байрлал мэдэгдэхгүй тул «холболт, нэгдэл эсвэл байрлал — шалгана уу» гэж ил хэлнэ.

### 17.3 Үлдсэн
* Бодит хулганаар (Revit-ийн Move товч, чирэлт) гараар шалгаагүй — гүйлгээг скриптээр хийсэн (Revit-д ижил `DocumentChanged`).  Сонголтгүйгээр Move хийх (Revit-ийн Move-оос
  «сонгох» алхам) нь `SelectionChanged`-ээр мөн дамжина гэж үзсэн — гар QA.
