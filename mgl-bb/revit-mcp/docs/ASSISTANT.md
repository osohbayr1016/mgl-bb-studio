## 0. Хэрэглэгч хэн бэ (тайлбар хэрхэн бичих вэ)

Энэ төслийн хөгжүүлэгч нь **програм хангамжийн хөгжүүлэгч, архитектор БИШ**.
MGL E&C-д шинээр орсон. Revit, BIM, барилгын салбарын мэдлэггүй.

Тиймээс:
- **Компани хэрхэн ажилладаг тухай асуу**, кодын дотоод бүтцийн тухай БИШ.
  Сайн: «Инженерүүд ажлаа жагсаалт болгож тэмдэглэдэг үү?»
  Муу: «UNIQUE индекс глобал байх уу, төслөөр байх уу?»
- Техник сонголтыг **өөрөө шийдэж, юу шийдснээ хэл**.
- Шаардлагатай зүйлийг л, хэдэн өгүүлбэрээр тайлбарла. Revit-ийн хичээл
  заах хэрэггүй.
- **Хийж боломгүй хүлээлтийг ЭРТ, тодорхой хэл** — 3 сарын дараа биш.
- Монголоор ярь.

## 1. Бизнесийн даалгавар (CEO-гоос)

1. Revit AI-г компанийн вэбсайт (mgl-e-c) дээр оруулах.
2. Ажилтнууд **монголоор, Revit дотор** AI ашиглаж хурдан ажиллах.
3. Дуусахад **AI-д хэлэхэд бүртгэгдэнэ**.
4. Удирдлага «энэ сарын бүтээмж» гэж асуухад **хэн ямар төсөлд юу хийснийг**
   хардаг — хүн тутам, төсөл тутам, сар тутам, тайлан руу урсана.
5. Бүгд **ERP-тэй интеграцтай** (= mgl-e-c өөрөө).

### Сайн мэдээ: 3, 4, 5 нь АЛЬ ХЭДИЙН БИЙ

`progress_entries`, `user_points`, leaderboard, `performanceReports.ts`, team
reports — бүгд ажиллаж байна. Дутуу нь зөвхөн **Revit-ээс тэр машин руу
хүрэх гүүр** ба туслахын UI.

CEO-д: *«Систем маань 60%-ийг нь аль хэдийн хийдэг. Бид дутуу гүүрийг барина.»*

### ⚠️ ХОЁР ХҮЛЭЭЛТ БИЕЛЭХГҮЙ — хэлсэн, дахин ярихгүй

**(1) «AI ажилтны хийсэн ажил хэдэн хувь болохыг илрүүлнэ».**
Компьютер `.rvt` уншаад «энэ зураг 60% дууссан» гэж хэлж чадахгүй. Бараг
дууссан зураг, хагас зураг хоёр ижил элементтэй байж болно; бүтэн өдөр
зохицуулалт хийхэд элемент бараг нэмэгддэггүй; схемд «зорилтот тоо» байхгүй.
13 агентаар бүх кодыг шалгасан: **моделийн өгөгдлөөс явц тооцдог газар нэг ч
байхгүй**. Хувь нь ХҮНЭЭС гарна — checklist эсвэл гараар бичсэн тоо.

**(2) «AI өөрөө ажлын зураг зурна».**
Схемийн геометр үүсгэх нь БОЛОМЖТОЙ (`scripts/revit/` дэх теннисний ордон нь
батлагдсан жишээ). Гэхдээ **бодит үр дүн**: 9 алхмын **5 дээр зогссон**,
~400 схематик элемент, хананы багана руу залгах / 105 ферм / дээврийн дам
нуруу / 70 суурь **нэг нь ч гараагүй**, гараар засварласан, 77 өрөө → 73.
Зөвшөөрлийн түвшний ажлын зураг гэдэг нь БНбД-ийн заалт бүрээр шалгагдсан,
ТЗБ-тэй зохицуулсан, бүрэн хэмжээслэсэн, гарын үсэгтэй байх ёстой.

**CEO-д хэлэх мөр:** «AI зураг зурахгүй — зургийн бэлтгэлийн 60%-ийг хийж
өгнө.»

## 2. Одоогийн систем

### Гурван зам (аль нь ч ажиллаж болно)

```
Revit доторх «MGL туслах» самбар (WPF, AssistantPane)
   │
   ├─ 1. IntentParser        офлайн, 0 мс, түлхүүр үг
   │                          «илгээ» «буцаа» «харуул» «шинэчил» «суурь» «тусламж»
   │
   ├─ 2. ЛОКАЛ АГЕНТ         localhost:5099 → claude-agent-sdk
   │                          → MCP stdio → revit_mcp.server
   │                          → localhost:5005 → add-in → Revit API
   │     ХЭРЭГЛЭГЧИЙН Claude ЗАХИАЛГААР.  API түлхүүр хэрэггүй.
   │
   └─ 3. СЕРВЕР              POST /api/revit/agent/turn (Cloudflare Worker)
         Anthropic түлхүүр Worker дээр.  ⚠️ ХАРААХАН DEPLOY ХИЙГЭЭГҮЙ → 404.
```

**Одоогийн бодит байдал:** 1 ба 2 ажиллаж байна. 3 нь код бэлэн ч
production-д байршуулаагүй.

### Явц илгээх урсгал (тусдаа, бүрэн ажиллаж байна)

```
Нэг удаа: «Зураг холбох» → Revit хуудас ↔ вэбийн ажил (2 минут)
          → ажлын дэд жагсаалт АВТОМАТААР үүснэ (хуудас тутам нэг мөр)
Өдөр бүр: «хийснээ илгээ»
          → diff_since_baseline (юу өөрчлөгдсөн)
          → POST /api/revit/draft   (сервер хувь тооцоод монгол тэмдэглэл бичнэ)
          → ХҮН уншиж, засаж, ☑ баталгаажуулна
          → POST /api/revit/submissions  (ЦОРЫН ГАНЦ бичих гарц)
          → progress_entries → оноо → тайлан
```

## 6. ШИНЭ ЧИГЛЭЛ — локал, өөрөө суралцдаг туслах

### Яагаад

API/LLM-д тулгуурлах нь: суудал тутам төлбөр, интернэт шаардана, Anthropic-ийн
нөхцөлтэй зөрчилддөг (нэг захиалгыг олон хүнд үйлчлүүлж болохгүй), бусад
компанид **зарахад тохиромжгүй**.

Гэтэл «ямар текст → ямар үйлдэл» гэдэг нь **хаалттай, жижиг ангиллын бодлого**
— сонгодог ML үүнийг маш сайн шийддэг. Тиймээс:

```
Хэрэглэгч бичнэ
   ├─ 1. ТОДОРХОЙ ТҮЛХҮҮР ҮГ      0 мс, офлайн   (аль хэдийн бий)
   ├─ 2. СУРГАСАН АНГИЛАГЧ        ~1 мс, офлайн, ҮНЭГҮЙ   ← БАРИХ ЗҮЙЛ
   └─ 3. LLM                       сонголт, унтраалттай ч болно
```

### Техник

- **TF-IDF (тэмдэгтийн 3–5 n-gram) → Logistic Regression.**
  Монгол хэл залгамал («илгээ/илгээх/илгээнэ/илгээчих») тул тэмдэгтийн
  n-gram нь морфологийн задлагчгүйгээр бүх хэлбэрийг барина.
- **Сургалт:** Python + scikit-learn, манай компьютер дээр, нэг удаа.
- **Таамаглал:** ЦЭВЭР C#, add-in дотор, ~60 мөр, хамааралгүй.
  Жинг JSON болгож экспортлоно (~200 KB).
- Ажилтны компьютерт Python, процесс, интернэт **юу ч хэрэггүй**.

### ⭐ ГОЛ ШИЙДВЭР — КИРИЛЛ↔ЛАТИН ЭВХЭЛТ

Урьд нь загвар «илгээе» ба «ilgeeye»-г ОГТ ӨӨР мөр гэж үздэг байсан.
Тэмдэгтийн n-gram нь хоёр бичлэгийн хооронд нэг ч онцлог хуваалцдаггүй.

**Хэмжилт (кирилл дээр СУРГААД латин дээр ШАЛГАХ):**

| | нарийвчлал |
|---|---:|
| эвхэлтгүй (хуучин) | **52.8%** |
| эвхэлттэй | **97.8%** |

Өөрөөр хэлбэл латинаар бичдэг хүн бараг ойлгогдохгүй байжээ.  Ерөнхий
нарийвчлал ч 88.5% → 92.3% болов — **ижил өгөгдөл дээр, зөвхөн эвхэлтээс**.

`preprocess()` одоо `fold_text()`-ийг дуудна:

```
«Хийснээ илгээе»  «hiisnee ilgeeye»  «ХИЙСНЭЭ ИЛГЭЭЕ»   →  " hisne ilge "
«ХАС-01»  «has 01»  «HAS_01»  «hac-01»                  →  " has 01 "
```

Давхардсан үсэг хураадаг тул («уу»→«у», «ee»→«e») эгшиг нэмэх/хасах
алдаа ӨӨРӨӨ арилна — тусад нь алдааны жишээ цуглуулах шаардлагагүй.

**ЭНЭ НЬ ДӨРВӨН ХОСЛОЛ.** Аль нэгийг өөрчилвөл дөрвүүлээ:

```
backend/src/lib/textFold.ts                  вэб хайлт
frontend/src/shared/lib/search/normalize.ts  вэб хайлт
revit-mcp/training/textfold.py               загвар сургалт
revit-mcp/addin/TextFold.cs                  Revit таамаглал
```

⚠️ **Эвхэлт нь цэг таслалыг устгана.** Монголд асуултыг бөөм («уу/вэ/бэ»)
зөөдөг тул алдагдахгүй; англид «is it 70%?» ба «it is 70%» хоёрын цорын
ганц ялгаа тэмдэг байж болох тул `qmark` гэсэн үг залгадаг.

⚠️ **Эвхэлтийг «зөв болгох» гэж бүү өргөтгө.** Латин «c»-г «s» болговол
«ц»→ts→c→s болж «цаг»/«саг» нийлнэ, англи «cat»→«sat» болно.  Харагдацын
холимогийг ЗӨВХӨН шифрийн түвшинд, засварын зай ≤ 1-ээр барина
(`Slots.cs`) — тэнд олонлог хаалттай, богино тул аюулгүй.

### ХАРИУЛТЫН ХЭЛ — бичсэн хэлээр нь хариулна

⚠️ Ангилагч англи хэлийг таньдаг болсны дараа ч хариулт нь МОНГОЛООР гардаг
байв: «unhide everything again» → зөв ажиллаад «Тусгаарлалтыг цуцаллаа» гэж
хариулна.  Санааг ойлгоод хариултаа ойлгуулахгүй байх нь хагас ажилласантай адил.

`addin/Lang.cs` гурван дүрэмтэй:

1. **кирилл байвал → монгол** (хамгийн тодорхой дохио)
2. **англи туслах үг байвал → англи** (`the · is · my · what · please · can …`)
3. **дохиогүй бол → өмнөхийг хадгална** («BA-01», «70%», «ok»)

⚠️ **`progress`, `sheet`, `isolate`, `push` зэрэг мэргэжлийн үг ДОХИО БИШ.**
Монголчууд эдгээрийг өдөр тутам холимог бичдэг («progress оо push хий») тул
дохио болговол монгол мөрийг англи гэж алдана.

⚠️ **Латинаар бичсэн монгол нь МОНГОЛ хариулт авна.** Ажилтнууд кирилл
УНШИНА, зөвхөн БИЧИХ нь хэцүү (гарын байрлал, утас).

⚠️ **Орчуулгын түлхүүрийн хүснэгт БИШ, `Lang.T(mn, en)` шууд хос.**  Ингэснээр
монгол текст эх кодод УНШИГДАХУЙЦ үлдэнэ; түлхүүр ашиглавал уншиж байгаа хүн
юу бичигдэхийг мэдэхгүй болж, орчуулга нь кодоос салж хоцордог.

### СЛОТ ГАРГАЛТ — «өөрөө зөв гүйцэтгэх» хэсэг

Санаа зөв таних нь хагас нь.  `addin/Slots.cs` нь хуудас ба хувийг гаргана.

⚠️ Өмнө нь `num.Replace(" ","")`-ийг мөрөөр нь харьцуулдаг байсан тул
**«BA-01» (латин), «БА01» (зураасгүй), «ба 1» (тэггүй) гурвуулаа ОЛДОХГҮЙ**
байв.  Одоо дөрвөн түвшин:

1. шифр ЯГ таарах — `ba01` = `ba01`
2. эхний тэггүй — `ba1` = `ba01`
3. ойрын таарц (зай ≤ 1) — `hac03` ≈ `has03` *(кирилл «с» ↔ латин «c» харагдацаар ижил)*
4. хуудасны **НЭРЭЭР** — «фасад харуул» → «Нүүр фасад» (үгийн давхцлаар)

Түвшин бүрд **хоёрдмол бол NULL** — таамаглахаас асуусан нь дээр.
Мөн тусгаарласан хуудсаа НЭРЛЭЖ хэлдэг болов, ингэснээр буруу хуудас
сонгосон бол хэрэглэгч тэр дор нь харна.

### ⚠️ Хилийг тодорхой хэл

Ангилагч нь **чиглүүлэгч**, LLM БИШ. Тэр нь:
- ✅ «ямар үйлдэл» гэдгийг тоглоно
- ✅ хуудасны дугаар, тоо гаргана
- ✅ «ойлгосонгүй» гэдгээ мэднэ
- ❌ чөлөөт асуултад хариулахгүй
- ❌ монголоор тайлбар зохиохгүй
- ❌ олон алхамт төлөвлөгөө гаргахгүй

Эдгээрийг «бэлэн хариу» (canned response) болон UI-аар шийднэ.
