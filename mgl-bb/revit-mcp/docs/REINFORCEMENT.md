## 5. Хомутын хэмжээс — шийдвэр ба хязгаарлалт

**Асуулт:** «Бетон нүүрээс хомутын ГАДНА/ДОТОР ирмэг хүртэл» гэсэн хэмжээсийг Revit-ийн жинхэнэ `Dimension`-аар хийж болох уу?

**Хариулт (API-аас):** Арматурын «rendered edge»-д Reference өгдөг API **алга**.  Хомутын шулуун хэсгийн геометр нь цилиндр
нүүр (`CylindricalFace`); түүнд хэмжээс тавивал Revit цилиндрийн ТЭНХЛЭГ (centerline) хүртэл хэмждэг.  Тиймээс гурван
backend-тэй (`ISectionDimensionRenderer`), хэмжээс бүрд дарааллаар оролдоно — **хэмжээс үүссэний дараа `dim.Value`-г тооцоолсон
зайтай (0.5 мм) тулгаж, таарахгүй бол буцаана** (SubTransaction):

1. `NativeRebarFaceRenderer` — бетон нүүр ↔ хомутын цилиндр нүүрний лавлагаа.  **ЗӨВХӨН «Тэнхлэг» горимд** (цилиндрийн тэнхлэг = centerline).
2. `ProxyLineRenderer` — бетон нүүр ↔ хомутын ирмэгийн ЯГ тооцсон байрлал дахь **үл үзэгдэх detail шугам** (`OST_InvisibleLines`).
   Revit-ийн жинхэнэ `Dimension`; утга нь яг гадна/дотор ирмэг хүртэл.  Шугам нь хомуттай холбогдоогүй → «Тэмдэглэгээ шинэчлэх»-ээр дахин тооцно.
3. ~~`AnnotationOnlyRenderer` — детайл шугам + `TextNote` (ЛАВЛАГААГҮЙ, хэмжээс биш).~~  **УСТСАН (2026-10-02, §11)**: бүх backend унавал буруу хэмжээс/зураг
   тавихгүй, тэр талыг алгасч «Хомутын бодит ирмэгийн reference олдсонгүй — хэмжээсийг алгаслаа.» гэж мэдэгдэнэ.  Оронд нь backend №1.5 — `NativeRebarEdgeRenderer`
   (бодит геометрийн ирмэгийн Reference).

Тайлан бүр хэмжээс бүрийн backend-ыг хэлнэ.  **Гадна/Дотор ирмэг горимд хэмжээс бетон нүүр талдаа жинхэнэ холбоостой, хомут талдаа
proxy шугамд холбогдоно** — хомут зөөгдвөл хэмжээс өөрөө дагахгүй.

⚠️ Native backend: `Options.View` ба `DetailLevel`-ийг ХАМТ тавивал `InvalidOperationException` (Revit-ийн баримт) — зөвхөн `DetailLevel = Fine`
тавина.  Rebar-ийн геометр coarse/medium 2D харагдацад solid БИШ муруй буцааж магадгүй (UNSURE — live шалгана); тэр үед Native нь
«цилиндр лавлагаа олдсонгүй» гэж proxy руу шилжинэ.

⚠️ **Proxy шугамд өөрийн хэмжээсээ (гараар) холбовол** «Тэмдэглэгээ шинэчлэх»/дахин ажиллуулах үед шугамтай хамт Revit тэр хэмжээсийг
чимээгүй устгана — proxy шугамд бүү холбо.

**Multi-Rebar Annotation** (`MultiReferenceAnnotation`)-ыг ашиглаагүй: төрөл нь төсөл тус бүрийн тохиргоо, өөрөө хэмжээсийн шугам
үүсгэдэг (инженер ажлын арматурт зөвхөн tag л хүссэн).  Ажлын арматурт `IndependentTag` (арматурын Reference-д холбогдсон, бичвэр нь
инженерийн Rebar tag family-ийн параметрээс).

## 6. Хомут / ажлын арматурыг ангилах (нэрээр БИШ, геометрээр)

`RfSectionGeometry.Classify`: хомутын (дэгээгүй) гинж — **хавтгай** (Newell-ийн нормаль, хазайлт ≤ 0.1 мм+0.1 %) ба нормаль нь
огтлолын нормальтай ≤ 15° ⇒ **хомут**; үгүй бол хамгийн урт хэрчим огтлолын нормальтай ≤ 25° ⇒ **ажлын арматур**; бусад (спираль,
хөндлөн дам нурууны хомут) ⇒ алгасна.  Хомутын олонлогоос огтлолын хавтгайд ХАМГИЙН ОЙР ширхгийг л авна; ажлын арматурыг ширхэг
бүрээр хавтгайг огтолсон цэгээр.  Эзний ЗӨВХӨН өөрийн арматурыг уншина (`GetRebarsInHost`, харагдацад харагдаж буй) — загварын бүх арматур БИШ.

**Арматурын эхлэл/төгсгөл** (төгсгөлийн тэмдэг): `GetTransformedCenterlineCurves`-ийн гинжийг `curves[0]`-ийн эхлэл гэж ТААМАГЛАХГҮЙ —
баримт зөвхөн «chain of curves» гэдэг тул үзүүрийг ХОЛБОЛТООР олно (`Core/RfChain`: өөр муруйтай давхцдаггүй чөлөөт үзүүр; индекс бага
муруйных = эхлэл; хаалттай гогцоо бол Revit-ийн дараалал).  Муруй эсрэг хадгалагдсан, гинж буцаж өгөгдсөн ч зөв (тестлэгдсэн).

**Харагдацын хавтгай:** `View.Origin` нь ПЛАН дээр утгагүй (баримт) → план дээр харагдацын түвшний `ProjectElevation`, бусад үед SketchPlane
(`RfView.PlaneOrigin` = `CdEngine.ViewPlaneOrigin`-ийн бодит Revit дээр шалгагдсан логик).  Огтлолын түвшин: View Range-ийн Cut Plane-ийн
`Level.ProjectElevation + offset` (`AutoAnnotate/AaScan.ReadPlan`-тай ижил; `Level.Elevation` БИШ — «Elevation Base = Shared» үед зөрнө).

Эргэсэн гишүүн: бетон нүүрнүүдийн нормалаас **гишүүний локал тэнхлэг (U, V)** гаргаж, «зүүн/баруун/дээд/доод»-ыг тэрээр тодорхойлно.
Tag-ийн бичвэр ХЭВТЭЭ тул байрлуулалт гишүүний тэнхлэгт, давхцал ХАРАГДАЦЫН координатад (SAT) шалгагдана.

## 8. ГАР QA (Revit дээр) — эхлээд ЭНЭ хийгдэх ёстой

Эхний удаа: файлд тэмдэглэгээний family-үүд (Detail Item/Generic Annotation тэмдэг, Rebar tag) ачаалсан, дам нуруу + хомут + ажлын
арматуртай (олонлог/bar set ч) төсөл.  **Үнэлэх үед `reinforcement.json`-ыг устгаж өгөгдмөлөөс эхэл.**

### 8.1 Түүвэр хувилах
1. DN-1 түүврээ бүрэн форматлаж, арматурт `Partition = DN-1…DN-5` онооно.  «Түүвэр хувилах» → эх = DN-1.
   **Хүлээлт:** Partition талбар автоматаар танигдсан («автоматаар танисан»), жагсаалтад DN-1 нь сонгогдоогүй, нэрийн загвар «Beam {Partition} Reinforcement».
2. Урьдчилан харалт: DN-2…5 «+ Үүсгэнэ».  Үүсгэх → **хүлээлт:** 4 шинэ түүвэр; багана, гарчиг, формат, эрэмбэ, тооцоолсон талбар эхтэйгээ ижил; шүүлтүүр нь Partition бүрийнх.  Нэг Ctrl+Z → бүгд арилна.
3. Дахин ажиллуул (бодлого «Алгасах»): «✓ Байгаа», юу ч өөрчлөгдөөгүй.  Нэг шүүлтүүрийг гараар буруу болгоод «Filter шинэчлэх» → зөвхөн тэр засагдана.
4. Partition талбаргүй түүвэр дээр: «Partition — нуугдсан талбар нэмнэ» сонголт; хуулбарт нуугдсан талбар орсон, **эх түүвэр өөрчлөгдөөгүй**.
5. 100+ Partition (скрипттэй өгөгдөл): урьдчилан харалт шууд, үүсгэлт нэг transaction group, хугацаа тайланд (`ms`).
6. Онцгой: хоосон Partition (жагсаалтад ороогүй, анхааруулга), кирилл нэр, «DN-1 » (захын зай — анхааруулга), «DN:1» (нэр `DN_1` болно), давхардсан нэр, нэр өөр (Rebar биш) түүвэрт эзлэгдсэн (Мөргөлдөөн — ХЭЗЭЭ Ч дарахгүй).
7. «Солих»: хуудсан дээр байрласан түүвэрт баталгаажуулалт гарч, шинэ түүвэр ЯГ тэр хуудсан дээр дахин байрласан.
8. **Эх түүвэр дээр Duplicate-ийн хадгалсан зүйлийг нүдээр шалга** (багана өргөн, нуугдсан талбар, групп гарчиг, calculated field, itemize).  Хэрэв Revit ямар нэг юмыг хадгалахгүй бол энд тэмдэглэ.
9. **Хуудсан дээр байрласан түүвэрт «Солих»:** байрлал, эргэлт сэргээгдсэн; хуудсыг өөр хэрэглэгч эзэмшсэн үед БҮГД буцаж хуучин түүвэр хэвээр.
   ⚠ **Хуваагдсан (split) эсвэл «хуудсаар шүүх» түүвэрт «Солих» ХИЙГДЭХГҮЙ** — «Мөргөлдөөн» (сегмент шинэ түүвэрт сэргэхгүй; §12).
   Гараар хийсэн ижил нэртэй түүвэрт «Солих» нь «Мөргөлдөөн» гэж гарч юуг ч устгахгүй.  Синкийн «Шүүлтүүр засах» эх түүврийг хөндөөгүй.
10. «Түүвэр синк хийх»: шинэ Partition нэмэх → «+ Дутуу», шүүлтүүр сольсон → «↻», Partition-ыг арматураас арилгах → «○ загварт алга» (чагтлахгүй бол юу ч устахгүй).

### 8.2 Арматурын төгсгөлийн тэмдэг
1. Сонгогдоогүй байхад дарж, тэмдэг + «Эхлэл + Төгсгөл» сонго → арматур сонго.  **Хүлээлт:** тэмдэг арматурын БОДИТ төгсгөлд, арматурын чиглэлд (зүгээр, L, U, дэгээтэй, олонлог).
2. Дахин ижил арматур дээр дар → «Өмнө тавигдсан» тоо, давхар тавигдсангүй.  «Давхар зөвшөөрөх» чагтлавал л нэмнэ.
3. Эргэсэн зүсэлт (View Rotate / эргэсэн дам нуруу): тэмдгийн чиглэл арматурын чиглэлтэй таарна.  Mirror хийсэн дам нуруу.
4. Чиглэл буцсан арматур (Flip): эхлэл/төгсгөл солигдсон тэмдэг зөв талд.
5. Зүсэлтэд цэг болж харагдах арматур: тэмдэг эргэлгүй, тайланд «end-on».
6. Нуугдсан ширхэг (Presentation Mode «Эхний/Сүүлийн»), crop-оос гадна төгсгөл — тавигдахгүй, тайланд тоо.
7. Арматурыг зөө → «Тэмдэглэгээ шинэчлэх» → тэмдэг дагаж зөөгдсөн/эргэсэн; гараар тавьсан тэмдэг хөндөгдөөгүй.
8. Харагдацыг «Duplicate with Detailing» хий → хуулбар дээр дахин ажиллуул → давхардахгүй, эх харагдацын тэмдэг хөндөгдөөгүй.
9. Family ачаалаагүй үед ойлгомжтой Монгол мессеж.
10. Хоёр ширхэг, дэгээтэй, **Flip** хийсэн, олонлог (bar set) арматур дээр: тэмдэг ЛОГИК төгсгөлд, чиглэл арматураас гадагш — план, зүсэлт, эргэсэн/mirror харагдацад.
11. Зүсэлтэд цэг болж харагдах олон арматур (host горим): ширхэг бүрд нэг л тэмдэг, зөвхөн зүсэлтийн гүнд төгсөж буй нь; харагдахгүй арматур алгассан.

### 8.3 Огтлолын арматурын тэмдэглэгээ
Тест тохиолдлууд: тэгш өнцөгт дам нуруу, өргөн, гүн, дөрвөлжин/тэгш өнцөгт багана, **эргэсэн багана (план), эргэсэн огтлол**, олон хомут (өөр голч, дотор боолт), 4 талд ажлын арматур, булангийн арматур, налуу огтлол (≤5°), хомут/ажлын арматургүй, crop дотор хэсэгчлэн.
1. Дам нурууны огтлол нээж дам нуруугаа сонго → цонх.  **Preview** нь хомутын зай (cover), tag-уудыг харуулна.
2. «Гадна ирмэг» → Үүсгэх.  **Хүлээлт:** Left/Right/Top/Bottom хэмжээс cover-тэй (ж: 40) таарна; **тайлан хэлэх backend-ыг тэмдэглэ** (Native / лавлагаа шугамтай / зөвхөн зураг).  Хэмжээсийг сонгож «Reference»-ийг шалга: нэг үзүүр нь бетон нүүр, нөгөө нь `<Invisible lines>` шугам.
3. «Дотор ирмэг»: cover + хомутын голч; «Тэнхлэг»: cover + голч/2.  Утгууд preview-тэй яг таарна.
4. Ажлын арматурын tag-ууд: tag бүр арматурын элементэд холбогдсон (арматурыг сонгоход tag-ийн шалгагдана), бичвэр нь Rebar tag family-ийн параметрээс (хатуу бичвэр БИШ), leader зөв ширхэгт; tag-ууд давхцахгүй.
5. Дахин ажиллуул (өөр cover-тэй) → ЗӨВХӨН энэ эзэн дээрх өмнөх автомат тэмдэглэгээ солигдоно; гараар тавьсан хэмжээс/tag хөндөгдөөгүй.
6. Хомутыг зөөгөөд «Тэмдэглэгээ шинэчлэх» → шинэ байрлал, хоосон үр дүнтэй бол өмнөхийг УСТГАХГҮЙ.
7. Нэг Ctrl+Z → бүх тэмдэглэгээ нэг дор арилна.
8. Хомутгүй/Rebar-гүй гишүүн, фасад харагдац, 3D: ойлгомжтой мессеж, юу ч бичигдэхгүй.
9. **Баганын ПЛАН** — Project Base Point / Survey Point-ийн өндөр 0 БИШ, «Elevation Base = Shared» файл дээр: хомутын хэмжээс гарсан (тайланд «хомут хол» биш),
   `NewDetailCurve`/`TextNote`/`Dimension` план дээр ажилласан, `<Invisible lines>` загвар хэрэглэгдсэн.
10. Tag-ийн leader: олонлог (bar set) дээр leader ЗӨВ ширхэгт очсон; тайланд «leader-ийн төгсгөл» гэсэн анхааруулга гараагүй.  Үгүй бол `GetTaggedReferences()`-ийг шалга.
11. Дахин ажиллуулахад Rebar tag family-г түр (Unload) хийвэл өмнөх тэмдэглэгээ ХЭВЭЭР үлдэх ёстой (юу ч устахгүй).

## 9. Мэдэгдэж буй хязгаарлалт

* **Хомутын гадна/дотор ирмэг:** Revit API Reference өгдөггүй (§5).  «Тэнхлэг» горимоос бусад үед хомут талдаа proxy шугам.  Хэмжээс хомутыг дагахгүй (шинэчлэх товч хэрэгтэй).
* **Тэгш өнцөгт огтлол:** налуу/муруй нүүртэй (трапец, хавтан) гишүүнд хүрээг босоо/хэвтээ нүүрээр л тооцож анхааруулна.
* **Налуу огтлол:** хавтгай гишүүний тэнхлэгт ±5.7° дотор л (нүүр), ±15° (хомут), ±25° (ажлын арматур).
* **Спираль, хөндлөн хомут, Area/Path Reinforcement-ийн арматур** (`RebarInSystem`), freeform арматур — дэмжигдэхгүй (тайланд тоо).
* **Tag-ийн хайрцаг:** family-ийн бодит хэмжээг уншихгүй, цаасан 16×5 мм-ээр ойролцоолно → гараар засах хэрэгтэй үед тайлан «давхцал үлдсэн» гэнэ.
* **Түүвэр хувилах:** Partition нь ТЕКСТ параметр гэж үзнэ (Integer/Double параметрт шүүлтүүр алдаа өгч тэр түүврийг алгасна).  Хоосон Partition-д түүвэр үүсгэхгүй.  Нэг талбар дээрх олон шүүлтүүрийн ЭХНИЙХИЙГ л солино.  «Цуцлах» = диалогийг хаах (Revit transaction дундаас цуцлах боломжгүй).
* **Огтлолын «Дахин ажиллуулах/шинэчлэх»:** ЭХЛЭЭД шинийг үүсгэж, хамгийн багадаа нэг элемент амжилттай үүссэн үед л өмнөхийг устгана; юу ч үүсээгүй бол
  БҮГД буцаж өмнөх тэмдэглэгээ хэвээр.  Өөр хэрэглэгч эзэмшсэн (workshared) харагдацад юу ч тавихгүй (бүртгэл бичигдэхгүй тул).
* **Түүвэр «Солих»:** ЗӨВХӨН энэ хэрэгслийн үүсгэсэн (Extensible Storage тэмдэглэгээтэй) түүврийг устгана; хэрэглэгчийн гараар хийсэнд
  «Мөргөлдөөн» (шүүлтүүрийг «Filter шинэчлэх»-ээр засна).  Хуудсан дээрх байрлал, эргэлтийг сэргээнэ (хуваагдсан/«хуудсаар шүүх» түүврийг СОЛИХГҮЙ — §12); аль нэг алхам унавал БҮГД буцна.
  Revit 2027-ийн `ScheduleAnchor`/`SchedulePosition`-ийг хараахан хуулахгүй (UNSURE — live шалгана).  «Синк»-ийн «Шүүлтүүр засах» эх түүврийг ХЭЗЭЭ Ч хөндөхгүй.
* **Tag-ийн толгой:** Revit-ийн баримтаар `IndependentTag.Create`-ийн цэг нь leader-ийн ТӨГСГӨЛ; толгойг дараа нь `TagHeadPosition`-оор зөөдөг.  Толгойн
  бодит анхдагч цэг (family-ийн anchor) төвтэй таарахгүй байж болно → «давхцалгүй» нь баталгаагүй, preview-ийн хайрцаг төвтэй гэж үзсэн.  Leader-ийн
  чөлөөт төгсгөл тохируулагдахгүй бол тайланд ИЛ мэдэгдэнэ.
* **Төгсгөлийн тэмдэг:** харагдахгүй арматурыг (харагдацад) алгасна; цэг болж харагдах (end-on) арматурын төгсгөлийг (зүсэлт/фасад/detail-д) харагдацын
  гүнд (crop хайрцгийн Z) орсон ТӨГСГӨЛД, ширхэг бүрд нэг л тэмдэг тавина.  Crop хайрцгийн Z-ийн утга учир (UNSURE) live шалгагдах хүртэл
  гүнгийн шүүлтүүр ЗӨВХӨН end-on төгсгөлд хэрэглэгдэнэ.  Тэмдэглэгээ (marker) бичигдэхгүй бол тэмдгийг үлдээхгүй.
* **Модель хөндөх тэмдэглэгээ:** хэрэгслүүд зөвхөн харагдацад хамаарах элемент (хэмжээс, шугам, tag, тэмдэг) ба түүврийг ҮҮСГЭНЭ — арматур, family, бусдын түүвэр/хэмжээсийг өөрчлөхгүй, устгахгүй (ЗӨВХӨН «Солих»/синкийн «Устгах» — баталгаажуулалттай).

Нэг тэмдгийн бүх элемент ижил Extensible Storage түлхүүртэй (`SymbolUid = "mk:circle"` г.м.; schema өөрчлөгдөөгүй), «Тэмдэглэгээ шинэчлэх» бүгдийг нь зөөж/эргүүлнэ (төвийг элементүүдийн дунд цэгээс).  Хагас үүссэн тэмдгийг үлдээхгүй |
| Тохиргоонд ElementId хадгалахгүй | `reinforcement.json`: `SymbolFamily` + `SymbolType` (нэр).  Хуучин `SymbolUid`/«Family : Type» нэг мөр зөвхөн уншигдана.  «MGL» угтвартай family анхны сонголт |

### 11.2 Огтлолын арматурын тэмдэглэгээ

* **Ангилал** (`RfSectionGeometry.Resolve`): `StirrupTie` + хавтгай гогцоо ⇒ хомут (tag + хэмжээс); `Standard` + огтлолын нормалиар урсах ⇒ ажлын арматур
  (ЗӨВХӨН tag, хэмжээс ХЭЗЭЭ Ч үгүй); **`Standard` + хомут шиг хавтгай гогцоо (бөгж Standard shape-ээр) ⇒ гогцоог tag-лана, хэмжээс ХЭЗЭЭ Ч үгүй**
  (`RfClassBasis.StandardLoop`, `RfBarSample.TagOnly`; хэмжээс зөвхөн Stirrup/Tie style-тай хомутоос).  `StirrupTie` боловч уртааш (зөрөлт) таамаглахгүй —
  алгасаж тайланд тоог хэлнэ.  Style мэдэгдэхгүй (shape/free-form accessor уншигдаагүй) үед геометрээр нөөцөлнө.
* **Бодит ирмэгийн Reference**: `rebar.get_Geometry(Options{ComputeReferences=true, View=идэвхтэй харагдац})`, дараа нь `DetailLevel=Fine`
  (Revit-ийн баримтаар `View` ба `DetailLevel`-ийг ХАМТ тавьж болохгүй) — `Solid.Edges` / `Line`-ээс тухайн хомутын ширхэг
  (`GetBarIndexFromReference`), харагдацын хавтгайд параллель, хүлээсэн физик ирмэгийн координатад (0.5 мм) таарсныг ТАТНА.  Хэмжээс үүссэний
  дараа `dim.Value`-г тооцоолсон зайтай тулгана.  Цилиндрийн нүүр ихэнхдээ яг гадна/дотор ирмэгт seam шугамгүй тул энэ нь **олдохгүй байж болно** —
  тэр үед үл үзэгдэх witness шугам (хэвээр).  ⚠️ Бодит Revit дээр аль нь ажилладаг нь ТУРШИГДААГҮЙ.
* **Хомутын голч уншигдахгүй** (0/сөрөг) ⇒ «Гадна/Дотор ирмэг» хэмжээс тавигдахгүй (эс бөгөөс гадна = тэнхлэг болж чимээгүй буруу), «Тэнхлэг» боломжтой.
* **Tag бүлэглэл** (`GroupTags`, өгөгдмөл асаалттай): ⚠️ Revit-ийн арматурын tag нь ЗӨВХӨН tag-лагдсан ЭЛЕМЕНТИЙН өөрийн мэдээллийг (Quantity/Mark/Number) уншдаг тул
  элемент хоорондын нэгтгэл ЗӨВХӨН Revit өөрөө **ИЖИЛ `Rebar Number`** (`BuiltInParameter.REBAR_NUMBER`) өгсөн арматурт: түлхүүр = (төрөл | голч 0.01 мм | shape | Rebar
  Number) + гишүүний хамгийн ойр тал (Доод > Дээд > Зүүн > Баруун, тэнцүү үед тогтмол); төлөөлөгч = бүлгийн төвд хамгийн ойр ширхэг.  **Дугааргүй (хоосон) арматур бүр
  өөрийн tag-тай** (нэгтгэхгүй — тоо дутуу харуулахгүй).  Унтраавал бүгд элемент бүрээр.  Layout түлхүүрээр эрэмбэлэгдсэн тул оролтын дараалалаас үл хамаарна.
* **«Өмнөх MGL тэмдэглэгээг солих»** (өгөгдмөл асаалттай): унтраавал өмнөх тэмдэглэгээ ХЭВЭЭР үлдэж (энгийн тэмдэглэгээ болно, бүртгэлээс гарна) шинэ нь нэмэгдэнэ.
  Гараар тавьсан хэмжээс/tag аль ч тохиолдолд УСТАХГҮЙ.  «Тэмдэглэгээ шинэчлэх» нь үргэлж солино.  Асаалттай үед **төрлөөр** солино: шинэ хэмжээс (эсвэл хэмжээс
  төлөвлөөгүй) үүссэн бол өмнөх хэмжээс/лавлагаа шугамыг, шинэ tag үүссэн бол өмнөх tag-ийг л устгана — нэг төрөл бүтэн унавал (ж: зөвхөн tag үүсч хэмжээс бүгд унасан)
  өмнөх сайн хэмжээсийг ҮЛДЭЭНЭ (бүртгэлтэй хэвээр).  Устгал өөрөө унавал тэр элементүүд шинэ багцад бүртгэлтэй үлдэнэ (бүртгэлгүй «өнчин давхардал» болохгүй).
  ⚠️ «Шинэчлэх»/«Солих» нь тэмдэглэгээг ШИНЭЭР үүсгэдэг тул хэрэглэгчийн гараар зөөсөн/форматласан (ж: tag-ийн байрлал) өөрчлөлт алдагдана.
* Proxy (witness) шугам **fail-closed**: «Үл үзэгдэх шугам» хэв маягийг тавьж чадахгүй бол харагдах шугам үлдээхгүй, буцаана.  `View.SketchPlane` нь харагдацын хавтгайд
  байхгүй (зүсэлтийн work plane өөр түвшинд) үед `View.Origin` ашиглана (`NewDetailCurve` «хавтгайд биш» гэж унахгүйн тулд).
* Tag family ачаалаагүй: «Арматурын tag family энэ төсөлд ачаалагдаагүй байна…» — tag алгасагдана, хэмжээс хэвээр, tool унахгүй.
* Шошго: «Хомутын гадна ирмэг — бетон гадаргуунд ойр тал» / «Хомутын дотор ирмэг — огтлолын төв рүү харсан тал» / «Тэнхлэг» (нэмэлт).

### 11.3 Түүвэр клонлох

* **Нэг global scan**: `RfParam.ScanPartitions` — `FilteredElementCollector(OST_Rebar)`-ыг НЭГ удаа явж арматур бүрийн `NUMBER_PARTITION_PARAM`-ийг
  ЗӨВХӨН уншина (⚠ `ELEM_PARTITION_PARAM` = Workset тул §12-оор ХАСАГДСАН — өмнө нь Number хоосон үед нөөц болгон ашигладаг байсан нь Workset-ийн нэрсийг «Partition» гэж жагсаадаг алдаа байв); Partition-ийн индекс ЭНЭ scan-аас.
  Partition тус бүрт дахин scan хийхгүй (өмнө нь 400 арматурын sample + бүтэн scan хоёр дамжлага байсан).
* **Шүүлтүүр**: `ScheduleFilterType.Equal` (`RfScheduleNames.SameValue` — «ДН-1» ≠ «ДН-10»).  `RfFilterPlan.Decide` (Core, тестлэгдсэн): байгаа Partition
  шүүлтүүрийг `SetFilter(index)`-ээр СОЛИНО, байхгүй бол `AddFilter`; бусад шүүлтүүр хөндөгдөхгүй (`SetFilters(list)` ашиглаагүй).  **8 шүүлтүүртэй,
  Partition шүүлтүүргүй** бол 9 дэхийг нэмэхгүй — «Түүвэр 8 шүүлтүүртэй тул Partition шүүлтүүр нэмэх боломжгүй.»; эх түүвэр дээр Duplicate хийхээс ӨМНӨ нэг удаа шалгана.
* `View.CanViewBeDuplicated(Duplicate)` шалгана.  Workshared файлд байгаа түүврийн шүүлтүүр шинэчлэх/солихдоо `GetCheckoutStatus`-аар өөр хэрэглэгчийн эзэмшил
  илрүүлбэл «Энэ түүврийг өөр хэрэглэгч эзэмшиж байна: {нэр} — алгасав.» (баримтаар кэш — баталгаа БИШ; бодит унасан Transaction-ыг SubTransaction буцаана).
* Нэрийн fallback «{эх нэр} — {Partition}» (урт зураас).  Үр дүн: «{N} түүвэр үүсгэв · {M} алгасав · {K} алдаатай.»  Диалогт **хайлт** (Partition-оор): «Бүгдийг сонгох»,
  урьдчилан харалт болон «Үүсгэх» нь ЗӨВХӨН харагдаж буй (хайлтад тохирсон) мөрөнд — хайлтаар нуугдсан мөр чагтлаатай ч үүсгэгдэхгүй.

### 12.2 Тусгай асуултуудын хариулт (A–J)

* **A. Тэмдгийн өмчлөл/давхардлын хамгаалалт rerun + Copy/Paste-д найдвартай юу?**  Түлхүүр = (арматур, төгсгөл, ширхэг, дэгээ) НЭГ харагдацад; тэмдгийн элемент бүр Extensible Storage-тай.  Rerun: давхардахгүй [U].  Copy/Paste:
  Entity хамт хуулагдана (RevitAPI.xml) ⇒ хуулбар ижил түлхүүртэй → байрлалаар тусдаа бүлэг («Copy/Paste-ийн хуулбар»), эх = хамгийн бага id; Refresh ЗӨВХӨН эхийг зөөнө, хуулбарыг хөндөхгүй/УСТГАХГҮЙ [U].  Эх тэмдгийн яг дэргэд (≲0.7×хэмжээ) paste хийвэл нэг бүлэг болж «гэмтсэн» гэж ХӨНДӨГДӨХГҮЙ (аюулгүй тал).  Хайлт ажиллах нь [R] (S2/E2/E5) — ажиллахгүй бол эхний тэмдэг тавигдахад ТҮҮНИЙГ ШУУД БУЦААНА.
* **B. `OfClass(typeof(CurveElement))` аюулгүй юу?**  Баримтаар `ElementClassFilter` нь тухайн класс болон удамшсан классыг татна; харин `DetailLine/DetailArc` гэх мэт нарийн дэд классыг ШҮҮЛТҮҮРЭЭР шууд таних боломжгүй ⇒ бүх `CurveElement`-ийг (зөвхөн ЭНЭ харагдацын өмчлөлд — `OwnedByView`) татаад `as DetailCurve` гэж ялгана [S].  Харагдац бүрийн хэмжээгээр хязгаарлагдана.  Бодит ажиллагаа [R].
* **C. `Edge.Reference` хэмжээсийг найдвартай дэмждэг үү, эсвэл witness (proxy) ердийн зам уу?**  Арматурын silhouette ирмэгт зориулсан тогтвортой Reference API-д БАЙХГҮЙ; `Edge.Reference` нь null эсвэл тэнхлэг/шүргэгчийг хэмжиж болно.  Тиймээс код **хэзээ ч итгэхгүй**: хэмжээс үүсгээд `Regenerate` → `Dimension.Value`-г хүлээсэн зайтай (0.5 мм) тулгана, `GetBarIndexFromReference`-ээр ширхэгийг шалгана; таарахгүй бол буцаана.  **Гадна/Дотор ирмэгт witness шугам НЭ ердийн зам** (native edge нь боломжийн үед л).  Witness хэмжээс үүсгэх үедээ зөв боловч хомутыг ДАГАХГҮЙ (тайлан, tooltip-д ИЛ бичсэн; «Шинэчлэх» хэрэгтэй).  [R] (N2).
* **D. Replace/update нь гараар тавьсан тэмдэглэгээг устгаж чадах уу?**  Устгал нь ЗӨВХӨН бүртгэлд байгаа (энэ хэрэгслийн үүсгэсэн, `OwnerViewId == view`) UniqueId-аар; гараар тавьсан юу ч бүртгэлд байхгүй ⇒ хөндөгдөхгүй.  Үлдсэн эрсдэл ХАМААРАГЧ (cascade) — §12.1: SubTransaction дотор бодит устгалын жагсаалтаар шалгаж, бидний биш элемент орвол үлдээнэ [R] (N6).  Бидний ӨӨРИЙН элементийг гараар засвал (tag зөөх, ValueOverride) солиход алдагдана — БАРИМТЖСАН.
* **E. Хэрэгсэл бүрийг хоёр удаа ажиллуулахад давхардах уу?**  Төгсгөлийн тэмдэг: үгүй (end-on засагдсан) [U].  Огтлол: «Солих» асаалттай — шинийг үүсгээд, ТӨРӨЛ БҮРЭН үүссэн үед л өмнөхийг устгана; дутуу үед тэр төрөл давхардаж болно (өгөгдөл алдахаас дээр, мэдэгдэнэ).  «Солих» унтраалттай — өмнөх нь энгийн тэмдэглэгээ болж ҮЛДЭНЭ (зориуд).  Түүвэр: Үүсгэх — нэр мөргөлдвөл «Мөргөлдөөн» (давхар үүсэхгүй); «Алгасах» — юу ч бичихгүй; «Filter шинэчлэх» — идемпотент.
* **F. Rebar Number бүлэглэл бүх замд зөв үү?**  Түлхүүр = төрөл|голч|shape|#дугаар|p:Partition; дугааргүй ⇒ элемент бүр өөрийн tag; Partition ӨӨР ⇒ нэгтгэхгүй (шинэ) [U].  Үлдсэн: нэгтгэсэн tag нь ТӨЛӨӨЛӨГЧ элементийн мэдээллийг л (Quantity) харуулна — ижил дугаартай ӨӨР элемент (тус тусдаа олонлог) бол тоо дутуу харагдана; тайланд мэдэгддэг, «Tag нэгтгэх» унтрааж болно (SHOULD-FIX: тоо нийлбэртэй тэнцүү үед л нэгтгэх).
* **G. Partition шүүлтүүрийн таних нь орчуулагдсан нэрээс хамааралгүй юу?**  Тийм: `ParameterId` / `ScheduleFieldId` — нэрийг ЗӨВХӨН UI шошгонд [S].  Workset-ийг Partition гэж андуурдаг байсан нь засагдсан.  Үлдсэн: Partition нь built-in БИШ (shared parameter) талбар бол автоматаар танигдахгүй — гараар сонгоно (C4, C5 [R]).
* **H. Түүвэр хуулах нь адил нэртэй бусад түүврийг дарж бичиж чадах уу?**  «Алгасах»: БИЧИХГҮЙ.  «Filter шинэчлэх»: зөвхөн (марккер хүчинтэй) эсвэл (аль хэдийн «Тэнцүү» Partition шүүлтүүртэй ба нэр яг таарна) үед; гараар хийсэн, шүүлтүүргүйд шүүлтүүр НЭМЭХГҮЙ; хоёр Partition нэг нэртэй бол ХЭЗЭЭ Ч.  «Солих»: зөвхөн хүчинтэй тэмдэглэгээтэй, split/«хуудсаар шүүх» БИШ, нэрсийг жагсаасан баталгаажуулалттай.  Үлдсэн (зориуд): гараар хийсэн, ижил нэртэй, өөр утгатай «Тэнцүү» шүүлтүүртэй түүвэр «↻ Шинэчлэх» гэж урьдчилан харагдаж, шинэчлэгдэнэ.
* **I. Эх арматур устгагдсаны дараа тэмдэглэгээнд юу болох вэ?**  Төгсгөлийн тэмдэг: «Шинэчлэх» нь «өнчин» гэж тоолно, тэмдгийг УСТГАХГҮЙ.  Огтлол: эзэн (host) устсан бол багцыг «өнчин» гэж алгасаж ХЭЗЭЭ Ч устгахгүй.  Native хэмжээс лавлагаагаа алдвал Revit өөрөө устгаж/хүчингүй болгож болно (Revit-ийн зан — [R] N13); witness хэмжээс шугамтайгаа үлдэнэ.
* **J. Revit-гүйгээр ЮУ БАТЛАГДАХГҮЙ вэ?**  Дараахыг §12.6-д жагсаав: `Edge.Reference`/цилиндр нүүрний хэмжээс, `GetBarIndexFromReference`, Delete-ийн cascade жагсаалт, ES-ийн хуулалт (Copy/Paste, Duplicate View, түүвэр Duplicate), `OfClass(CurveElement)` үр дүн, нүүрний хилийн цэг (`GetEdgesAsCurveLoops`) ба `Reference` Regenerate/SubTransaction rollback-ийн дараа хүчинтэй байх, `Reference.GlobalPoint`, `IsBarHidden` Presentation Mode-д, tag leader, `ScheduleFilterType.Equal`-ийн том/жижиг үсэг/зай, `View.Duplicate`-ийн хадгалалт, workshared унасан хэзээ гарах, 150 Duplicate-ийн хугацаа.

### 12.6 Revit API-ийн үлдсэн хязгаарлалт (баримтаар)

* Арматурын «гадна/дотор ирмэг»-ийн тогтвортой Reference БАЙХГҮЙ; `Edge.Reference`/`Curve.Reference` нь зөвшөөрөгдөөгүй үед null.
* `Options.View` ба `DetailLevel` нэгэн зэрэг тавигдахгүй (код хоёр дамжлагаар).
* `Document.Delete` нь хамаарагчийг асуулгагүй устгана; `GetDependentElements` нь ЯГ Delete-тэй адил гэсэн баталгаагүй ⇒ бодит Delete-ийн жагсаалтыг SubTransaction-д авдаг.
* Extensible Storage-ийн Entity нь элемент хуулагдахад хамт хуулагдана ⇒ эзэмшил/давхардлын шалгалт харагдацын өмчлөл, UniqueId, байрлалаар баталгаажна.
* `WorksharingUtils.GetCheckoutStatus` нь локал кэш (найдвартай биш); `CheckoutElements` нь зөрчилд хязгааргүй хүлээж болно.
* `View.Duplicate`-ийн хадгалалт, `ScheduleFilterType.Equal`-ийн том/жижиг үсэг, түүврийн нэрийн давтагдал/урт/зайн дүрэм — баримтад тодорхойгүй.
* Revit 2027 `ScheduleAnchor`/`SchedulePosition`-ийг «Солих» хараахан сэргээхгүй.
* `IsBarHidden` нь зөвхөн Presentation Mode = Select үед хүчинтэй (баримт) ⇒ FirstLast/Middle дахь харагдахгүй ширхэгийг мэдэхгүй.

  «0 индекс» гэж таамаглахгүй (хасагдсан байрлалыг алгасна), дарсан цэгт ойр / ElementId / геометрийн дарааллаар БИШ.  Горимууд: «Сонгосон ширхэг (дарсан цэгт ойр)» (өмнөх, өгөгдмөл) · «Бүх ширхэг» ·
  **«Эхний ширхэг»** · «Эхний ба сүүлийн ширхэг».  Нэг ширхэгтэй олонлог / нэг л байрлал бодитоор байгаа олонлогт «Эхний ба сүүлийн» ДАВХАР тэмдэг тавихгүй.  Дахин ажиллуулахад давхардал хамгаалалт хэвээр
  (түлхүүр = арматур + төгсгөл + ширхгийн индекс + дэгээ).  Presentation Mode (Эхний/Сүүлийн, Дунд) нуусан бол ТЭР горимоос үлдсэн эхний ширхэг; «Select» горимд нуугдсан ширхэг «эхний» бол
  тайланд «нуугдсан ширхэг» гэж тоологдоно (таамаглаж өөр ширхэг сонгохгүй).  Prefs: `BarSet = "first"`.
* **A2 Эхлэл / Төгсгөлийн БИЕ ДААСАН эргэлт** (`StartRotationDeg`, `EndRotationDeg` — `reinforcement.json`-д тусдаа, хоёр `double?`).  **Семантик (диалогт ИЛ бичсэн):**
  «Арматур дагуу» горимд автомат чиглэл ДЭЭР нэмэгдэх өнцөг (**offset**, CCW градус; `RfEndSymbolMath.TargetAngle`), «Тогтмол» горимд харагдацын хавтгай дахь **абсолют** өнцөг; Эхлэл, Төгсгөл тус тусдаа.
  Ямар ч утга (−45, 135, 450, 22.5) `NormalizeDegrees`-ээр (−180, 180]-д хэвийжинэ — хавчихгүй.  Эргэлт нь тэмдгийн ӨӨРИЙН оруулах цэгийн эргэн тойронд, ХАРАГДАЦЫН нормаль тэнхлэгээр
  (`ElementTransformUtils.RotateElement`); код-оор зурсан тэмдэгт Core-ийн геометр өөрийн төвийн эргэн тойронд тооцно (тойрог — харагдахгүй ч утга хүчинтэй; «×», «/» — харагдахуйц).  Family эргэхгүй бол
  (RotateElement алдаа) чимээгүй орхихгүй: тавьсан тэмдгийг устгаж «Тэмдгийн family-г …° эргүүлж чадсангүй» гэж ИЛ мэдэгдэнэ.
  **Шилжилт** (`RfEndSymbolMath.MigrateRotation`): шинэ талбар байхгүй хуучин файл — «Тогтмол» байсан бол хуучин ганц өнцөг хоёуланд, «Арматур дагуу» байсан бол 0/0 (харагдац өөрчлөгдөхгүй).
  **Refresh-д эргэлт алдагдахгүй:** Extensible Storage-ийн schema-д ШИНЭ талбар НЭМЭХГҮЙ — «Арматур дагуу» горимд хэрэглэгчийн эргэлтийг хадгалах «байгалийн» өнцөгт шингээнэ
  (`StoredNatural = natural − user`, ингэснээр Refresh-ийн `RotationToApply(auto, stored)` = auto + user − natural — Place-тэй ЯГ ИЖИЛ).
* **A3 Тэмдгийн шууд хайлт** (`Core/RfSearch.cs`, `Ui/RfSearchBox.cs`): жагсаалтыг (Family / Type) нэг удаа цуглуулж, бичих бүрд ЗӨВХӨН санах ойд шүүнэ (collector дахин ажиллуулахгүй); том/жижиг үсэг үл хамаарна
  (кирилл, латин, Ө/Ү); Family, Type, «Family : Type» аль нэгээр; хайлтын үгс БҮГД орох (AND).  «Код-оор зурах тэмдэг» сонголт хайлтаас үл хамааран ҮРГЭЛЖ харагдана.  Сонгосон нь шүүлтээр нуугдсан ч
  сонголт/тохиргоо ӨӨРЧЛӨГДӨХГҮЙ («Сонгосон: … (хайлтаар нуугдсан)» гэж харуулна); тохирох зүйл алга бол «Илэрц олдсонгүй».  Тохиргоонд ElementId биш Family + Type нэр (хэвээр).

### 13.3 Түүвэр хувилах

* **B1 Эх түүврийн хайлт**: ижил `RfSearchBox` (хайлт эх түүврийн нэрээр, том/жижиг үсэг үл хамаарна, байгалийн эрэмбэ ДН-1 < ДН-2 < ДН-10 хэвээр).  `RfScheduleSession.Templates()` нэг удаа (зөвхөн Rebar ангилалтай, key/material takeoff, template биш түүвэр).
* **B2 «Түүврийн нэрийн загвар» юу хийдэг (кодыг уншиж тогтоосон):** талбар → `RfScheduleNames.Resolve(pattern, templateName, partition)` → **үүсэх түүвэр бүрийн нэр** (`View.Name`).  Токен нь ЗӨВХӨН `{Partition}` (Partition-ийн утга)
  ба `{Template}` (эх түүврийн нэр); загварт `{Partition}` заавал; хориотой тэмдэгтийг «_» болгоно.  Өгөгдмөл нь `SuggestPattern`: эх нэр өөрийн Partition-ыг агуулбал түүнийг `{Partition}`-аар солино
  («Beam DN-1 Reinforcement» → «Beam {Partition} Reinforcement»), үгүй бол «{Template} — {Partition}».  Мөргөлдөөн: нэр хэн нэгний (манай биш) түүвэрт эзлэгдсэн / хоёр Partition нэг нэрэнд хөрвөх ⇒ «Мөргөлдөөн», ХЭЗЭЭ Ч дарж бичихгүй.
  **Шинэ UI:** «Үүсэх түүврийн нэр» хэсэгт **жишээ** (`Жишээ: DN-2 → Beam DN-2 Reinforcement`) ҮРГЭЛЖ харагдана — ЯГ бодит `Resolve`-оор, чагталсан эхний Partition-оор (үгүй бол эх түүврийнхээс ӨӨР эхнийх).
  Загварын талбар нь «Нэмэлт: үүсэх түүврийн нэрийг өөрчлөх» (хураасан) хэсэгт, токены тайлбартай; хүснэгтийн «Үүсэх түүврийн нэр» багана нь «Үүсгэх» дарахаас ӨМНӨ мөр бүрийн нэр.  Нэрийн томьёо, мөргөлдөөний логик ӨӨРЧЛӨГДӨӨГҮЙ.

### 13.4 Огтлолын арматурын тэмдэглэгээ

* **C1 Хуурамч шугам БАЙХГҮЙ.**  `ProxyLineRenderer`, `NewDetailCurve`, `OST_InvisibleLines`, `InvisibleStyle` Revit давхаргаас УСТСАН (эх кодын хамгаалалт тест: `SectionFeedbackTests.Renderer_source_never_creates_detail_curves_or_invisible_lines`;
  build хийсэн DLL-д ч байхгүйг шалгасан).  Лавлагаа олдохгүй бол тэр талыг алгасч **«Арматурын хэмжээсийн лавлагаа олдсонгүй.»** гэж мэдэгдэнэ (+ юуг үзсэн статистик: шугам N · цилиндр N · лавлагаатай N · хүлээсэн байрлалд N).
  Хуучин ажиллуулалтын witness шугам (өмнөх хувилбарын бүртгэлтэй) ЗӨВХӨН энэ хэрэгслийн бүртгэлээр (`OwnerViewId == view`, UniqueId) «Солих»-д л устна; хэрэглэгчийн DetailLine/CurveElement-ийг ХЭЗЭЭ Ч хөндөхгүй,
  мөн устгалын cascade-ийн хамгаалалт (`DeleteWouldTakeForeign`) хэвээр.
* **Хэмжээсийн Reference-ийн ЯГ зам** (`RfRebarRefs`): хомутын лавлагаа = `rebar.get_Geometry(Options{ComputeReferences=true, View=идэвхтэй харагдац})`, дараа нь `{ComputeReferences=true, DetailLevel=Fine}` (Revit-ийн баримтаар
  `View` ба `DetailLevel`-ийг хамт тавьж болохгүй) — `Solid.Edges`-ийн ШУЛУУН `Edge.Reference` / `Line.Reference`; «Тэнхлэг» горимд нэмэх нь `CylindricalFace.Reference` (тэнхлэг нь хэмжих чиглэлд перпендикуляр).
  Бетон нүүр = `PlanarFace.Reference` (`GetSymbolGeometry()`, `CdEngine`-ийн бодит Revit дээр шалгагдсан хэв маяг).  ⚠️ Reference-ийг ХЭЗЭЭ Ч transform хийсэн хуулбар геометрээс авахгүй (transform нь зөвхөн байрлал/ангилал шалгах математикт).
  Хүлээн авах нөхцөл: тухайн хомутын ширхэг (`GetBarIndexFromReference`), харагдацын хавтгайд параллель, хүлээсэн физик ирмэгийн локал координатад (0.5 мм) — **Гадна/Дотор: хомутын тэнхлэг ∓ голч/2**.
  Дараа нь **trial**: нүүр ↔ хомутын ирмэгийн түр 2-лавлагаат хэмжээс үүсгэж БОДИТ утгыг хүлээсэн зайтай (0.5 мм) тулгаад ЗАВАЛ буцаана — буруу ирмэг/тэнхлэг заасан лавлагаа гинжинд орохгүй.
  ⚠️ Revit API хомутын «гадна/дотор ирмэг»-д тогтвортой Reference ӨГДӨГГҮЙ (цилиндр нүүр) тул «Гадна/Дотор» горимд лавлагаа олдохгүй байж БОЛНО — тэр үед тэр тал алгасагдана (§12.6).  Энэ нь зориуд: буруу/хуурамч хэмжээснээс дутуу хэмжээс дээр.
* **C2 Гинжин хэмжээс** (`Core/RfDimChain.cs`): тэнхлэг бүрт ЯГ НЭГ `Dimension` — хэвтээ `[зүүн нүүр, зүүн хомут, баруун хомут, баруун нүүр]` (гишүүний локал U дагуу), босоо `[доод нүүр, доод хомут, дээд хомут, дээд нүүр]` (V дагуу);
  **нэг `ReferenceArray`, ЛОКАЛ ТЭНХЛЭГИЙН БАЙРЛАЛААР эрэмбэлсэн** (ElementId / collector / геометр туулсан дарааллаар БИШ), 0.5 мм дотор давхцсаныг хасна (нүүр үлдэнэ).  4 лавлагаа ⇒ 3 сегмент (`Dimension.NumberOfSegments`);
  үүссэний дараа лавлагааны тоо, сегментийн тоо, сегмент бүрийн утга (`DimensionSegment.Value` ≟ дараалсан байрлалын зөрүү, 0.5 мм) шалгана — таарахгүй бол буцаана.  Нэг талын лавлагаа олдохгүй бол ТЭР талын нүүр + хомутыг хамт хасч
  **бүрэн биш гинж** (2–3 лавлагаа, «Бүрэн биш гинж» гэж ИЛ мэдэгдэнэ; «Солих» үед өмнөхийг УСТГАХГҮЙ); хомутын лавлагаагүй гинж (зөвхөн бетоны өргөн) үүсгэхгүй.  Хэмжээсийн шугам: хэвтээ — дээд талд, босоо — баруун талд.
  Гадна/Дотор/Тэнхлэг сонголт хэвээр; **30 мм cover, Ø8 ⇒ гадна 26 / дотор 34** (тест: 0/45/90/135° эргэлтэд, гинжний сегментээр ч).  Preview нь нэг гинж (| 26 | 248 | 26 |) харуулна.
* **Multi-Rebar Annotation (MRA) — үнэлсэн, ХЭРЭГЛЭЭГҮЙ.**  RevitAPI.xml: `MultiReferenceAnnotationOptions.SetElementsToDimension` — «dimension will automatically find geometric references in the elements» (Revit өөрөө сонгоно),
  `SetAdditionalReferencesToDimension` (арматур БИШ лавлагаа), лавлагаа нь «харагдацад цэг болж харагдах эсвэл хэмжих шугамд перпендикуляр шугаман» байх ёстой.  Шалтгаан: (1) хомутын ГАДНА/ДОТОР ирмэгийг заах параметр БАЙХГҮЙ — Revit автоматаар сонгоно ⇒
  инженерийн шаардлагыг (outer 26 / inner 34) баталгаажуулах боломжгүй; (2) `MultiReferenceAnnotationType` нь төслийн түвшний төрөл (`CreateDefault` / `Duplicate`) — загварын төрөл өөрчилнө; (3) үүссэн хэмжээсийн лавлагааг уншиж нотлох API байхгүй;
  (4) Revit дээр ажиллуулж БАТАЛГААЖУУЛААГҮЙ.  «Тэнхлэг» горимд нэр дэвшигч — Revit QA-ийн дараа дахин үнэлнэ.
* **C3 Tag үүсэхгүй байсан алдаа.**  ⚠️ Revit-гүйгээр ГАНЦ мөрийг баталж чадаагүй (статик шинжилгээ) — тиймээс бүх боломжит шалтгааныг хаав.  Хуучин урсгалд: (1) tag-ийн төрөл олдохгүй / Structural Rebar Tag биш / ангилал нь харагдацад
  НУУГДСАН (VG) үед ч «амжилттай» (tag-гүй) дуусч болдог, (2) tag-ийн family идэвхжүүлэлт (`Activate`) нь SubTransaction дотор, `Regenerate`-гүй байсан, (3) алдаа ЗӨВХӨН хураагдсан «дэлгэрэнгүй» жагсаалтад, (4) үүссэн tag бодитоор арматурт холбогдсоныг шалгадаггүй байсан.
  **Одоо:** диалог ТҮРҮҮНД (planner tag төлөвлөсөн төрөл бүрт) шалгана — төрөл алга / сонгогдоогүй / «Сонгосон шошго нь арматурт тохирохгүй байна» / «Арматурын шошгоны төрөл олдсонгүй» / «Structural Rebar Tags ангилал … НУУГДСАН» ⇒ «Үүсгэх» ИДЭВХГҮЙ + улаан шалтгаан
  (чимээгүй zero-tag амжилт БАЙХГҮЙ); Render дахин шалгаж (Refresh-ийн замд диалоггүй), төрлийг ЭХЛЭЭД нэг удаа идэвхжүүлж `Regenerate`, дараа нь `IndependentTag.Create(…, СОНГОСОН FamilySymbol, …)`, үүссэний ДАРАА төрөл, харагдац,
  `GetTaggedLocalElementIds` (арматурын id) шалгана; бүх алдаа тайлангийн ҮНДСЭН хэсэгт («⚠ N tag үүсээгүй»).  Үүсэх объект = Revit-ийн жинхэнэ `IndependentTag` (Structural Rebar Tag, арматурт холбогдсон) — текст биш.
  Rebar Number бүлэглэл: ӨӨР дугаар/Partition ХЭЗЭЭ Ч нэгтгэгдэхгүй (тест), дугааргүй арматур бүр өөрийн tag; дахин ажиллуулахад өмнөх MGL tag «Солих»-оор л солигдоно (бүртгэлтэй элемент), гараар тавьсан tag хөндөгдөхгүй.
* **C4/C5/C6 Одоогийн харагдац + сонгосон элемент.**  Командын эхэнд харагдацыг шалгана (Section / Detail / баганын План; бусад — «…Одоогийн харагдац: «нэр»» мессеж, юу ч бичигдэхгүй).  Эзэн: **яг нэг** хүчинтэй (Structural Framing / Column БА арматур агуулах боломжтой) элемент урьдчилан сонгогдсон
  бол ДАХИН сонгуулахгүй; байхгүй бол `ISelectionFilter`-тэй `PickObject`; **хэд хэдэн** бол дур зоргоор нэгийг авахгүй — «НЭГИЙГ нь сонгоно уу»; хүчингүй (ханан г.м.) сонголтыг алгасна (`RfHostPick`, тестлэгдсэн).  Диалог дээд хэсэгтээ «Харагдац: <нэр> (Огтлол)» ба
  «Элемент: <Mark · Family : Type [Ангилал]> Id N» ИЛ харуулна (түүхий Id хоёрдогч); хуучин «Эзэн элемент (Автомат/Дам нуруу/Багана)» сонгогч (юу ч хийдэггүй байсан) хасагдсан.  Диалог: «Хэмжээс (гинжин)» → хомутын ирмэг (Гадна/Дотор/Тэнхлэг), талууд, хэмжээсийн төрөл;
  «Шошго» → ажлын арматур/хомутын tag, төрөл, нэгтгэх; «Өмнөх MGL тэмдэглэгээг солих».

### 13.5 REQUIRES REVIT QA — Revit-гүйгээр БАТЛАГДААГҮЙ зүйлс

Хомутын ирмэгийн Reference-ийн олдох эсэх (`Edge.Reference` / `CylindricalFace.Reference`, Гадна/Дотор vs Тэнхлэг) · `Reference` нь trial-ийн SubTransaction `RollBack` + `Regenerate`-ийн дараа хүчинтэй хэвээр байх · `NewDimension` нь олон reference-тэй (4) НЭГ
хэмжээс үүсгэж `NumberOfSegments == 3`, `DimensionSegment.Value` өгөх · `Dimension.References.Size` · хэмжээс шилжих/арматур устахад Revit-ийн зан · `IndependentTag.Create` нь `new Reference(rebar)`-ээр (ялангуяа олонлог) үүсэх, `GetTaggedLocalElementIds`
нь арматурын id-г агуулах (агуулахгүй бол зөвхөн мэдэгдэл гарна, tag буцахгүй — QA-I дээр ЗААВАЛ ажигла) · tag-ийн category нуугдсан эсэхийн шалгалт · `FamilySymbol.Activate` + `Regenerate` · family тэмдгийн эргэлт (`RotateElement`) анотацийн family бүрт ажиллах ·
`View.GetCategoryHidden(OST_RebarTags)` · ES-ийн `Natural` шингээлтээр Refresh-ийн эргэлт · WPF шинэ хэсгүүд (RfSearchBox, Expander, контекстийн хайрцаг) нүдээр.

### 13.7 Үлдсэн хязгаарлалт (бодит)

* Гадна/Дотор ирмэгийн бодит Reference олдохгүй байх магадлал өндөр (§12.6) — тэр үед хэмжээс алгасагдана; «Тэнхлэг» горим эсвэл Revit QA-ийн үр дүнгээр MRA-г дахин үнэлнэ.
* Бүрэн биш гинж (нэг тал лавлагаагүй) нь 2–3 reference-тэй; инженер гараар нөхнө.
* «Эхний ширхэг»: Presentation = «Select» үед эхний ширхэг нуугдсан бол тэмдэг тавигдахгүй (тайланд «нуугдсан ширхэг»).
* Tag-ийн хайрцгийн хэмжээ цаасан 16×5 мм-ээр ойролцоолсон (хуучин хязгаарлалт хэвээр).
* Ямар ч шинэ тэмдэглэгээг хэрэглэгч гараар зөөвөл «Солих»/«Шинэчлэх»-д алдагдана (хуучин хязгаарлалт).
* **Дахин ажиллуулахад давхардал (хэсэгчилсэн үед):** өмнөх хэмжээс/tag-ийг ЗӨВХӨН тэр төрөл БҮРЭН үүссэн үед солино (`RfReplacePolicy`).  Нэг тэнхлэг/нэг tag тогтмол унадаг бол өмнөх багц үлдэж, шинэ нь дээр нь нэмэгдэнэ
  (өгөгдөл алдахаас дээр гэсэн шийдвэр) — гараар цэвэрлэнэ.  Бүрэн үүссэн ажиллуулалтад давхардал үгүй.
* **tag нуугдсан эсэх:** `View.GetCategoryHidden` нь зөвхөн ангиллын нуултыг мэднэ; харагдацын filter / ангиллын ангилал (category class)-аар нуугдсаныг мэдэхгүй — tag үүссэн боловч харагдахгүй байж болно (QA-I дээр нүдээр шалга).
* **Family эргэлт:** `RotateElement` алдаа өгвөл ИЛ мэдэгдэнэ; харин family эргэлтийг чимээгүй үл тоовол (алдаагүй) илрүүлэх API-г (`GetTransform` г.м.) баримтаас батлаагүй тул илрүүлэхгүй — QA-B-д нүдээр шалга.
  Код-оор зурсан ТОЙРОГ тэмдэгт эргэлт харагдахгүй (хэлбэр тэгш хэмтэй).
* **end-on арматур + «Эхлэл + Төгсгөл»:** хоёр төгсгөл нэг цэгт тул ганц тэмдэг — Эхлэлийн эргэлт хэрэглэгдэнэ; Төгсгөлийн нь ӨӨР бол тайланд ИЛ мэдэгдэнэ («Зөвхөн төгсгөл» сонговол Төгсгөлийнх хэрэглэгдэнэ).
* **Олонлог:** хомутын бодит лавлагаа хайх хязгаар 60 → 200 ширхэг (илүү бол «олонлог хэт том» — хайхгүй, хуурамч лавлагаа үүсгэхгүй); гүйцэтгэл Revit дээр хэмжигдээгүй (N9-ийг ашигла).
* **Tag-ийн холбоос:** `GetTaggedLocalElementIds` / `GetTaggedReferences` нь олонлогийн reference-д юу буцаахыг баримт тодорхойлоогүй тул «арматурт холбогдсоныг батлаж чадсангүй» нь ЗӨВХӨН мэдэгдэл (tag-ийг буцаахгүй); төрөл/харагдац буруу бол хатуу алдаа.
* **Цонхны хэмжээ:** шинэ цонхнууд ажлын талбайгаас (task bar-гүй дэлгэц) том болохгүй (`RfUi.Setup`); бага дэлгэц дээр гүйлгэнэ.  Тоо оруулахад NaN/Infinity татгалзаж, Unicode «−» хүлээн авна (`RfNumber`).

## 14. Төгсгөлийн тэмдэг — ДАРААЛАН дарах горим (2026-10-02)

Инженерийн хүсэлт: «нэг ашиглахдаа олон арматур дээр дараад, дараад тавьдаг болгомоор — одоо нэг дараад дахиад шинээр сонгох хэрэгтэй».

* Урьдчилан сонголтгүй үед: цонхны тохиргоо **НЭГ удаа** → арматур бүр дээр дарах бүрт тэмдэг **ШУУД** тавигдана → дахин дар… → **Esc = дуусгах** (тавьсан нь хэвээр). `RebarEndSymbolCommand.PickLoop` (`EndSymbolCommands.cs`).

## 15. Огтлол — ЗАГВАР ХАРАГДАЦААС ХУУЛАХ (2026-10-02)

Инженерийн хүсэлт: «Огтлолын арматурын тэмдэглэгээ plug-ийн хэмжээс, tag тавигдахгүй байна.  Хэрэглэгч Revit дээр өөрийн үүсгэсэн төстэй харагдацын нэрийг зааж өгөхөд түүнтэй адил clone-дож, зураг дээр нь засвар хийх боломжтой болгомоор байна».  Асуугаад сонгосон: **шинэ харагдац ҮҮСГЭХГҮЙ — ИДЭВХТЭЙ харагдац дээр шууд хуулна**.

### 15.1 Яагаад генераторын оронд хуулалт
Генератор (§13) нь хомутын гадна/дотор ирмэгийн Reference-ийг API-аас ХАЙЖ олдог — олдохгүй бол тэр талыг алгасдаг.  Инженер өөрөө Revit-ийн UI-аар (хэмжээс, MRA) зурсан харагдацад эдгээр лавлагаа АЛЬ ХЭДИЙНЭЭ байна.  Хуулалт нь тэр бодит тэмдэглэгээг (ижил хэмжээсийн төрөл, tag-ийн төрөл, leader, байрлал) шинэ дам нуруу дээр ДАХИН үүсгэнэ — лавлагааг таамаглахгүй, зөвхөн зорилтын ИЖИЛ нүүр/арматур руу буулгана.  Хуурамч (үл үзэгдэх) геометр ХЭЗЭЭ Ч үүсэхгүй.

### 15.2 Хэрэглэгчийн урсгал
1. Дам нуруу/баганын ОГТЛОЛ нээж, элементээ сонгоод «Огтлолын тэмдэглэгээ» (§13.4-ийн ижил цонх).
2. Цонхны ДЭЭД хэсэгт **«Загвар харагдацаас хуулах»**: хайлтын талбарт загвар харагдацынхаа нэрийн хэсгийг бич → жагсаалтаас сонго (мөр бүрт «хэмжээс N · tag N · текст N»; идэвхтэй харагдацтай ИЖИЛ төрөл — огтлол ↔ огтлол — эхэнд).
3. Сонгосны дараа «Загварын элемент: Дам нуруу … Id …» гарна — тэр харагдацын хэмжээс, tag-ийн лавлагаанаас тодорхойлсон (арматур бол эзэн нь).  Хэд хэдэн дам нуруу олдвол сонгуулна; загвар/зорилтын төрөл өөр (дам нуруу ↔ багана) бол анхааруулга.
4. Юуг хуулахыг сонго (Хэмжээс · Tag · Текст/2D) → **«Загвараас хуулах»**.  Нэг Ctrl+Z-ээр бүгд арилна.
5. Тайлан: үүссэн / байсан (давхар үүсгээгүй) / алгассан тоо + АЛГАССАН БҮРИЙН ШАЛТГААН (тайлангийн «АНХААР»/«АЛДАА» жагсаалт) + «Арматур тулгасан: N (олдоогүй M)».

### 15.3 Хэрхэн ажилладаг (код)
* **Хөдөлгүүр = «Зураг клонлох»-ын ЯГ ТЭР** (`CloneDrawings/CdEngine.cs`: tag, хэмжээс, MRA, 2D; арматурыг загварын бодит байрлалаар нь тулгана `MatchChildren`; хэмжээсийн лавлагааг зорилтын ижил нүүр рүү `MapRef`/`MapFaceRef`; үүссэн хэмжээсийн утгыг `FinishDims` шалгана; давхардал хасна).  Шинэ орох цэг: `CloneDrawings/CdOntoView.cs` `Run(...)` — `CdPlan.Prepare` → `CdEngine.BeginTarget` → `ctx.Dest[загвар харагдац] = ИДЭВХТЭЙ харагдац` → `BeginAnnotate` / `ContinueAnnotate`.  Шинэ харагдац, хуудас үүсэхгүй; `Stray` (хол зүсэлтийн тэмдэг нуух) ЗОРИУД унтраалттай — хэрэглэгчийн өөрийн харагдацад юу ч нуухгүй.
* **Давхардал:** tag — (төрөл|элемент) түлхүүр; хэмжээс — ижил элемент, ижил чиглэл, ИЖИЛ УТГА; 2D — `ctx.DetailCheck` (идэвхтэй харагдацад байгааг шалгана).  Дахин ажиллуулахад «байсан» гэж тоологдож давхар үүсэхгүй.  Хэрэглэгчийн ГАРААР тавьсан зүйл ХЭЗЭЭ Ч устахгүй (зөвхөн нэмнэ; `Drop` нь энэ ажиллуулалтад ШИНЭЭР үүссэн, шалгалтад тэнцээгүй хэмжээсийг л устгана).
* **Эсрэг талаас харсан харагдац:** идэвхтэй харагдац дам нурууг загварын харагдацаас ЭСРЭГ талаас (нөгөө үзүүрээс) харж байвал хуулсан зүйл зүүн-баруун толин тусгал болно.  `CdOntoView.TargetFrame` нь хоёр харагдацын `ViewDirection · тэнхлэг`-ийг харьцуулж (`OntoViewRules.NeedsFlip`, цэвэр, тестлэгдсэн) зорилтын хүрээг 180° эргүүлнэ.  Тайланд «байрлалыг эргүүлж буулгав» гэж бичигдэнэ.  Дагуу огтлол/план (тэнхлэгт ⟂ харагдац) дээр шийдвэр гаргахгүй — ердийн хүрээ.
* **Эзэн таних** (`RfTemplateService.FindHosts`): загвар харагдацын хэмжээс, tag бүрийн лавлагаа → арматур бол `GetHostId()`, дам нуруу/багана бол өөрөө; хамгийн олон лавлагаатай нь эхэнд (`OntoViewRules.OrderHosts`).  Лавлагаагүй бол «тодорхойлж чадсангүй» — таамаглахгүй.
* **Transaction:** НЭГ TransactionGroup + НЭГ Transaction, `CdFailureHandler(silentRollback: true)`; юу ч үүсээгүй/Revit буцаасан бол БҮГД буцаж тоолуур цэвэрлэгдэнэ (Notes/Errors үлдэнэ — шалтгааныг тайлбарлана).
* Файлууд: `CloneDrawings/CdOntoView.cs`, `CloneDrawings/Core/OntoViewRules.cs` (+ `tests/CloneDrawings.Tests/OntoViewRulesTests.cs`, 8 тест), `CdAnalysis.CoreInfo` (харагдац хайлтгүй загварын мэдээлэл), `CdContext`/`BeginTarget` (зорилтын хүрээг гаднаас өгөх сонголттой параметр — «Зураг клонлох»-ын хуучин зан төлөв ХЭВЭЭР), `Reinforcement/Revit/RfTemplateService.cs`, `Ui/SectionAnnotationDialog.cs` (дээд самбар + «Загвараас хуулах» товч), `SectionAnnotationCommand.CopyFromTemplate`, `RfText` (`Tpl*`).

### 15.5 Мэдэгдэж буй хязгаар
* **Утгын шалгалт ЗӨВХӨН хэмжээ ижил үед яг.**  Загвар, зорилтын дам нурууны хэмжээ өөр бол хэмжээсийн утга зорилтын нүүрээс дахин уншигдаж «зорилтод тохирсон» гэж тоологдоно — буруу нүүр рүү холбогдсон эсэхийг утгаар барьж чадахгүй (хуучин «Зураг клонлох»-тай ижил).  Тайлан тоог ИЛ харуулна.
* **Арматурын лавлагаа** (MRA биш энгийн хэмжээсийн) нь Rebar → Rebar `ConvertToStableRepresentation` солилтоор буулгагдана; арматурын хэлбэр өөр бол олдохгүй → тэр хэмжээс алгасагдаж тайланд бичигдэнэ.  MRA нь ЭЛЕМЕНТЭЭР (лавлагаагүй) үүсдэг тул энэ хязгаарт ордоггүй.
* **Харагдах байдал:** арматур идэвхтэй харагдацад харагдахгүй (Rebar View Presentation, нуусан ангилал) бол tag алгасагдана (`CdContext.Sees`).
* Дараалал: загварын 2D (текст, зураас) нь `CopyElements` + буулгасан төв рүү зөөх — нарийн хэлбэржилт (шрифт) загварынхтай ижил, байрлал ойролцоо.

## 17. «Хэмжээс, тэмдэглэгээ» хэрэгсэлд АРМАТУРЫН ГОРИМ — огтлол + дэлгээс (2026-10-05, 1.15.0)

Эзний хүсэлт: «Хэмжээс, тэмдэглэгээ» (AutoAnnotate) хэрэгсэлд «Огтлолын арматурын тэмдэглэгээ»-ний «загвараас хуулах»-аас БУСАД бүх ажил орно; арматурын дэлгээс
дээр multi-rebar tag-ийг гараар зурсан дэлгээс шиг; дэлгээсийн шошго автоматаар; шошгоны зай = ЗӨВХӨН «Үндсэн шошго» хэсэгт хэрэглэгчийн өгсөн мм; «Facereference-г таниж шошго тавина».
Эзний 2 шийдвэр (AskUserQuestion): шошгоны зай = хэрэглэгч мм-ээр, хэрэгсэл өөрөөсөө нэмэхгүй · дэлгээсэд ажлын арматурын шошго + хомутын MRA + тэнхлэг/нийт хэмжээс + бэхэлгээ/давхцлын хэмжээс (бүгд).

### 17.1 Бүтэц
* **Таних** (`AutoAnnotate/AaRebar.cs`): харагдацад арматур (`Rebar`) байвал дам нуруу/баганыг ТУС БҮР ялгана — тэнхлэг нь харагдацын хавтгайд ∥ ба «баруун»-тай ∥ бол **дэлгээс**
  (`RfElevationService.IsElevationHost`); тэнхлэг нь харагдацын нормалтай ∥ БА огтлолын хавтгайг дайрсан бол **огтлол** (одоо байгаа `RfSectionService` — өөрчлөгдөөгүй).
  Арматурын дам нуруу олдвол «Арматур» таб нээгдэнэ, ерөнхий хэмжээс (тэнхлэг, түвшин, tag) өгөгдмөлөөр тавигдахгүй (давхардахгүй) — «Бас ерөнхий» сонголтоор.
* **Дэлгээсийн цөм** (`Reinforcement/Core/RfElevation.cs`, цэвэр, 18 тест): `RfElevPlanner.Build` — шошгоны эгнээ, хомутын MRA, давхцлын хос, тэнхлэгийн гинж; `Dodge` = 1D
  хамгийн бага квадрат хазайлт (Pool-Adjacent-Violators) — хөрш шошгоны **харагдах** зай яг `TagGapFt`.
* **Revit тал** (`Revit/RfElevationService.cs`): ANALYZE (дам нурууны хүрээ, тэнхлэг, арматурын ангилал — огтлолтой ИЖИЛ `Resolve`), RENDER хоёр шаттай: (1) шошго, MRA-г leader-гүйгээр ТҮР
  үүсгэж бодит өргөн/өндрийг хэмжээд БУЦААНА; (2) хэмжсэн хэмжээгээр эцсийн байрлал.  Дараалал дээд: [шошго] → [давхцал]; доод: [шошго] → [давхцал] → [хомутын шошго] → [хомутын хэмжээс] → [тэнхлэг] → [нийт].
* **Шошгоны зай ГАНЦ эх сурвалж**: `AaRebarOptions.TagOffsetMm` (дам нуруунаас эхний эгнээ), `TagGapMm` (шошго хоорондын), `DimPitchMm` (хэмжээсийн эгнээ) → огтлолд (`TagOutMm`/`TagGapMm`) ч,
  дэлгээсэд ч ижил утга.  Хоёр шатны хэмжилтээр шошгоны өргөнийг family бүрээр хэмждэг тул «16 мм» гэх мэт таамаг ашиглахгүй.
* Replace: дэлгээсийн id-г `AaStore` (одоо байгаа) хадгалж дахин дарахад солино (гараар тавьсан хөндөгдөхгүй); огтлол нь өөрийн `RfSectionStore`.

### 17.2 FACE REFERENCE — бодит Revit 2027 дээр хэмжсэн (эх баримт)
* **Шошго**: `IndependentTag.Create(..., new Reference(rebar), ...)` дэлгээсэд «The reference can not be tagged» — гараар тавьсан шошго нь **арматурын ДЭД-ЭЛЕМЕНТИЙН лавлагаа**
  `<uid>:2000000:SUBELEMENT` (2000000 + ширхгийн индекс).  `RfRebarRefs.TagReferences(rebar, barIndex, subFirst)` нэр дэвшигчдийг дарааллаар оролдоно; огтлолын `RenderTags` ч ижил
  нөөцтэй болсон (огтлолд `new Reference(rebar)` өмнө нь ажиллаж байсан).  ⚠️ Энэ нь огтлолын хэрэгслийн «tag үүсэхгүй» гэсэн хуучин асуудлын шалтгаан байж болзошгүй.
* **Хэмжээс**: арматурын хэмжээсийн лавлагаа нь Edge/Face БИШ — `get_Geometry(View + IncludeNonVisibleObjects + ComputeReferences)`-ийн «Highlight» шугам: шулуун арматурын **төгсгөлийн хэрчим**
  `…:1003000` (эхлэл) / `…:1004000` (төгсгөл), голын шугам `…:1100000`, хомутын босоо хөл `2000000` (эхний) / `2000001` (сүүлийн ширхэг).  «500» давхцал = B-ийн зүүн төгсгөл ↔ A-ийн баруун
  төгсгөл (`RfElevationService.FindEndCaps`).  Давхцал **өөр голчтой** арматур хооронд ч байна (Ø22 тулгуур ↔ Ø12 мөр).
* Хомутын олонлог: `MultiReferenceAnnotation.Create` (тэдний төрлөөр `…_Tag`, алхам × тоо = нийт урт); `DimensionLineOrigin/Direction`, `TagHeadPosition`, `TagHasLeader`.

### 17.4 Гар QA / мэдэгдэж буй хязгаар
* ⭐ «Хэмжээс, тэмдэглэгээ» → «Арматур» таб → дэлгээс дээр: шошго, хомутын MRA, давхцал, тэнхлэг.  Огтлол дээр: хомутын гинж + шошго («Хомутын ирмэг: Дотор»).

Эзний хүсэлт: (1) «Арматурын багцыг нэг шошгоор» нь багцын БҮХ ширхгийг нэг шошгонд холбох (multi tag), шаардлагатай бол Merge leader; (2) MRA-ийн элементээс зай «Арматур (огтлол, дэлгээс)» табд; (3) хана, хучилт дээр тусдаа цэс — MRA-г ХАРАГДАЖ БУЙ АРМАТУРААС л зайтай тавина.

### 20.1 Multi-leader / Merge leader (огтлол)
* `AaRebarOptions.MultiLeaderPerSet` (өгөгдмөл асаалттай, `SingleTagPerSet`-ээс хамаарна) · `MergeLeaders` (өгөгдмөл унтраалттай).  Цонх: «Багцын БҮХ харагдаж буй ширхэг рүү нэг шошгоор leader татах (multi tag)» → «Leader-үүдийг нэгтгэх (Merge leader)».
* Planner (`RfSectionPlanner`): ганц багц (`GroupCount == 1`) бол `RfTagPlan.BarIndices/BarTargets` (≤ `MaxLeadersPerTag` = 40).  Олон элемент нэг шошгонд нэгдсэн бол multi-leader БАЙХГҮЙ (шошго ганц элементийн мэдээлэл уншдаг).
* Renderer (`RfSectionRenderer.AddSetLeaders`): ширхэг бүрийн `<uid>:2000000+idx:SUBELEMENT` лавлагааг `IndependentTag.AddReferences`-ээр нэмж, `SetLeaderEnd`-ээр leader бүрийг тухайн ширхгийн цэгт; `MergeLeaders` → `MergeElbows = true`.  Унавал нэг ширхгийн шошго хэвээр, тайланд тэмдэглэнэ.

### 20.2 Хомутын MRA зай → «Арматур (огтлол, дэлгээс)» таб
`_stirDimOffset` («{Дам нуруу/Багана} хомутын MRA (multi rebar tag) хүртэл», мм цаас, 0 = автомат) MRA-ийн сонголтын доор.  Шалгалт `ValidateTags`; «Баганын арматурын хэмжээс» таб-аас хасагдсан.

### 20.3 «Хана, хучилт» таб (`AaWallSlab`, `AaWallSlabPanel`, `RfSetMraService`, цэвэр `RfSetMra.cs`)
* Таних: харагдацад харагдаж буй, `NumberOfBarPositions ≥ 2` арматурын БАГЦ бүхий хана (`OST_Walls`) / хучилт (`OST_Floors`).  Арматурын дам нуруу/багана байгаа эсэхээс үл хамаарна (тусдаа таб; зөвхөн хана/хучилт олдвол энэ таб эхний таб, «Бас ерөнхий хэмжээс» түүний доор).
* Байрлал = **арматураас, хостоос БИШ**: багцын харагдаж буй ширхэгүүдийн (≤ 24 түүвэр) голын шугамын цэгээс тархалтын чиглэл, хамгийн гадна цэг (ширхгийн төгсгөл ч) → хэмжээсийн шугам тэндээс хэрэглэгчийн мм (өгөгдмөл 10, 2–60) · шошго шугамаас 4 мм (0–40).  «Эсрэг талд тавих».  Нуугдсан ширхэг тооцогдохгүй.
* MRA = `MultiReferenceAnnotation.Create` (арматурын ЭЛЕМЕНТЭЭС — лавлагааны асуудалгүй), `ApplyMraDimensionType` (`RfElevationService`-тэй ХУВААЛЦСАН) → цонхны НЭГ хэмжээсийн төрөл MRA-ийн хэмжээсэд ч.
