# «Автомат хэмжээс» (Auto dimension + tag) — add-in 1.7.0 (2026-09-30)

> **Нэршил / ribbon (2026-10-03, add-in UI/UX шинэчлэл):** ribbon-ы самбарууд **Ажил · Зураг · Арматур · Түүвэр · Шалгалт · Экспорт · Сан ба тохиргоо** болсон, товч бүр хоёр мөрт богино нэртэй, дэлгэрэнгүй тайлбар нь «Хэрэгсэл хайх» цонхонд.
> Энэ баримтад хуучин нэр гарвал: Smart Count → **Элемент тоолох**, Clash шалгах → **Давхцал шалгах**, Smart Publish → **Файл гаргах**, Зураг клонлох → **Зураг хувилах**,
> Автомат хэмжээс → **Хэмжээс, тэмдэглэгээ**, Хуулж тавих → **Элемент хуулах**, Preflight → **Гаргахын өмнөх шалгалт**, «Загвар»/«Smart» самбар → **Зураг** / **Шалгалт**/**Түүвэр**/**Экспорт**.
> Команд, класс, `PushButtonData.Name`, AddInId, тохиргооны түлхүүр **өөрчлөгдөөгүй**. Бүрэн зураглал: [`MGL_UI_UX_REDESIGN.md`](MGL_UI_UX_REDESIGN.md) §5.2.

Идэвхтэй харагдацын элементийг таньж хэмжээс, tag-ийг **ажлын зургийн бүтцээр** (ГОСТ 21.501 / MNS)
нэг товчоор тавина.  Ribbon: MGL → «Загвар» → «Автомат хэмжээс»
(`RevitMcpAddin.AutoAnnotate.AutoAnnotateCommand`, бүдгэрэх нөхцөл `AutoAnnotateAvailability`).

## Юу тавьдаг вэ

**План** (давхрын, бүтээцийн, таазны, талбайн план):

| Гинж | Агуулга | Байрлал |
|---|---|---|
| 1. Фасад | Гадна хананы булан, цонх/хаалганы нүхний ирмэг (хананы хажуу нүүр), тэнхлэгийн холболт | Барилгын ирмэгээс 12 мм (цаас) |
| 2. Тэнхлэг | Зэргэлдээ тэнхлэг хоорондын зай | +8 мм |
| 3. Нийт | Хамгийн захын тэнхлэг хоорондын зай | +8 мм |
| Дотор | Тэнхлэг хоорондын зайн дундаар хана хөндлөн: хананы зузаан, өрөөний цэвэр хэмжээ, тэнхлэг | Өрөөний tag-аас 5 мм зайлсхийнэ |
| Хаалга | Дотор хананы хаалганы нүх + ойрын ханын нүүрээс холболт | Хаалганы «нүүр» талд, 8 мм |
| Багана | Нүүр — ойрын тэнхлэг — нүүр (X ба Y) | Баганын доор / зүүн талд 6 мм |

Tag: хаалга, цонх, өрөө, (хана), бүтээцийн багана, дам нуруу.  Тэнхлэгийн бөмбөлгийг хамгийн гадна
гинжээс цааш гаргана (зөвхөн ЭНЭ харагдацад, ViewSpecific).

**Зүсэлт / фасад:** зүүн (ба баруун) талд түвшин хоорондын гинж + нийт өндөр, доод (ба дээд) талд
тэнхлэгийн гинж + нийт, цонх/хаалганы доод/дээд ирмэг доорх түвшнээс (ижил өндөртэй эгнээнд нэг удаа),
хаалга/цонхны tag.  Түвшний тэмдгийг гинжээс 26 мм, тэнхлэгийн бөмбөлгийг 5 мм цааш гаргана.

## Ачааллын гол дүрмүүд (хэмжиж олсон)

- **Гадна ханыг ГЕОМЕТРООР таньна** — хананы тал бүрээс 3 цэгээс туяа; ≥2 нь өөр ханыг огтлохгүй
  «зугтвал» гадна.  `WallType.Function`, `Wall.Orientation` ашиглахгүй (өгөгдмөлөөрөө / урвуу зурсан байдаг).
  Хаалттай хашааны хана «дотор» болно — зориуд.
- **Булан = хөрш ГАДНА хананы гадна нүүр** (`Walls.ExteriorCorner`): гүдгэр булан ч, шаталсан фасадын хотгор
  булан ч зөв.  Дотор хана (фасад үргэлжилнэ) бол булан биш.  Чөлөөт үзүүр → өөрийн үзүүрийн нүүр.
- **Нүхний ирмэг = хост хананы хажуу нүүр (jamb)**, family-ийн Left/Right хавтгай БИШ — байрлал нь геометрээс
  яг гарна (эрэмбэлэхэд хэрэгтэй: `NewDimension` лавлагааг ӨӨРӨӨ эрэмбэлдэггүй).  Огтлолын хавтгайг
  хамраагүй jamb (өндөр цонх) орохгүй.  Jamb олдохгүй бол Left/Right хавтгай.
- **0 урттай сегмент Revit-д алдаа** — `Chain.Normalize` 1 мм-ээс ойр лавлагааг нэгтгэнэ (тэнхлэг &gt; булан &gt; нүүр).
- **Гинж унавал** (нэг лавлагаа харагдацад хэмжигдэхгүй) булан + тэнхлэгээр дахин оролдоно.
- **Давхардалгүй дахин ажиллуулалт:** харагдац дээрх ES жагсаалтаар өмнөхийг устгаад дахин тавина (хэмжсэн:
  137 → 137).  Гараар тавьсан хэмжээс/tag хэзээ ч хөндөгдөхгүй.  «Duplicate with Detailing» хуулбарт ES ч
  хуулагддаг тул устгахдаа `OwnerViewId == энэ харагдац`-ыг шалгана.  Шинжилгээ өмнөх автомат tag-ийг
  «аль хэдийн tag-тай»-д тоолохгүй.
- ⚠️ **Фасад/зүсэлтэд `FilteredElementCollector(doc, viewId)` ХААГДСАН элементийг ч буцаадаг** (фасадын ард
  дотор хаалга, газар доорх хаалга) — Snowdon South фасадад 295 tag тавьсан.  Нүхний төвөөс харагч руу
  (харагдацын хавтгай хүртэл, тэр өндөрт) план дээр туяа цацаж өөр хана огтолбол алгасна → 59.
- **Түвшний тэмдгийн бичвэр шугамын үзүүрээс ДОТОГШ ~20 мм сунадаг** — гинжтэй давхцсан тул 26 мм.
- **Архитектурын планд баганын холболт анхдагч УНТРААЛТТАЙ** (ханан доторх багана бүрд 2 хэмжээс — бөөгнөрөл);
  бүтээцийн планд асаалттай.  Хоёр тохиргоо тусдаа хадгалагдана.
- **Жижиг сегментийн бичвэр** (`TextLayout`): эхний/сүүлийнх гадагш, дундах дараалсан жижгүүдийн хоёр дахь бүр
  дээш.  Бүх хэмжээсийн дараа НЭГ `Regenerate`.
- **Хурд:** нээлттэй харагдацад IndependentTag ~2–3 мс, план бүтэн (Snowdon L3: 47 гинж + 90 tag) 0.7 с.
  ⚠️ Нээгээгүй (далд) харагдацад tag бүр ~390 мс (Revit харагдацыг дахин үүсгэдэг) — тест харness-д
  харагдацыг заавал идэвхжүүлнэ; командын жинхэнэ урсгалд асуудалгүй.
- **Tag family ачаалаагүй ангилал** алгасагдаж тайланд хэлнэ (Revit-ийн сан энэ ПК-д ~50 rfa — автоматаар
  ачаалахгүй).
- «Зөвхөн сонгосон» горимд тэнхлэг/түвшний гинж нь тэнхлэг/түвшин өөрөө сонгогдсон үед л (3 багана → 6 холболт + 3 tag).
- `AaStore` Schema GUID `703fd5e6-e20d-4ba2-9edc-7752e0181c43` — **ХЭЗЭЭ Ч бүү өөрчил, талбар бүү нэм**.
- Core-ийн төрөл `Frame` гэж нэрлэвэл `Autodesk.Revit.DB.Frame`-тэй мөргөлдөнө (CS0104) — `AaFrame`.

## Link (холбосон файл) — 1.7.1 (2026-10-01)

Хэрэглэгчийн мэдээлэл: «Олдсон 0, хэмжээсийн чагт ажиллахгүй».  Шалтгаан: харагдацын хана, тэнхлэг,
хаалга бүгд **link**-ээс ирдэг байсан; `FilteredElementCollector(doc, viewId)` зөвхөн хостынхыг буцаадаг тул
1.7.0 бүгдийг 0 гэж тоолоод цонх бүх хэмжээсийн хайрцгийг ИДЭВХГҮЙ болгодог байв (хэмжсэн: link-ээр 244
хана, 28 тэнхлэг харагддаг планд 0).

- ⚠️⚠️ **`FilteredElementCollector(doc, viewId, linkId)` (Revit 2024+) -ийг ХЭЗЭЭ Ч БҮҮ ХЭРЭГЛЭ.**  Revit 2027.2
  дээр дэлгэцэнд нээгдээгүй харагдац, эсвэл TransactionGroup буцаасны дараа `OfClass` дээр нативаар
  (0xc0000005, coreclr) Revit-ийг БҮХЭЛД НЬ унагадаг — try/catch барихгүй (3 удаа давтагдсан, Windows
  Event Log-д стек).  Оронд нь link-ийн баримтыг `new FilteredElementCollector(linkDoc)`-оор уншиж
  `ViewData.Visible` өөрөө шүүнэ; link «By linked view» бол тэр харагдацын цуглуулагч.
- **Харагдах эсэхийн дүрэм (Revit-тэй тулгасан, L1 план: тэнхлэг 28/28, хаалга 34/34, багана 36/36,
  өрөө 14/14):** хостын VG ангилал нуугдаагүй; үе шат — хостын харагдацын Phase-тэй нэрээр таарах link-ийн
  Phase дээр `Future/Past` бол нуугдана, Phase Filter `DontShow` бол нуугдана; өрөө зөвхөн өөрийн үе шатанд;
  үндсэн биш Design Option нуугдана; план — View Range: харагдацын гүнээс огтлолын хавтгай хүртэл
  (огтлолоос БҮХЭЛДЭЭ ДЭЭШ элемент харагддаггүй; цонх/casework/generic model дээд хавтгай хүртэл), таазны
  план — огтлолоос дээш; Crop XY; зүсэлт — Crop + Far clip.  Тэнхлэгт BoundingBox байхгүй байж болно →
  `Grid.GetExtents()`.  Зөрүү: хостын View Filter-ээр нуусан link элемент (1 хана) орж ирнэ.
- **Координат:** цэг/вектор бүрийг `RevitLinkInstance.GetTotalTransform()`-ээр хост руу (`Lk.P/Vec`).
  Түлхүүр `"<linkId>:<elemId>"` (`Lk.K`) — хост ба link-ийн id давхцдаг.
- **Лавлагаа:** нүүр, family-ийн хавтгай → `Reference.CreateLinkReference(inst)`.  ⚠️ Тэнхлэг, түвшин
  (datum) дээр тэр нь «Invalid number of references» өгдөг — stable representation-ийн төгсгөлд
  `:0:LINEAR` нэмж `ParseFromStableRepresentation` (`Lk.DatumRef`; 8 тэнхлэгийн зай, түвшний өндөр яг
  таарсан).  Өрөөний tag: `NewRoomTag(new LinkElementId(inst.Id, room.Id), …)`.  Аль хэдийн tag-тайг
  `IndependentTag.GetTaggedElementIds()` / `RoomTag.TaggedRoomId` (LinkElementId)-ээр.
- Link-ийн тэнхлэг/түвшинг энэ файлаас уртасгах (бөмбөлөг гаргах) боломжгүй — хостынхыг л.
- **«References are no longer parallel»:** `Dir.Parallel`-ийн 2.6° хүлцэлтэй «параллель» налуу хана/тэнхлэг
  гинжинд орвол Revit Commit дээр БҮХ гинжийг хасдаг ба 1.7.0-ийн failure handler шийдэлгүй үлдээж Revit-ийн
  алдааны цонх гаргадаг байв.  Одоо `ChainItem.WithNormal` + `Chain.KeepParallel` (cos ≥ 1−1e-9, тэнцвэл
  тэнхлэгтэй бүлэг) гинж бүрийг ЯГ параллель лавлагаагаар үлдээнэ; failure handler ЭНЭ ажиллагаагаар
  үүссэн элемент алдаатай бол устгана (хэрэглэгчийн элементийг хэзээ ч), RollBack үед `Continue` л
  (ProceedWithCommit буцаавал Revit унадаг), тайлан хасагдсан гинжийг төрлөөр нь хэлнэ (`AaRunner.Reconcile`).
- Огтлолын хавтгайд нэг ч хана таараагүй бол хамгийн олон хана огтлох өндрийг сонгоно (`ChooseCut`, цонхонд хэлнэ).
- Цонх: хэмжээсийн хайрцаг хэзээ ч идэвхгүй болохгүй (боломжгүй бол шар шалтгаан, хэрэглэгч хөндөөгүй бол
  хадгалсан тохиргоо өөрчлөгдөхгүй); `AaViewInfo.EmptyReason`, link-ээс уншсан, ачаалагдаагүй link-ийн
  тэмдэглэл.

Шалгасан (2026-10-01, Revit 2027.2): Snowdon Architectural-ыг link хийсэн хоосон хост — L1 план (фасад 3,
тэнхлэг 4, нийт 4, дотор 10, хаалга 16, багана 66, tag 40, алдаа 0), нээгээгүй план, зүсэлт 2 (түвшин 4,
тэнхлэг 4, цонхны өндөр 5, tag 53); link-гүй Snowdon L3 регресс (1.7.0-тэй ижил тоо).

## Revit дотор турших (2026-09-30-ны арга)

1. Revit 2027-г `MGL_ALLOW_EXEC=1`-тэй асаана.  Тест загварыг scratch руу хуулна (read-only тэмдгийг арилгана).
2. `AutoAnnotate/Core/*.cs`, `Aa*.cs`, `AutoAnnotateDialog.cs` + `SettingsStore.Dir` stub-ийг ӨӨР нэртэй
   assembly болгож (`-p:AssemblyName=AaHarnessN`, дахин ачаалах бүрд N өсгөнө) `Assembly.LoadFrom`.
3. `run_revit_code` нь идэвхтэй баримтад нээлттэй Transaction-тэй тул (`OpenAndActivateDocument`,
   `ActiveView` солих, TransactionGroup боломжгүй) — скрипт дотор `IExternalEventHandler` классаар
   `ExternalEvent.Create` хийж `Raise()`; дараагийн MCP дуудлагын үеэр транзакцгүй ажиллана.
   (`UiApp.Idling` нь Revit ар талд байхад ажилладаггүй — хэмжсэн.)
4. «Unresolved References» цонх гарвал: `SendMessage(hwnd, TDM_CLICK_BUTTON=0x0466, 1002, 0)`
   («Ignore and continue»; UIAutomation-д InvokePattern алга).
5. `ImageExportOptions`-оор PNG гаргаж, System.Drawing-оор хэсэглэн томруулж нүдээр шалгана.
   Цонхыг `RenderTargetBitmap`-аар (харуулалгүй) зурж шалгасан.

Шалгасан: Snowdon Architectural L3 (империал, 210 хана), Transverse Section, South фасад; Snowdon Structural L2
(багана, дам нуруу); Revit-ийн японы метрийн жишээ 2階 (мм).  **Шалгаагүй:** товч дарах бодит UI урсгал
(хэрэглэгч шалгана), Revit 2024–2026 дээр ажиллуулалт (зөвхөн эмхэтгэсэн), link доторх link (nested).

## Хязгаар

Муруй хана, шилэн (curtain) хана, налуу (тэнхлэгт эргэсэн) хананы фасадын гинж, link доторх link-ийн элемент,
шатны хэмжээс, давхар фасадын дотор давхарга хэмжигдэхгүй.  Хэмжээсийн текст бусад аннотацтай (зүсэлтийн
тэмдэг, ...) давхцахыг шалгахгүй — зөвхөн өрөөний tag-аас зайлсхийнэ.

## Нэгтгэл — «Хэмжээс, тэмдэглэгээ» нэг цонх, багана, хэмжээсийн төрөл (2026-10-05)

Бүрэн тайлбар, шалгалтын баримт: [`REINFORCEMENT.md`](REINFORCEMENT.md) §18.  Товчоор:

* **Нэг орох цэг, гурван таб** (арматурын дам нуруу/багана олдвол): «Арматур (огтлол, дэлгээс)» · «Баганын арматурын хэмжээс» · «Хуулбарлаж зурах».  Олдохгүй бол «Ерөнхий хэмжээс» (өмнөх цонх хэвээр) ·
  «Хуулбарлаж зурах».  «Бас ерөнхий хэмжээс» нь арматурын табын доор эвхэгдэх хэсэг (давхар таб үгүй).
