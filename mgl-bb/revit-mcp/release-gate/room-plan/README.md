# Room Plan — live Revit gate

«Олон өрөөний план (Python)»-ыг **бодит Revit дотор** туршина. Хэрэглэгчийн Revit-ийг хөндөхгүй: тусдаа Revit процесс асааж,
шинэ төслийг template-ээс үүсгэн туршилтын «plate» (3 орон сууц) барина. Дараа нь production кодоор төлөвлөгөө үүсгэж,
Revit-ийн бодит геометрээр шалгана.

```powershell
# Revit 2027, дууссаны дараа Revit үр дүнтэйгээ нээлттэй үлдэнэ
powershell -NoProfile -ExecutionPolicy Bypass -File revit-mcp\release-gate\room-plan\run-live.ps1
# хүнгүй горим (дууссаны дараа Revit хаагдана)
powershell -NoProfile -ExecutionPolicy Bypass -File revit-mcp\release-gate\room-plan\run-live.ps1 -ExitWhenDone
```

Нөхцөл: Revit 2027 суусан, **ажиллаагүй** байх; Python 3.10+ PATH-д; 2024-ийн metric сан
(`C:\ProgramData\Autodesk\RVT 2024\Libraries\English\US`). Нэг run ≈ 1–2 мин.
Үр дүн: `%LOCALAPPDATA%\MGL\RoomPlanGate\<он>\<огноо>\` — `run.json` (verdict + бүх хэмжилт), `verify.json`,
`gate.log`, `plan-generated.png`, `models\RoomPlan_Generated.rvt`.
Хэрэглэгчийн суралцах сан хөндөгдөхгүй: feedback нь тухайн run хавтсан дахь `roomplan-feedback.sqlite3`-д бичигдэнэ.

## Юуг ажиллуулдаг

`tests/RoomPlan.LiveGate` — тестийн add-in (`MGL_RP_GATE_JOB`-гүй процесст юу ч хийхгүй). Production-ий **яг тэр эх кодыг**
link хийж компайлна: `RoomPlan/Core/*`, `RoomPlanPythonBridge`, `ExistingFloorBoundary`, `RoomPlanFurnitureRevit`,
`RoomPlanBatchApply` + Python worker. Архитекторын сонголтыг (орох хана, хамгийн өндөр оноотой хувилбар, family-ийн төрөл)
gate өөрөө хийж, `run.json`-д бичнэ.

| Алхам | Юуг баталдаг |
|---|---|
| `plate.build` / `plate.open` | `Default_M_ENU.rte` → 28×8.5 м эгнээ байр: U01 11 м, U02 9 м, U03 8 м. U03-ийн орц зүүн талд. |
| `roomplan.generate` | Floor таних, давхцал ба «эзэлсэн» шалгалт, цонхтой тал, программ, Python хувилбар, хуваалцсан хананд хаалга давхцахгүй сонголт |
| `roomplan.families` | Production-ий `DoorHostProblem` preflight: хаалга сонгосон дотор/гадна хананд Revit-д үүсэх эсэх |
| `roomplan.door-probe` | Төлөвлөгөөний хаалга бүрийг нэг нэгээр нь байрлуулж, Revit-ийн алдааг тухайн хаалганд оноож шалгана (эцэст нь бүгдийг rollback) |
| `roomplan.partial-failure-rollback` | U01 бүрэн бичигдсэний дараа U02 унавал моделд **0** элемент үлдэнэ |
| `roomplan.apply` | Нэг transaction (нэг Ctrl+Z), үүссэн элементийн тоо төлөвлөгөөтэй тэнцүү |
| `roomplan.verify` | Хана ↔ төлөвлөгөө; Room битүү, нэр, талбай; tag; хаалганы host ба уулзвар; **хаалганы эргэлт** (family-ийн plan нум) хана/тавилга/өөр хаалга мөргөхгүй; **тавилгын бодит хэмжээ** өрөөнд багтана; орцоос өрөө бүрт хүрэх зам; үүссэн элементийн Revit анхааруулга |
| `roomplan.undo` / `redo` | Revit-ийн өөрийн Undo/Redo командаар модел яг plate болж, дараа нь буцааж сэргэнэ |

Hard асуудал → `FAIL`. Soft асуудал (жишээ нь ор өрөөний голд байх) нь зөвхөн тэмдэглэл.

## 2026-10-14-нд хэмжсэн ба зассан (Revit 2027.2)

1. **Family-ийн origin төвд байдаггүй.** `M_Counter Top` нь 0.78×2.50 м хэмжээтэй, Python 0.6×1.2 м-ийн гал тогоо төлөвлөсөн.
   Ийм үед бүх batch rollback болдог байсан. Засвар (`RoomPlanFurnitureRevit.FitToTarget`): family-г бодит bbox-оор нь хэмжиж, урт
   талыг зорилттой нэг чиглэлд эргүүлнэ, бодит төвийг нь зорилт дээр тавина. Өрөөнд багтах боловч төлөвлөсөн цэг дээрээ
   хальж байвал хамгийн бага зайгаар дотогш гулсуулна.
2. **Хаалга ↔ хананы зузаан.** `M_Door-Passage-Single-Flush`-ийн 17 төрөл бүгд 100 мм хананд үүсэхгүй
   («Profile sketch is empty!» → «Can't make type»), 200 мм хананд үүснэ. Засвар: `RoomPlanBatchApply.DoorHostProblem` preflight —
   юу ч үүсгэхээс өмнө ойлгомжтой мессеж өгнө. Template-ийн `M_Single-Flush 0915 x 2032mm` 100 мм хананд үүсдэг.
3. **Revit-ийн алдаа хагас төлөвлөгөө болдог байсан.** Commit үед алдаа гарахад Revit алдааны цонх гаргадаг байсан;
   «Delete Element(s)» дарвал үлдсэн хэсэг нь commit болж «applied» гэж бүртгэгддэг байв. Засвар: failures preprocessor
   алдаа гарвал бүгдийг `ProceedWithRollBack` хийнэ, мессежинд элементийн ID-г оруулна.
4. **Хаалганы эргэлтийг хэн ч тогтоодоггүй байсан.** Revit хаалгыг хананы зурсан чиглэлээр нь санамсаргүй тал руу эргүүлдэг байв:
   1.4 м коридорт унтлагын, ариун цэврийн болон орох хаалга мөргөлдөж, хаалга орны буланг мөргөж байв. Засвар
   (`RoomPlanBatchApply.OrientSwings`): тавилга байрласны дараа хаалга бүрийн 4 хувилбарыг (facing × hinge) family-ийн нумаар
   тооцно. Эрэмбэ нь: тавилга/хана мөргөхгүй > өөр хаалгатай мөргөлдөхгүй > коридор/зочны өрөөнөөс хувийн өрөө рүү эргэнэ.
   Тэнцвэл Revit-ийн байрлуулснаар үлдээнэ.
5. **«Эзэлсэн» шалгалт бүх давхарт хамаардаг байсан.** 1-р давхар төлөвлөгдсөний дараа ижил хэмжээтэй 2-р давхрыг «эзэлсэн»
   гэж үздэг байв. Засвар: хана, room-оос бусад ангиллыг тухайн давхрын өндрийн мужаар шүүнэ.

## Давхрын план — `-Mode floor` (Finch маяг, 2026-10-14)

«Давхрын план» хэрэгсэл (`RoomPlanFloorCommand`, туузан цэсний Архитектурын самбар) бүтэн давхрын ХООСОН шалнаас эхэлнэ:
коридор, шат-лифтийн хонгил, айлын харьцаагаар давхрыг айлуудад хувааж (`Core/FloorPlateSplitter`), коридор / айл хоорондын

Revit алхам хооронд нээлттэй group-ийг зөвшөөрдөггүй тул хуваалтаас коридорын Room хүртэлх бүх зүйл `floor.apply` нэг алхамд.

## Нээлттэй

- Wall-hosted тавилга (`M_Tub-Rectangular-3D` г.м.) дэмжихгүй — сонголтод гарахгүй.
- Дотор ханын зузааныг төлөвлөгөө үүсгэх үед мэдэхгүй (хананы төрлийг дараа нь сонгоно) — 0.1 м гэж үзнэ; Revit тал бодит нүүрэнд
  тааруулна.
- Family-ийн ар нь +Y гэсэн Revit-ийн уламжлалд тулгуурлана; өөр чиглэлтэй компанийн family эргэсэн гарна.
- АЦӨ-д tag бүтэн багтахгүй (tag өрөөнөөс том) — голлуулсан, текст хананы дээгүүр гарна.
- Монгол нормын шалгалт ХИЙГДЭЭГҮЙ. Хаалганы эргэлтийн дүрэм нь коридорыг чөлөөтэй байлгах ерөнхий зарчим — норм биш.
- Бодит компанийн модел, family дээр шалгаагүй.
